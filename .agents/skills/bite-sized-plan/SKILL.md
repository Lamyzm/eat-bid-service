# 한입 크기 계획

계획은 **이 코드베이스를 전혀 모르고 판단할 것도 없고 테스트 작성을 싫어하는 숙련 개발자**가 그대로
따라 할 수 있을 만큼 구체적이어야 한다. 이 기준을 넘으면 계획이 스스로 설 수 있다.

## 1. 파일 구조를 먼저 스케치한다

작업을 쪼개기 전에 **어떤 파일이 새로 생기거나 바뀌는지, 각 파일이 무엇을 책임지는지**를 먼저
적는다. 여기서 분해가 확정된다.

- 파일당 책임 하나. 명확한 경계와 인터페이스를 따라 나눈다.
- **한 번에 머릿속에 들어오는 크기**가 크고 잡다한 파일보다 낫다. 작고 초점이 분명한 파일이 실수를
  줄인다.
- 함께 바뀌는 것은 함께 둔다. **책임**으로 나누고 기술 계층으로 나누지 않는다.
- 기존 코드베이스에서는 그 코드베이스의 기존 패턴을 따른다. 큰 파일을 선호하는 코드베이스를 혼자
  재설계하지 않는다.
- Principal 관점: 다른 팀이 그 위에 무언가를 쌓을 파일 구조(공유 라이브러리, 공개 모듈)는 다른 팀이
  베낄 선례가 된다 — 여기서 경계를 바로 잡아야 한다. 나중에 고치면 리팩터링이 아니라 마이그레이션이
  된다.
- **Distinguished/Fellow 관점:** 회사 전체 표준이 되거나 오픈소스로 나갈 구조라면, 5년 뒤 이 경계가
  왜 이렇게 그려졌는지 아무 기억이 없는 사람에게도 말이 되어야 한다 — 경계뿐 아니라 그 이유도 적어
  둔다.
- **경영진 관점(CTO·VP-Eng):** 이 분해가 팀 경계(누가 어느 모듈을 소유하고 운영에 몇 명이 필요한지)를
  암시한다면, 저장소뿐 아니라 조직 구조와 인력 배치에도 반영해야 하는 문제인지 확인한다.

## 2. 작업 단위 크기 정하기

**작업 하나 = 자체 테스트 주기를 갖고 리뷰어의 판단이 필요한 최소 단위.**

- 셋업, 스캐폴딩, 문서화 단계는 **필요한 작업 안에 접어 넣는다.** 별도 작업으로 쪼개지 않는다.
- A와 B를 별도 작업으로 쪼개는 건 리뷰어가 A는 승인하고 B는 반려할 수 있을 때뿐이다.
- 각 작업은 **독립적으로 테스트 가능한** 산출물로 끝난다.

## 3. 단계는 한 동작, 2~5분 단위

작업 안의 각 단계는 하나의 동작이다.

```
1. 실패하는 테스트를 작성한다
2. 실행해서 실패를 확인한다
3. 통과할 최소한의 코드를 작성한다
4. 실행해서 통과를 확인한다
5. 커밋한다
```

## 4. 모든 작업이 가져야 할 것

- 정확한 파일 경로(추측하게 하지 않는다)
- 무엇을 검증하는지, 그리고 **어떻게**
- 관련 문서나 기존 코드로의 포인터
- 완료 조건 — 어떤 상태가 되면 이 작업이 끝난 것인지

## 5. 범위 확인

계획이 여러 독립된 하위 시스템에 걸쳐 있다면 **계획을 쪼갠다.** 각 계획은 그 자체로 완결되고
테스트 가능한 결과를 내야 한다.

## 경고 신호

| 생각 | 실제 |
|---|---|
| "계획은 이 정도면 됐고, 코딩하면서 정리하지" | 코딩하면서 정하는 건 계획이 아니라 표류다 |
| "이 작업이 크긴 한데 한 덩어리로 두자" | 한 번에 테스트할 수 없으면 그건 한 작업이 아니다 |
| "파일 구조는 나중에" | 분해 결정은 나중에 되돌리기 비싸다. 먼저 스케치한다 |
| "단계를 다 적는 건 과하다" | 다음 사람(또는 다음 세션의 자신)에게는 과하지 않다 |

## 이 저장소에서

- `packages/contracts`를 가로지르는 첫 기능이나 다음 end-to-end 기능은 파일 구조 스케치 없이 시작하지
  않는다. `.agents/skills/eatbid-vertical-slice`가 이미 그 층 순서(versioned API → 서버 module →
  database adapter → Next.js consumer)를 정해 두었으니, 1절의 파일 구조 스케치는 그 순서 위에서 한다.
- AGENTS 정언명령 18(300줄을 넘는 파일은 책임 분리 검토)은 이 스킬의 1절과 같은 판단이다. 파일을
  나누는 이유가 복잡도 감소나 재사용이 아니라 줄 수 맞추기라면 둘 다 반대한다.
- Claude 또는 다른 실행자에게 위임하거나 구현 결과를 인계받는 절차는
  `.agents/skills/eatbid-supervised-delivery`가 소유한다. 이 스킬로 쪼갠 작업 목록은 그 인계 절차의
  입력이 된다.
