# SPEC-SCHOOL-ID — 학교 정체성을 문자열에서 코드로 (2026-08-28 · architect)

사용자 한 줄: *"엥 학교를 문자열로 봐? id 다 있지 않냐."* — **맞다. 원본에 이미 있다.**
`SPEC-SSOT.md` A3·A34, `DEBT.md` A-8·A-9의 처방이고 X20의 구현 스펙이다.

---

## 0. 측정 먼저 — **두 경로로 갈린다** (내가 레이크에서 직접 쟀다)

| 필드 | 레이크 상태 | 재파싱 |
|---|---|---|
| **`institution_code`(PURR_CD)** | **174,070건 100% 채움 · 고유 7,639** | **불필요. 이미 있다** |
| `sido_code`(SIDO_CD) | 100% 채움 | 불필요 |
| **`sigungu_code`(SIGUNGU_CD)** | **컬럼 자체가 없다** — `normalize.py`가 안 읽는다 | **필요** |

**이게 X20을 둘로 가른다. 그리고 값싼 쪽이 더 해로운 버그를 닫는다.**

| | **1단계 (재파싱 0)** | **2단계 (재파싱 필요)** |
|---|---|---|
| 쓰는 것 | `purr_cd` | `sigungu_cd` |
| 고치는 것 | **정체성** — 학교가 무엇인가 | **지역 축** — 표시·필터 |
| 닫는 사고 | **A-9(병합)** · **A-8(분열)** | 주소 오염(`남구학익2동`) · A35(원장 47건) · 계층 혼동(창원시 vs 성산구) |
| 죽는 규칙 | `clean_inst` 괄호 절단 | `_SGG_CANON`·`_SGG_RE`·`cleanSggs`·`clean_regions`·`_SIDO_MAP`·`_split_address` |
| 비용 | 로더 수정 + 재적재 1회 | `normalize.py` + **전량 재파싱** + 재적재 |

> **1단계가 A-8과 A-9를 둘 다 닫는다.** 분열은 `sigungu`가 **키에 있어서** 생긴 것이라,
> 키를 `purr_cd`로 바꾸면 `sigungu`가 무엇이든 검단중학교는 **한 행**이다.
> 2단계는 `sigungu` **값 자체**를 고치는 것이고 그건 표시·필터 축이다.

## 1. 로더가 코드를 채우는 지점

**선행 조건 없음(1단계).** `by_school` 집계 키를 바꾼다:

```python
# 지금:  by_school[(sido, sgg, inst)]           ← inst = clean_inst(원본 기관명)
# 바꿈:  by_school[purr_cd]                      ← 회차 행의 institution_code
```

집계·로스터·시장 3곳이 같은 키를 쓴다(`load_postgres.py:196` · `:451` · `:472`).
`schools` INSERT에 `purr_cd`를 싣는다 — **컬럼은 이미 존재한다**(`varchar(32)`, 현재 0/4,700 채움).

**표시 이름과 지역은 관측으로 정한다. 규칙을 만들지 않는다.**
- `name` = 그 `purr_cd`의 **`PURR_NM` 최빈값**
- `sigungu` = 그 `purr_cd`의 **최근 회차 값**(1단계) → **`(sigungu_cd, 개찰월)` 최빈값**(2단계)

§2-c 결정 ②와 같은 원리다 — **선언 테이블을 만들지 않는다. 관측이다.**

---

## 2. `schools.id`는 형식을 유지한다

**`id`를 안 바꾼다.** `{sigungu}|{institution}` 그대로 두고 **코드를 옆에 싣는다.**
§5-5("`school_id` 형식 변경 금지")를 위반하지 않는다.

```
schools( id varchar PK,        ← 형식 불변. 정본 purr_cd의 현재 이름으로 만든다
         purr_cd varchar,      ← 정체성. 조인·집계·중복 판정은 전부 이걸로
         sigungu, name, … )
```

**조인·집계·로스터는 `purr_cd`를 쓰고, `id`는 URL 호환용 표시 키로만 남는다.**
서버 조회는 **`purr_cd` 우선, 없으면 `id`** — 이 폴백은 이제 영구 부채가 아니다.
`user_biz`·`user_mark`·`user_region`이 `schoolId`를 참조하는 곳이 **0건**이라 사용자 데이터는 안 걸린다.

---

## 3. 별칭과 리다이렉트 — **URL 죽는 범위 0**

한 `purr_cd`가 여러 `{sigungu}|{name}` 조합을 갖는 경우가 실재한다(최대 **6조합**, 코드 `200242`).

```
school_alias( alias_id varchar PK,   -- 옛 조합 전부
              purr_cd varchar )      -- 정본
```
- 정본 = 그 코드의 **최근 회차 기준 조합**
- 나머지 = 별칭
- `analysis/[id]`·`schools/[id]`가 별칭으로 들어오면 **308 → 정본 id**

**검단중학교로 확인**: `서구|검단중학교`(구) · `검단구|검단중학교`(신) 둘 다 살아 있고,
북마크·공유 링크가 **하나도 안 죽는다.** 이게 이 설계에서 URL 안전을 보장하는 유일한 장치다.

---

## 4. 이름을 `(sigungu_cd, 개찰월)` 관측으로 (2단계)

인천 개편이 **코드 분열이 아니라 개명**이었다는 실측 위에 선다 —
`SIGUNGU_CD=722`는 안 바뀌고 이름만 서구→검단구가 됐다.
따라서 시간축은 **표시 계층에만** 들어간다: *"그 지역을 그때 뭐라고 불렀나."*

```sql
-- 선언 테이블 없음. 관측 뷰 하나.
select sigungu_cd, substr(opened_at,1,6) ym, mode(주소시군구) nm
from auctions group by 1,2
```
**정체성(코드)은 안 변하고 표시명만 시점을 갖는다.**

---

## 5. 괄호 절단 폐기 — **원래 막으려던 것이 안 생기는지 확인했다**

`clean_inst`는 `식생활관(전주시` 같은 **주소 오염**을 막으려고 만들어졌고(`:117-119` 주석),
그 과정에서 `남산초등학교(진해)`와 `(창원)`을 **합쳐버렸다**(A-9).

**코드 기반에서 그 오염은 정체성에 도달하지 않는다** — 키가 `purr_cd`라
기관명이 오염돼도 **다른 학교와 합쳐지지 않는다.** 남는 건 **표시명 문제 하나**이고,
그건 §1의 **`PURR_NM` 최빈값 관측**이 처리한다: 오염된 표기는 소수라 최빈값에서 밀린다.

> **규칙을 규칙으로 대체하지 않는다.** 절단 규칙을 없애고 그 자리에 최빈값 **관측**을 둔다.

## 6. 되돌리는 방법

동작을 바꾸는 변경이라 되돌릴 경로를 먼저 정한다.

| 단계 | 되돌리기 |
|---|---|
| 1단계 | **로더 커밋 되돌리고 재적재 1회.** `schools`는 매 적재 `delete` 후 재구축이라 **원상복구가 완전하다** |
| 별칭·308 | 라우트 코드 되돌리기. `school_alias`는 **읽기 전용 부가 테이블**이라 남아도 무해 |
| 2단계 | `normalize.py` 되돌리기 + 재파싱. **레이크는 append-only라 옛 파일이 남아 있고**, 스냅샷 상한(`part-{ns}`)으로 이전 상태를 그대로 재현할 수 있다 |
| 사용자 데이터 | **건드리는 것이 없다.** `user_*` 테이블에 `schoolId` 참조 0건 |

**되돌릴 수 없는 것: 없다.** 이 변경의 가장 좋은 성질이다.

## 8. 한계 — **`PURR_CD` 재발급은 이 표본에서 안 보인다**

`PURR_CD` 한 코드 → 두 기관명 **0 / 6,590**은 강한 신호지 **전수가 아니다**(표본 60,000 / 168,816 = **36%**).
**폐교 후 재개교 같은 코드 재발급**은 이 표본에서 보이지 않는다.

**그 경우 무엇이 깨지나**: 서로 다른 학교 둘이 **한 `purr_cd` 아래 합쳐진다.**
**A-9의 재발이고 더 은밀하다** — 지금은 이름이 같아서(`남산초등학교`) 의심할 여지라도 있지만,
재발급이면 **이름이 달라도 합쳐진다.**

**탐지 신호(카운터에 넣는다)**: 한 `purr_cd`에 이름이 둘 이상이면서 **기간이 안 겹치는** 경우.
개명은 기간이 인접하고, 재발급은 **공백을 두고 끊긴다.**
→ 8/30 전수 재확인을 **1단계 착수 조건**에 넣는다. 신호가 나오면 그 코드만 예외 처리하고 나머지는 간다.

## 9. 두 경로의 비용 (리더 요청)

| | **경로 A — 지금 1단계만** | **경로 B — 8/30에 묶어서 전부** |
|---|---|---|
| 재적재 | **2회**(지금 + 8/30) | **1회** |
| 언제 닫히나 | A-8·A-9가 **이번 주** | 8/30 이후 |
| 측정 안정성 | 백필 중이라 **수치가 흔들린다**. 완료 판정 1·2번은 재실행마다 달라진다 | 전남·광주 6만 건 포함한 **확정 수치로 판정** |
| 위험 | 낮음(되돌리기 완전) | 낮음 |
| 2단계(`sigungu_cd`) | 어차피 8/30 이후 | 같이 |

**내 권고: 경로 B.** 이유는 비용이 아니라 **판정이다** —
경로 A는 완료 판정 1·2번을 **흔들리는 수치 위에서** 내려야 하고(SPEC §6 실패4),
"병합 0건"을 확인한 다음 날 백필이 새 조합을 넣으면 그 판정이 무효가 된다.
**A-9의 실해가 0이라(아버지 투찰 0건) 일주일을 기다릴 여유가 있다.**

> 단 **A35는 다르다** — 실해가 있다(김해율하고 22건이 지금 분석판 진입 불가).
> 그런데 A35는 **2단계 소관**이라 어차피 8/30 이후다. **경로 A를 골라도 안 당겨진다.**
> 이 사실이 경로 B를 더 지지한다.

**사용자가 "지금 하자"면 경로 A로 간다.** 그 경우 완료 판정 1·2번에
**"백필 완료 후 재확인"을 조건으로 달아야 한다** — 판정을 두 번 해야 한다는 뜻이다.
