## 재개할 첫 단계와 의존 순서

   [계정 웹 검토 메모](2026-09-09-account-web-review.md)를 대조하고, 미해결 항목만 같은 issue에서 마감한다.
2. EAT-40를 인계받을 때 own-bid backend에 아직 빠진 인증 backend `215ce0d`, `3d5d8d4`와
   UI dev `81be4b6`, 최종 인증 웹 commit을 **검증 후** 통합한다. 먼저 ancestry를 확인해 이미 포함된
   commit을 중복 적용하지 않는다. EAT-47 writer가 쓰는 미커밋 파일을 복사해 병렬 통합하지 않는다.
   여기서 인수·통합 담당은 **이 문서를 받아 이어가는 세션**이다. 최종 인증 웹 commit은
   `codex/eat-47-account-foundation`의 최신 HEAD와 해당 issue의 검증 인계를 대조해 확정한다.
   아직 미커밋이면 먼저 EAT-47 범위에서 마감하며 임의의 SHA나 이전 backend HEAD로 대체하지 않는다.
3. [내 투찰 차트 인계](2026-09-09-own-bid-web.md)에 따라 실제 batch를 차트와 선택 회차 명단에 연결한다.
   이 단계는 관측 시점에 아직 시작하지 않았다. 새 응답/사업자 전환에 zoom이 초기화되지 않아야 한다.
4. 인증·DB 쓰기는 별도 일회용 DB와 dev 포트에서 검증한다. 실제 브라우저에서 사업자 등록→주소
   저장·새로고침→공고 복귀→실제 점 클릭→동일 회차 기록, 로그아웃·계정 전환을 확인한다.
5. 관련 결정적 gate와 공통 `pnpm review:ai` 뒤 인계한다. 코드 검증, dev 통합, 운영 배포,
   실제 Google 로그인, 사용자 인수는 각각 증거가 있는 상태만 보고한다.

## 유지할 실행 경계

- 기존 `3002` web / `4400` server는 **운영 PostgreSQL 역할에 연결된 개발 화면**이다.
  그 watched checkout에 새 인증 코드를 합쳐 테스트하거나 운영 DB에 DDL·등록·주소 쓰기를 하지 않는다.
- 계정 검증용 별도 포트는 web `3147`, Nest `4447`을 계획/사용한다. 실제 listener와 owner를
  확인하고 EAT-47 `apps/web/scripts/auth-e2e.ts`, `playwright.auth.config.ts`를 먼저 읽는다.
- 기존 `8767` 시안, backfill·Argo·DB tunnel·운영 서비스는 유지한다. Docker label만 보고 지우지 않는다.
- shared outbox에는 여러 작업의 오래된 이벤트가 섞여 있다. 전체 `workflow:sync` 금지.
  issue별 handoff만 기록하고 state/outbox 수기 편집이나 이벤트 삭제는 하지 않는다.
- 이 복구 변경에서는 원격 push·운영 배포·마이그레이션을 하지 않는다. 로컬 Git commit은 원격 백업이 아니다.
