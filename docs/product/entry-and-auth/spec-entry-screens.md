# 진입·설명 화면 명세 (marketing · auth)

- 상태: 초안 (2026-09-04). 승인 전에는 캔버스와 코드에 반영하지 않는다.
- 대상: Linear EAT-48. 인증 경계와 권한 수준은 [ADR 0032](../../adr/0032-authentication-and-authorization-boundary.md)를 따른다.
- 제품 경계: `AGENTS.md` 8항. 이 화면들은 추천가·예정가·승률 판정·낙찰 보장을 말하지 않는다.
  파는 것은 **판단 재료와 운영 상태**다.

## 0. 공통 규칙

### 토큰

결정 화면 v2와 같은 토큰을 쓰고 진입 화면 전용 스케일을 새로 만들지 않는다
(`docs/product/decision-screen-v2/README.md`).

| 항목 | 값 |
| --- | --- |
| 배경 | 페이지 oklch(0.970 0.005 271) · 카드 0.991 · 안쪽 0.976 |
| 잉크 | 0.34(본문) / 0.46(라벨) / 0.58(보조) / 0.70(비활성) |
| 파랑 | oklch(0.58 0.19 258) — 주 행동과 링크에만 |
| 빨강 | oklch(0.586 0.212 25) — 오류에만 |
| 타이포 | hero 32/700 · 제목 20/700 · 본문 15/600 · 라벨 13/600 |
| 그 외 | 반경 12/8 · 줄 높이 1.5 · 숫자는 tabular-nums |

색은 상태에만 쓴다. 마케팅 배경 그라디언트, 색 배지, 강조 색 블록을 만들지 않는다. 13px는 단위
꼬리와 라벨에만 쓰고 본문을 13px로 내리지 않는다.

### 문구 금칙

| 쓰지 않는 말 | 쓰는 말 |
| --- | --- |
| 낙찰 확률 / 승률 예측 / 적정 투찰가 | 과거 회차의 낙찰률 분포 |
| AI가 추천하는 값 | 값은 사용자가 정합니다 |
| 낙찰률 30% 향상 | 표본 수와 기간을 함께 표시합니다 |
| 자동 투찰 | NeaT 입력은 사용자가 직접 합니다 |

### 화면 공통 상태

모든 화면은 로딩·오류·빈 상태를 각각 정의한다. 색만으로 상태를 말하지 않고 항상 문장을 함께 둔다
(`product-and-quality.md` §4-6).

## 1. `(marketing)` `/` 랜딩

- **1차 질문:** 이 서비스는 나에게 무엇을 보여주는가?
- **주 행동:** `시작하기` → `/signup`
- **보조 행동:** `로그인`(우상단), `요금 보기` → `/pricing`
- **권한:** `public`. 데이터 계약을 읽지 않는다. 정적 prerender.

### 섹션

| # | 섹션 | 내용 |
| --- | --- | --- |
| 1 | 헤더 | 좌: 서비스명. 우: `요금` · `로그인` · `시작하기`(파랑) |
| 2 | hero | 제목 32/700 2줄, 부제 15/600 2줄, 주 행동 버튼, 결정 화면 캡처 1장 |
| 3 | 무엇을 보여주는가 | 3열. 열린 공고와 마감 / 기관 회차 이력 / 개찰 명단 복기 |
| 4 | 근거 표기 | 실제 화면의 `표본 n · 기간 · 산출 시각` 줄을 확대해 보여준다 |
| 5 | 하지 않는 일 | 제품 경계 4줄. 배지 없이 본문 목록 |
| 6 | 요금 요약 | 두 요금제 이름과 한 줄 차이, `요금 보기` 링크 |
| 7 | 바닥글 | 사업자 정보, 문의, 개인정보 처리방침, 이용약관 |

### 문구 초안

- hero 제목: `오늘 어떤 공고를 봐야 하는지, 그리고 그렇게 판단한 근거를.`
- hero 부제: `eaT 원본을 그대로 보존해 기관·품목·회차 이력을 표본 수와 함께 보여줍니다. 넣을 값은 사용자가 정합니다.`
- 3열 제목/본문:
  - `열린 공고와 마감` / `지역과 품목으로 거른 열린 공고를 마감 순으로 봅니다. 참여 수 변화를 함께 봅니다.`
  - `기관 회차 이력` / `이 기관의 지난 회차 낙찰률과 그날 하한, 명단 크기를 한 축에서 봅니다.`
  - `개찰 명단 복기` / `개찰 뒤 명단 전체와 내 자리, 2등과의 차이를 원본 그대로 봅니다.`
- 근거 표기 캡션: `모든 숫자에 표본 수, 기간, 산출 시각, 계산 버전이 붙습니다. 출처를 못 밝히는 숫자는 보여주지 않습니다.`
- 하지 않는 일:
  - `투찰가를 추천하지 않습니다.`
  - `예정가를 예측하지 않습니다.`
  - `대신 NeaT에 입력하거나 제출하지 않습니다.`
  - `확인하지 못한 값은 '모름'으로 둡니다. 추측으로 채우지 않습니다.`

### 상태

| 상태 | 처리 |
| --- | --- |
| 로딩 | 없음. 정적 prerender라 첫 페인트가 완성 화면이다 |
| 오류 | 없음(외부 데이터 없음). 이미지 로드 실패 시 캡처 자리에 배경만 남기고 레이아웃을 유지한다 |
| 빈 | 해당 없음 |
| 이미 로그인 | 헤더의 `로그인`·`시작하기`가 `내 워크스페이스로`(→ `/today`) 한 개로 바뀐다. 이 판정은 헤더 안 Suspense leaf가 하고 static shell을 막지 않는다 |

## 2. `(marketing)` `/pricing` 요금

- **1차 질문:** 얼마이고, 무료와 유료가 무엇이 다른가?
- **주 행동:** `시작하기` → `/signup`
- **권한:** `public`. 정적 prerender.

### 섹션

| # | 섹션 | 내용 |
| --- | --- | --- |
| 1 | 헤더 | 랜딩과 같음 |
| 2 | 제목 | 20/700 한 줄 + 부제 |
| 3 | 요금제 2열 | 무료 / 유료. 각 열: 이름, 가격, 대상 한 줄, 포함 목록 |
| 4 | 무엇이 창을 넓히는가 | 비교 표. 행은 기능, 열은 요금제. 값은 텍스트(체크 아이콘만 쓰지 않는다) |
| 5 | 자주 묻는 것 | 4문항. 결제 주기, 사업자 여러 개, 해지, 데이터 보관 |

### 문구 초안

- 제목: `보는 창의 크기가 다릅니다.`
- 부제: `두 요금제가 보는 데이터는 같습니다. 무료는 최근 12개월과 기본 지역, 유료는 5년과 전국입니다.`
- 무료: `무료` / `한 지역에서 시작하는 분` / `열린 공고, 기관 회차 이력 12개월, 개찰 명단 복기, 사업자 1곳`
- 유료: `유료` / `여러 지역·여러 사업자를 운영하는 분` / `무료의 모든 것 + 이력 5년, 전국 비교집단, 사업자 여러 곳, 성적표`
- 비교 표 행: `기관 회차 이력` `비교집단 범위` `등록 사업자 수` `성적표` `개찰 명단` `원본 추적`
- FAQ 문구는 요금이 확정된 뒤 채운다.

### 상태

| 상태 | 처리 |
| --- | --- |
| 로딩·오류·빈 | 랜딩과 같다. 요금 값은 코드 상수이며 계약을 읽지 않는다 |

요금 액수와 요금제 이름은 아직 확정되지 않았다. 확정 전에는 이 화면을 배포하지 않거나 액수 자리에
`준비 중`을 둔다. 확정되지 않은 숫자를 임시값으로 노출하지 않는다.

## 3. `(auth)` `/login` 로그인

- **1차 질문:** 어떻게 들어가는가?
- **주 행동:** `로그인`
- **보조 행동:** `Google로 계속하기`, `계정 만들기` → `/signup?next=`
- **권한:** `public`. 이미 유효 세션이면 `next` 또는 `/today`로 보낸다.

### 섹션

카드 하나. 위에서 아래로: 서비스명 · 제목(20/700) · Google 버튼 · 구분선 `또는` · 이메일 · 비밀번호 ·
`로그인` 버튼(파랑, 폭 100%) · `비밀번호 찾기` · `계정 만들기`.

### 문구 초안

- 제목: `로그인`
- 이메일 라벨: `이메일` / 비밀번호 라벨: `비밀번호`
- 주 버튼: `로그인`
- 소셜: `Google로 계속하기`
- 하단: `계정이 없으신가요? 계정 만들기`
- `next`가 있을 때 카드 상단 한 줄: `로그인하면 보던 화면으로 돌아갑니다.`

### 상태

| 상태 | 문구·처리 |
| --- | --- |
| 로딩 | 주 버튼이 `로그인 중`으로 바뀌고 비활성. 입력은 계속 보인다. 카드 전체를 스켈레톤으로 덮지 않는다 |
| 자격 오류 | 카드 상단 빨강 한 줄: `이메일 또는 비밀번호가 맞지 않습니다.` 어느 쪽이 틀렸는지 말하지 않는다 |
| 입력 오류 | 필드 아래 13/600 빨강. `이메일 형식이 아닙니다.` |
| 시도 초과(429) | `잠시 뒤에 다시 시도해 주세요.` 남은 시간을 추측해서 적지 않는다 |
| 서버 오류(5xx·503) | `지금 로그인할 수 없습니다. 잠시 뒤 다시 시도해 주세요.` 아래 13/600 회색으로 `요청 번호 <requestId>` |
| 빈 | 해당 없음 |

## 4. `(auth)` `/signup` 계정 만들기

- **1차 질문:** 무엇을 주면 시작할 수 있는가?
- **주 행동:** `계정 만들기` → 성공 시 `/welcome`
- **권한:** `public`.

### 섹션

로그인과 같은 카드. 필드는 이메일 · 비밀번호 · 이름(선택). 버튼 아래 약관 동의 문장 한 줄.
사업자번호는 여기서 받지 않는다. 온보딩 2단계에서 받는다.

### 문구 초안

- 제목: `계정 만들기`
- 비밀번호 도움말: `8자 이상`
- 약관 줄: `계속하면 이용약관과 개인정보 처리방침에 동의하는 것으로 봅니다.`
- 주 버튼: `계정 만들기`
- 하단: `이미 계정이 있으신가요? 로그인`

### 상태

| 상태 | 문구·처리 |
| --- | --- |
| 로딩 | 버튼 `만드는 중`, 비활성 |
| 중복 이메일(409) | `이미 가입된 이메일입니다.` 아래 `로그인` 링크 |
| 입력 오류 | 필드 아래 빨강 13/600 |
| 서버 오류 | 로그인과 같음 |

## 5. `(auth)` `/welcome` 온보딩 (2단계)

- **1차 질문:** 내 워크스페이스를 무엇이라 부르고, 어느 사업자로 일하는가?
- **주 행동:** 단계별로 `다음` → 마지막 `시작하기` → `/today`
- **권한:** `authenticated`. 세션 없으면 `/login?next=/welcome`.
- **단계 상태는 URL이 소유한다.** `?step=workspace|supplier`. 뒤로가기가 곧 이전 단계다.

### 5.1 단계 1 — 워크스페이스 이름

- 제목: `워크스페이스 이름을 정해 주세요.`
- 부제: `나중에 바꿀 수 있습니다. 회사 이름이나 팀 이름을 씁니다.`
- 필드: 이름 1개. 버튼 `다음`.
- 이미 워크스페이스가 있으면 이 단계를 건너뛰고 `?step=supplier`로 간다.

### 5.2 단계 2 — 사업자 등록

- 제목: `일하는 사업자를 등록해 주세요.`
- 부제: `사업자등록번호로 eaT 원본에 있는 사업자를 찾습니다. 번호 자체를 식별자로 쓰지는 않습니다.`
- 필드: 사업자등록번호(`000-00-00000`). 입력하면 조회 결과로 상호를 보여주고 사용자가 확인한다.
- 버튼: `등록하고 시작하기`. 보조: `나중에 하기` → `/today`.
- 보조 문구: `등록하지 않아도 공고와 회차 이력은 볼 수 있습니다. 내 값 기록과 성적표는 등록 뒤에 열립니다.`

### 상태

| 상태 | 문구·처리 |
| --- | --- |
| 로딩(조회) | 번호 아래 13/600 회색 `원본에서 찾는 중` |
| 찾음 | 번호 아래 상호를 15/600으로 표시하고 `이 사업자가 맞습니까?` 확인 |
| 못 찾음 | `이 번호로 등록된 사업자를 아직 원본에서 보지 못했습니다.` 아래 `나중에 하기`를 강조. 이름을 추측해 만들지 않는다 |
| 선점 충돌(409) | `이 사업자는 다른 워크스페이스에 이미 등록돼 있습니다. 문의해 주세요.` 어느 워크스페이스인지 말하지 않는다 |
| 권한 없음(403) | `이 워크스페이스를 바꿀 권한이 없습니다.` (소유자가 아닌 구성원) |
| 서버 오류 | 로그인과 같음. 단계 1에서 만든 워크스페이스는 유지되고 단계 2만 다시 시도한다 |
| 빈 | 해당 없음 |

## 6. 계약과 상태 소유

| 화면 | 소비하는 계약 | 호출 위치 | URL이 소유 | 서버가 소유 | 로컬이 소유 |
| --- | --- | --- | --- | --- | --- |
| `/` | 없음 | — | — | 헤더의 로그인 여부(`getCurrentSession`, Suspense leaf) | 없음 |
| `/pricing` | 없음 | — | — | 위와 같음 | 없음 |
| `/login` | Better Auth 전송 `/api/auth/*` | client | `next` | 세션 쿠키 | 폼 초안(TanStack Form), 제출 중 여부 |
| `/signup` | Better Auth 전송 `/api/auth/*` | client | `next` | 세션 쿠키 | 폼 초안, 제출 중 여부 |
| `/welcome` 진입 판정 | `getCurrentSession` | RSC(Suspense loader) | `step` | 세션·워크스페이스 존재 여부 | 없음 |
| `/welcome` 단계 1 | `createWorkspace` | client(mutation) → 성공 후 RSC 무효화 | `step` | `app.workspace`, `workspace_membership(owner)` | 이름 초안 |
| `/welcome` 단계 2 | `registerWorkspaceSupplier` | client(mutation) | `step` | `app.workspace_supplier` | 번호 초안, 확인 체크 |

원칙:

- 되돌아올 수 있어야 하는 것(단계, `next`)은 URL이 소유한다(`0031` 1항).
- 세션·워크스페이스·사업자 등록은 서버가 유일한 권위다. 게스트 localStorage 진실 원천은 폐기됐다
  (ADR 0032).
- 로컬은 제출 성공 전의 폼 초안과 일시적 UI 상태만 갖는다. 저장에 성공하면 로컬 사본을 버린다.
- 사업자등록번호 조회 결과(상호)는 화면에 보여주기만 하고 브라우저에 저장하지 않는다.
