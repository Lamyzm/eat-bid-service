# 선택 회차 상세의 실화면 통합

2026-09-08 사용자는 시안의 마지막 사용 흐름 보정 이후 구현 전환 판단을 위임했고, 기존 컴포넌트 재사용을 요구했다.
이번 변경은 실제 API가 연결된 공고 화면에서 하단 이력 표와 선택 회차의 참여 기록을 분리하는 첫 단계다.

## 재사용과 상태 소유

- `ApplicationShell`과 `DecisionFrame`을 유지한다. 화면과 loading skeleton이 같은 frame을 사용한다.
- `HistoryTable`은 기존 열·표현·가로 스크롤을 유지하며 선택 ID를 공통 상태에 전달한다.
- `AuctionRosterPanel`은 기존 `auctionQueries.roster`를 그대로 사용한다. 조회·재시도·미관측·원천 근거를 재구현하지 않는다.
- 같은 명단 컴포넌트의 shadcn Table을 순위·업체 / 비율 / 실제 금액 세 열로 조정하고 원천 결과·철회를 업체 아래에 둔다.
- 새 `AttemptSelectionProvider`는 ID와 포커스 복귀만 소유한다. 서버 행이나 참여 명단을 별도 저장소에 복사하지 않는다.
- 현재 공고 ID가 바뀌거나 이력 조회가 회차를 제외하면 선택을 초기화한다. 오른쪽은 선택이 없을 때 기존 공고 보조 정보로 돌아간다.

큰 화면에서는 기존 rail을 sticky로 사용하고, 좁은 화면에서는 동일한 상세를 오른쪽에 펼친다.
상세 선택 때문에 표를 교체하거나 문서를 위아래로 이동하지 않는다. 닫기·Escape 후 원래 명단 버튼으로 포커스를 돌려준다.
API·DB·파이프라인·원본 데이터는 변경하지 않는다.

## 검증과 현재 한계

기존 동작이 오른쪽 영역 밖에 상세를 렌더링하여 실패하는 regression을 먼저 확인한 뒤 연결했다.
현재 공고·표 유지, 조건 제외 후 복귀 시 예전 선택 방지, 다른 회차 명단으로 교체, Escape·포커스 복귀와
실제 금액·세 자리 비율·독립 철회 상태를 검증했다.

로컬 dev `/auctions/5270?view=흐름`에서 5274의 6행과 5271의 34행을 실제 API로 조회했다.
1440×900, 1920×1080, 375×812에서 문서와 상세의 가로 넘침 없이 확인했고, 큰 화면에서 선택 전후 문서 위치가 같았다.
검증 산출물은 저장소 밖 `eatbid-mvp-review/v7/dev-inspector-report.json` 및 `dev-inspector-*.png`다.

전체 v7 레이아웃 통합은 아직 완료되지 않았다. 이후 공통 frame의 차트 집중 보기, 실제 이력의 하한 필터 통합,
기관 비교와 선택 회차를 차트에 연결하고, 기존 사정률/관측 투찰률 표시의 분모 정합성을 확인한다.
현재 SVG 차트를 새로 확장하거나 시안 Canvas를 제품 엔진으로 복사하지 않는다. 차트 엔진 적합성 결정과
장기간 데이터·겹친 날짜의 검증을 이어간다. 관심 저장·기관 전용 진입·드로잉·요금제는 후속 범위다.
