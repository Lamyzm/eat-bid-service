# PDR-0012 — 넣을 공고는 값만 보인다: 넘겨주기·복사·완료 표시를 두지 않는다

- Status: Active
- Date: 2026-11-18
- Supersedes: [PDR-0011](0011-work-screen-pass-values-per-business.md) 결정 4(넘겨주기)와 결정 3·5의 배치(88% 값 줄마다·공고번호 복사).
  0011의 나머지(화면 이름·N번 값·하한율 묶음·두지 않는 것)는 그대로다.
- Superseded-by: 없음
- Issue: #241 (큐 #239 5번, 구현 정본 #239 댓글 6960906002)

## 결정

1. **넣는 사람은 계정 주인 한 사람이다.** 사장님이 사업장마다 eaT에 직접 넣는다. 화면은 사업장마다 넣을 값만 보이고, 값을 남에게
   건네는 장치(넘겨주기 단추, 값·공고번호 복사, "넘겨줬어요" 같은 완료 표시)를 두지 않는다.
2. **하한 90% 값은 오른쪽 판 하나에 둔다.** "N월 값" 판에 사업장마다 이름과 값(기초금액 대비 %, 소수 셋째 자리)을 두고 단추는 두지
   않는다. 값은 맞춤 칸의 순위 값(`marketValue`)이다.
3. **하한 88% 값은 묶음 머리에 둔다.** 88% 공고는 사업장마다 값이 같은 공고끼리 한 묶음이고, 묶음 머리에 사업장별 값 타일을 둔다.
   값이 갈리면 묶음도 나뉜다. 값은 서버 규칙(`bid-position-rule.ts`)이 참여 업체 수 구간(마감 1시간 전으로 보정)으로 정한 순위
   값이며, 화면 머리의 기준 시각에 서버가 낸 값이다.
4. **마감일은 칩으로 고르고 내일부터 보인다.** 오늘 마감은 넣는 날이 지났으므로 빼고, 주가 바뀌는 자리에 구분선을 긋는다.
5. **공고 줄은 읽기만 한다.** 마감 시각·학교 이름·공고번호(흐린 글자)이며 학교 이름은 링크가 아니다. 이 화면에서 누를 수 있는 것은
   마감일 칩, 결과 보기 줄, 메뉴뿐이다. 정본의 "오늘 N일 마감 N건은 개찰됐어요 · 결과 보기" 줄은 결과 화면(#243)과 함께 들인다 —
   지금 응답(`getMyBidBoard`)에는 열린 공고만 있어 오늘 개찰된 건수가 없고 결과 화면 주소도 아직 없다(#241 구현 시점, 기획 확인 중).
6. **사업장은 업체명으로 부른다.** 사업자등록번호는 보이지 않는다. 업체명을 아직 관측하지 못한 사업장은 등록 순번("1번 사업장")으로
   부른다.

## 배경

- 2026-11-18 사장님 판정: 투찰은 아버님이 사업장마다 직접 넣는다. 그래서 건네는 사람이 따로 있다는 0011의 전제(넘겨주기)가 쓰이지
  않는다. eaT는 그 업체가 넣을 수 있는 공고를 목록으로 보여 줘서 공고번호로 검색할 일도 없다.
- 시안 D(값만): https://claude.ai/code/artifact/f6588b36-290c-4dc9-b777-5d1248f72521 (보기 고르기 "D 값만"). 화면 구조·값 규칙·인수
  기준은 #239 구현 정본 댓글이 소유한다.

## 대안과 기각 이유

- **넘겨주기를 남기고 쓰지 않으면 그만:** 쓰이지 않는 단추가 판과 묶음 머리를 늘려 첫 화면 공고 줄을 줄인다(시안 C 대비 실측).
- **공고번호 복사만 남기기:** eaT에서 번호로 찾지 않는다는 사장님 말로 기각했다. eaT 화면 실물을 대조해 다르면 이 결정을 다시 본다.
- **88% 값을 줄마다 두기(0011):** 사업장 수만큼 열이 늘어 5곳이면 표가 옆으로 넘쳤다. 같은 대역의 공고는 값이 같아 묶음 머리 한
  번이면 된다.

## 되돌리기 조건

- 사장님이 사업장마다 다른 사람(직원·가족)에게 값을 건네기 시작하면 결정 1을 다시 본다(0011 결정 4의 넘겨주기가 후보).
- eaT 화면 실물에서 공고번호로 찾는 단계가 확인되면 결정 5에 공고번호 복사를 다시 들인다.
- 셋째 이후 사업장의 88% 값이 서버 규칙에 없어 "값 없음"이 첫 화면을 차지하면(#242 판정 뒤) 결정 3의 타일 배치를 다시 본다.
