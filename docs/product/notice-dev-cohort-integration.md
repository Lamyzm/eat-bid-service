# 공고 dev의 비교 조건과 차트 통합 계획

> 이 문서의 날짜별 절은 당시 작업 기록이다. **시안 재현은 미완료**이며 현재 차이와 수정 순서는
> [공고 분석 시안과 dev의 차이](notice-design-fidelity.md)에서 갱신한다.

목표는 현재 공고 → 같은 조건의 기관 이력 → 선택 회차 명단의 흐름을 실제 API로 완성하는 것이다.
계획 작성·실행 스킬의 작은 검증 단위로 진행하며 기존 DecisionFrame, HistoryTable,
AttemptSelectionProvider, shadcn 메뉴와 설치된 Lightweight Charts를 재사용한다.

## 결정과 적용 범위

- 공고 하한율과 낙찰 방식이 같은 기관 이력을 기본 조회한다. 하한율 전체와 미확인을 구별한다.
  88/90 같은 고정 목록을 만들지 않고 원본의 exact 하한율을 사용한다.
- 기간은 KST 개찰월이며 조회 전에 서버 조건으로 전달한다. 표·차트·페이지는 같은 응답을 사용한다.
- 품목은 회차 응답의 codeValueId만 사용한다. 현재 공고의 itemLabel로 ID를 추측하지 않는다.
- 원문 품목명은 코드가 없어도 표시한다. 표·점·선택 회차는 같은 관측 라벨을 쓰되 품목 필터와
  선 연결은 확인된 코드가 있을 때만 가능하다.
- 전국/지역 분포의 현 계약은 품목 조건, 전체/미확인 하한, 12개월 초과 기간을 지원하지 않는다.
  이 조건에서는 요청하지 않고 제한을 명시한다. 몰래 필터를 무시한 분포를 보여주지 않는다.
- 차트의 낙찰값은 원천 SAJEONG_PCT를 전달한 winRate다. 분모가 예정가격인 관측값이며
  기초금액 대비 awardedBidRate 및 dayFloorRate와 구별한다. 원천/DB 수치와 계약 의미는 바꾸지 않는다.
- 한 줄로 이어지는 회차는 확인된 품목·하한율·낙찰 방식이 같아야 한다. 미확인 조건은 점으로만 보인다.
- 기본 비율 창은 선택 하한율 -0.100 ~ +0.700%p, 전체/미확인은 관측 전체 범위다.
  이것은 표시 범위이며 추천이나 예측 구간이 아니다. 정확값은 최소 소수 셋째 자리로 읽는다.
- 일반 보기의 문서 스크롤과 집중 보기의 차트 조작을 구분한다. 집중 보기는 같은 화면을 넓히며
  현재 공고·조건·선택 회차·오른쪽 상세를 유지한다.

## 실제 화면 피드백 반영 — 2026-09-08

사용자는 시안보다 실제 dev의 과거 회차 구조·디자인을 선호했다. 이 표의 숫자 우측 정렬,
소수 정밀도, 낙찰값 강조와 행 밀도는 유지한다. 시안의 공간·색상 표현을 그대로 복제하기 위해
표를 새로 만들지 않는다. 기본 흐름은 차트 → 과거 회차 → 선택 회차의 오른쪽 상세다.

같은 날 사용자는 “그날 하한이랑 업체도 제거해 일단 시안대로 가자”라고 요청했다. 이전 기록에서
이를 별도 분석 탭 제거로 좁히고 표의 두 열은 유지한다고 적은 해석을 정정한다. 과거 회차 표와
확대 표의 해당 열 제거는 아직 미반영이다. 실제 참여 명단의 업체 정보는 회차 상세에서 제공한다.
추이 차트 자체를 없애려는 뜻은 아니라는 후속 설명에 따라 흐름을 기본 화면, 분포를 두 번째 보기로 둔다.

- 기존 Eatbid를 기본으로 보존하고 `Toss 기반`을 같은 테마 선택기에 추가한다. v7의 흰 배경,
  파란 강조색, 글자 대비와 경계선을 공통 CSS 토큰으로 적용한다. 라이트/다크와 cookie 복원을 지원한다.
- 차트 색상은 `shared/lib/chart-colors` 하나에서 읽는다. 테마 변경은 차트를 다시 만들지 않으며
  선택·줌을 보존한다. 두 동결된 dashboard 소비자의 옛 import는 정확히 한 경로의 tsconfig alias로
  이 파일에 연결한다. 다음 해당 화면 전환 때 import를 직접 갱신하고 alias를 삭제한다.
  레거시 화면의 책임 혼합은 이번 팔레트 이전과 별개이므로 큰 파일을 재작성하지 않았다.
- 메인 화면과 회차 상세에서 원문 추적 ID·hash·build 설명을 제거한다. 해당 값은 API 계약과
  표시 모델에 보존하며 데이터 계보를 삭제하지 않는다. 사용자가 요청한 제품 화면 정리다.
- “마지막 열은 지금 값을…” 설명을 제거한다. 값을 입력하기 전에는 빈 가정 계산 열도 숨긴다.
  값을 직접 입력했을 때 기존 계산 열의 제목은 가정임을 유지한다.
- 개찰 완료 공고의 중복 복기 안내를 제거한다. 선택이 없으면 차트가 빈 상세 공간을 쓰고,
  회차를 선택하면 같은 표와 차트 옆에 상세가 열린다.
- 조건 메뉴는 선택 후 닫힌다. Base UI LinkItem의 기본값은 `closeOnClick=false`이므로
  이 단일 선택 필터에서 명시적으로 닫도록 설정했다. 다중 선택 설계를 확정했다는 뜻은 아니다.

## 검증 근거와 남은 범위

실제 dev 공고 5270에서 88.000 하한은 과거 6행, 전체 하한은 7행이었다. 같은 날의 복수 회차는
날짜를 변조하지 않았으며 표와 별도 점으로 선택한다. 현재 공고를 제외한 값 있는 점은 5개다.
조회 기간 5년은 수집 완료 주장이 아니다. 현재 보유 데이터의 기간만 차트에 나타난다.

실제 Chromium에서 테마 전환 전후 동일 캔버스·회차 5274 명단 6건·현재 공고 유지,
cookie 재접속 복원, 하한 필터 왕복을 확인했다. 1440×1000와 1920×1080에서는 문서가
viewport 안에 들어가며 375×812는 문서 세로 스크롤을 사용하고 페이지 가로 넘침이 없었다.
관련 Web 테스트 285개(41개 파일), typecheck와 전체 architecture/계약 gate를 통과했다.
범위 lint 오류는 없고 미변경 rehearsal 모듈의 기존 배열 정렬 경고 4건은 남아 있다.
커밋 이후 AI advisory 결과는 최종 worklog에 기록한다.

첫 advisory의 조건 불일치 지적은 실패하는 테스트로 재현해 반영했다. 응답 cohort의 존재와 함께
명시한 하한율·낙찰 방식·기간의 일치를 검사한다. 반면 차트 이탈 즉시 후보를 지우는 제안은
캔버스 밖 후보 버튼으로 겹친 회차를 선택하는 동작을 막으므로 채택하지 않았다.

전체 화면을 시안과 픽셀 단위로 일치시켰다는 주장은 하지 않는다. 관심·최근 본 공통 rail,
복수 기관 비교, 기관 진입 화면, 상단 필터만 고정하는 헤더 분리, 큰 이력의 점진 조회는 후속 범위다.
현재 차트는 첫 조회 최대 60행, 과거 회차 확장은 최대 10페이지를 읽는다. 기간 버튼과 조회 완료량을
같은 의미로 표현하지 않는다. API meta.cohort가 없는 구버전 서버 응답은 새 비교 조건 결과로 공개하지 않는다.

## 시안과 dev를 함께 검토하는 반복 절차 — 2026-09-08

사용자가 시안과 계속 비교하며 부족한 점도 함께 진행하도록 요청했다. 기준은 v7 시안과 최신 사용자
피드백이다. 시안의 고정 예시 데이터는 실제 API 값이나 수집 완료의 증거로 사용하지 않는다.
각 변경에서 같은 viewport의 시안·dev를 확인하고, 현재 작업 한 묶음과 남은 차이를 이 표에 갱신한다.
실제 과거 회차 표의 정렬·밀도·정밀도는 유지하며 공통 frame·shadcn·차트 엔진을 재사용한다.

| 비교 영역 | 이번 반영 | 남은 차이와 다음 검토 |
|---|---|---|
| 현재 공고 요약 | 제목을 별도 행에 두고 상태 영역의 여백·보조 글자 위계를 줄였다. | 현재 공고 상세를 오른쪽에서 여는 명시적 진입은 후속이다. |
| 과거 이력 필터 | 공고 요약 아래 독립 행으로 분리했다. 일반 보기 640px 이상에서 필터만 고정한다. | 기관·지역·복수 품목 선택은 확인된 관계와 API 범위가 먼저다. |
| 차트 조작 | 확대/축소 보기를 상단으로 옮기고 반복 안내를 제거했다. 개찰일 KST 축을 명시했다. | 날짜별 점·선의 연결 조건은 기존 사실 기준을 유지한다. |
| 과거 회차 | 큰 집중 화면에서 표 높이를 늘리고 제목·열 제목을 유지한 채 목록만 스크롤한다. | 많은 회차의 점진 조회와 복수 기관의 구분은 후속이다. |
| 오른쪽 상세 | 일반 보기에서 필터 아래에 고정하고 긴 명단만 내부 스크롤한다. | 현재 공고 정보와 선택 회차를 전환하는 구조, 좁은 화면에서 상세를 여는 방식이 남아 있다. |
| 공통 도구 | 이번에는 기존 셸을 재사용했다. | v7의 관심·최근 본 도구와 기관 비교 선택을 아직 구현하지 않았다. 아래 탐색 구조 제안을 다음 검토로 둔다. |
| 실데이터 | 기존 조회 조건 검증과 원문 정밀도를 유지했다. | 품목 미확인·업체 번호 표시를 확인된 관계로 해결하는 작업이 다음 데이터 단위다. |

비교 전후 1440×1000의 제목 영역은 135px에서 74px로 줄었고, 과거 회차 시작점은 798px에서
752px로 올라왔다. 1024×768의 과거 회차 시작점은 1001px에서 786px로 올라왔다.
1440×1000와 1920×1080의 집중 화면은 문서 전체 세로 스크롤을 만들지 않는다. 낮거나 좁은 화면은
문서 스크롤을 사용한다. 375px에서는 필터를 고정하지 않아 본문을 가리지 않게 한다.

실제 브라우저에서 일반 보기 스크롤 후 필터 top 56px·상세 top 128px, 중앙 자체 overflow 없음,
집중 보기에서 표를 80px 스크롤해도 열 제목 위치 유지, 보기 전환 후 선택 회차 5274와 명단 6건
유지를 확인했다. 테스트는 기존 구조 명세를 새 배치에 맞추고 DOM만 복제하는 별도 테스트는 추가하지 않았다.

사용자는 이어서 왼쪽 메뉴의 처리도 물었다. 현재 `ApplicationShell`이 기존 `nav-config`의 오늘·학교 찾기·
개찰 속보·업체·내 성적·납품·내 사업자를 공통으로 노출한다. 공고 분석만의 새 메뉴가 아니다.
제안은 시안처럼 주 탐색을 상단에 두고, 관심·최근 본을 오른쪽에 두는 것이다. MVP의 진입은 실제로
완성한 공고 찾기부터 제공하고 기관·업체·내 기록은 기능 준비에 맞춰 노출한다. 이번 UI 변경에
공통 탐색을 조용히 갈아끼우지는 않았다. 다음 변경에서 기존 셸을 한 번 수정하고 route별 복제는 하지 않는다.

### 탐색 제안 재검토 — 같은 날 후속 대화

사용자는 설정·대시보드·현재 공고·다른 지역 탐색과 월 50만원 수준의 가치를 제공할 업무 서비스를
고려해 메뉴부터 함께 기획하자고 했다. 앞의 상단 주 메뉴 전환은 보류한 제안이며 확정 결정이 아니다.
제품 방향의 권위는 기존 `roadmap.md`와 `product-and-quality.md`에 그대로 둔다.

현재 유력한 검토안은 홈·탐색·내 투찰·결과처럼 업무를 묶은 상단 탐색과 화면별 작업 공간이다.
사용자는 토스의 상단 NAV와 오른쪽 도구가 기능을 압축하고 넓게 보이게 한다는 장점을 다시 제시했다.
엔터프라이즈라는 이유로 영구적인 왼쪽 메뉴를 강제하지 않는다. 설정은 공통 진입에서 열고 설정 화면
안에서만 왼쪽 세부 메뉴를 사용할 수 있다. 지도는 지도·목록, 분석은 차트·회차 표로 폭을 배분한다.

남기며, 정보구조 확정 전에는 공통 셸 메뉴를 변경하지 않는다.
워크스페이스·법적 사업자 문맥, 사업자 기준 지역과 일시적 탐색 필터를 혼합하지 않는다.

### 지도와 대시보드를 포함한 작업 공간 검토안

사용자는 실제 참여 경쟁이 적은 지역을 지도에서 찾는 기능도 계획에 포함하도록 요청했다.
다음은 대화 중인 제안이며 이번에 구현한 메뉴나 완료한 기능이 아니다.

- 공통 탐색은 홈·탐색·내 투찰·결과 복기 같은 업무 단위로 묶는다. 사업자 관리·설정은 공통 진입을 둔다.
  공고 분석은 공고·기관·지도에서 선택한 대상의 작업 공간이며 빈 분석 메뉴를 미리 만들지 않는다.
- 홈은 현재 검토 중 공고, 다가오는 마감, 관심 기관 신규 공고, 확인할 변경·결과를 우선한다.
  전국 탐색 결과를 홈의 업무 목록과 자동으로 같은 집합으로 취급하지 않는다.

  단계적으로 표시한다. 전국 개별 공고 점을 처음부터 모두 렌더링하지 않는다.
- 지도 비교는 같은 품목·하한율·기간의 참여업체 수, 표본 공고 수와 분포를 함께 제공한다.
  소표본·결측을 낮은 경쟁으로 칠하지 않고, 참가제한지역·기관 소재지·공고지역의 의미를 구별한다.
  지도 경계 코드와 eaT 지역 코드의 명시 매핑, 집계 계약·원본 근거가 확인된 범위부터 구현한다.

  홈은 업무 목록, 지도는 넓은 지도와 결과 목록 등 화면마다 적절한 폭·스크롤 규칙을 갖는다.
- 사용자는 오른쪽 관심·최근 본·내 공고 바로가기를 선호하지만 본문이 좁아질 것을 우려했다.

  두 개의 넓은 패널로 동시에 나열하지 않고 하나의 보조 공간에서 전환한다. 닫으면 그 폭을 본문에
  돌려주며 목록 스크롤·선택·차트 상태는 보존한다. 좁은 화면에서는 일시적인 겹침 표시를 검토한다.

### 전역 메뉴와 전체 폭 지면의 실제 구현 — 2026-09-08
