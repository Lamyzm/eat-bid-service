# 공고 dev의 비교 조건과 차트 통합 계획

목표는 현재 공고 → 같은 조건의 기관 이력 → 선택 회차 명단의 흐름을 실제 API로 완성하는 것이다.
계획 작성·실행 스킬의 작은 검증 단위로 진행하며 기존 DecisionFrame, HistoryTable,
AttemptSelectionProvider, shadcn 메뉴와 설치된 Lightweight Charts를 재사용한다.

## 결정과 적용 범위

- 공고 하한율과 낙찰 방식이 같은 기관 이력을 기본 조회한다. 하한율 전체와 미확인을 구별한다.
  88/90 같은 고정 목록을 만들지 않고 원본의 exact 하한율을 사용한다.
- 기간은 KST 개찰월이며 조회 전에 서버 조건으로 전달한다. 표·차트·페이지는 같은 응답을 사용한다.
- 품목은 회차 응답의 codeValueId만 사용한다. 현재 공고의 itemLabel로 ID를 추측하지 않는다.
- 전국/지역 분포의 현 계약은 품목 조건, 전체/미확인 하한, 12개월 초과 기간을 지원하지 않는다.
  이 조건에서는 요청하지 않고 제한을 명시한다. 몰래 필터를 무시한 분포를 보여주지 않는다.
- 차트의 낙찰값은 원천 SAJEONG_PCT를 전달한 winRate다. 분모가 예정가격인 관측값이며
  기초금액 대비 awardedBidRate 및 dayFloorRate와 구별한다. 원천/DB 수치와 계약 의미는 바꾸지 않는다.
- 한 줄로 이어지는 회차는 확인된 품목·하한율·낙찰 방식이 같아야 한다. 미확인 조건은 점으로만 보인다.
- 기본 비율 창은 선택 하한율 -0.100 ~ +0.700%p, 전체/미확인은 관측 전체 범위다.
  이것은 표시 범위이며 추천이나 예측 구간이 아니다. 정확값은 최소 소수 셋째 자리로 읽는다.
- 일반 보기의 문서 스크롤과 집중 보기의 차트 조작을 구분한다. 집중 보기는 같은 화면을 넓히며
  현재 공고·조건·선택 회차·오른쪽 상세를 유지한다.

## 변경 분류와 제외

EAT-112는 명시 query를 보내는 소비자에게만 조건 meta와 낙찰 방식 ID가 더해지는 additive 계약이다.
새 DDL, 수집/replay 변경, 데이터 값 보정, production 배포는 하지 않는다. EAT-103의 mart build 전환
정합성 문제는 독립 과제이며 이번 화면 통합으로 해결됐다고 주장하지 않는다.
기존 시안 worktree의 문서·미커밋 차트는 보존하며 이번 dev 구현과 혼합 커밋하지 않는다.

## 실제 화면 피드백 반영 — 2026-09-08

사용자는 시안보다 실제 dev의 과거 회차 구조·디자인을 선호했다. 이 표의 숫자 우측 정렬,
소수 정밀도, 낙찰값 강조와 행 밀도는 유지한다. 시안의 공간·색상 표현을 그대로 복제하기 위해
표를 새로 만들지 않는다. 기본 흐름은 차트 → 과거 회차 → 선택 회차의 오른쪽 상세다.

같은 날 추가 피드백으로 그날 하한·업체의 별도 분석 탭을 제거했다. 추이 차트 자체를 없애려는 뜻은
아니며 처음 시안을 우선한다는 사용자 설명을 반영해 흐름을 기본 화면, 분포를 두 번째 보기로 둔다.
과거 회차 표의 관측 하한값·낙찰 업체와 참여 명단은 계속 제공한다.

- 기존 Eatbid를 기본으로 보존하고 `Toss 기반`을 같은 테마 선택기에 추가한다. v7의 흰 배경,
  파란 강조색, 글자 대비와 경계선을 공통 CSS 토큰으로 적용한다. 라이트/다크와 cookie 복원을 지원한다.
- 차트 색상은 `shared/lib/chart-colors` 하나에서 읽는다. 테마 변경은 차트를 다시 만들지 않으며
  선택·줌을 보존한다. 두 동결된 dashboard 소비자의 옛 import는 정확히 한 경로의 tsconfig alias로
  이 파일에 연결한다. 다음 해당 화면 전환 때 import를 직접 갱신하고 alias를 삭제한다.
  레거시 화면의 책임 혼합은 이번 팔레트 이전과 별개이므로 큰 파일을 재작성하지 않았다.
- 메인 화면과 회차 상세에서 원문 추적 ID·hash·build 설명을 제거한다. 해당 값은 API 계약과
  표시 모델에 보존하며 데이터 계보를 삭제하지 않는다. 사용자가 요청한 제품 화면 정리다.
- “마지막 열은 지금 값을…” 설명을 제거한다. 값을 입력하기 전에는 빈 가정 계산 열도 숨긴다.
  값을 직접 입력했을 때 기존 계산 열의 제목은 가정임을 유지한다.
- 개찰 완료 공고의 중복 복기 안내를 제거한다. 선택이 없으면 차트가 빈 상세 공간을 쓰고,
  회차를 선택하면 같은 표와 차트 옆에 상세가 열린다.
- 조건 메뉴는 선택 후 닫힌다. Base UI LinkItem의 기본값은 `closeOnClick=false`이므로
  이 단일 선택 필터에서 명시적으로 닫도록 설정했다. 다중 선택 설계를 확정했다는 뜻은 아니다.

## 검증 근거와 남은 범위

실제 dev 공고 5270에서 88.000 하한은 과거 6행, 전체 하한은 7행이었다. 같은 날의 복수 회차는
날짜를 변조하지 않았으며 표와 별도 점으로 선택한다. 현재 공고를 제외한 값 있는 점은 5개다.
조회 기간 5년은 수집 완료 주장이 아니다. 현재 보유 데이터의 기간만 차트에 나타난다.

실제 Chromium에서 테마 전환 전후 동일 캔버스·회차 5274 명단 6건·현재 공고 유지,
cookie 재접속 복원, 하한 필터 왕복을 확인했다. 1440×1000와 1920×1080에서는 문서가
viewport 안에 들어가며 375×812는 문서 세로 스크롤을 사용하고 페이지 가로 넘침이 없었다.
관련 Web 테스트 283개(41개 파일), typecheck와 전체 architecture/계약 gate를 통과했다.
범위 lint 오류는 없고 미변경 rehearsal 모듈의 기존 배열 정렬 경고 4건은 남아 있다.
커밋 이후 AI advisory 결과는 최종 worklog에 기록한다.

전체 화면을 시안과 픽셀 단위로 일치시켰다는 주장은 하지 않는다. 관심·최근 본 공통 rail,
복수 기관 비교, 기관 진입 화면, 상단 필터만 고정하는 헤더 분리, 큰 이력의 점진 조회는 후속 범위다.
현재 차트는 첫 조회 최대 60행, 과거 회차 확장은 최대 10페이지를 읽는다. 기간 버튼과 조회 완료량을
같은 의미로 표현하지 않는다. API meta.cohort가 없는 구버전 서버 응답은 새 비교 조건 결과로 공개하지 않는다.
