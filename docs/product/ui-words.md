# 화면 낱말 — 단추·라벨·안내·숫자에 쓰는 말 (초안)

화면에 보이는 글을 쓰거나 고칠 때 이 표를 먼저 본다. 단추·라벨·탭·칩 이름·`aria-label`·빈 화면·오류 문장·도움말·숫자 옆
설명이 모두 들어간다. 같은 것은 앱 어디서나 같은 말로 부른다.

**초안이다.** 2026-11-17 사용자 진단("화면 곳곳의 단서 문장을 설명 없이 못 읽는다, 사용자들이 전부 부정적으로 본다")과
아버지 복기 통화(2026-10-14: 성적 숫자를 누르면 그 공고, 학교 이름 먼저, 기호 대신 문장)를 바탕으로, onnuri-attendance의 같은
문서 틀을 옮겨 왔다(#218). 지금 화면의 문구는 아직 이 표대로 고치지 않았다 — 고치는 일은 별도 issue에서 화면마다 사용자와
하나씩 본다. 그때 이 표의 줄을 확정하거나 바꾸고, 다 끝나면 `status: active`로 올린다.

앞선 문서 [`../COPY-GUIDE.md`](../COPY-GUIDE.md)(2026-08-27)의 아버지 입찰판 원본 낱말(잘 나온 구간 · 자주 걸린 값 · 밀림 ·
하한미달 · 내 투찰 버릇 · 내 성적 · 기초가 · 하한율 · 투찰 · 개찰 · 표본 부족)은 그대로 이어받는다.

## 원칙 — 이것이 이긴다

0. **설명·안심 문장을 쓰지 않는다.** "남한테 보이지 않아요", "문자로 결제를 받지 않아요" 같은 변명·안심 문구로 불안을
   달래지 않고 숫자와 구조로 보인다(2026-11-17 사용자: "쓸데없는 말 쓰지 말고 UI랑 신뢰성 있는 뷰로").

1. **화면은 사장님 질문에 답한다. 우리 실험 기록에 답하지 않는다.** "이 공고에 얼마 넣나", "지난달 잘했나", "놓친 공고가
   있나"가 질문이다. 방법을 어떻게 검증했는지는 질문이 아니다.
2. **우리 코드·연구·문서에서 만든 말은 화면에 쓰지 않는다** — 아래 "쓰지 않는 말". 사장님은 eaT·나라장터·은행에서 늘 보던 말을
   쓴다.
3. **한 화면, 한 답.** 같은 질문에 답을 셋 나란히 두고 사용자에게 고르게 하지 않는다. 방법이 여럿이면 우리가 하나를 골라 낸다.
4. **이름이 먼저, 숫자가 다음, 근거는 누를 때.** 학교·업체 이름을 줄의 첫머리에 두고, 숫자 하나를 두고, 왜 그 숫자인지는
   "왜 이 금액?" 같은 열기 안에 둔다. 단서 문장을 본문 자리에 늘어놓지 않는다.
5. **값은 기초금액 대비 %로.** "88.641%"처럼 쓰고 하한율 묶음 머리("하한 90%")가 분모를 말한다. 사정률을 앞세우지 않고 원 금액은
   확인용으로만 작게 둔다(ADR 0074, 2026-11-17 사용자).
6. **기호 대신 문장.** `·` 로 이은 숫자 띠, `~`, `→` 만으로 뜻을 전하지 않는다. 한 줄에 한 사실을 문장으로 쓴다.
7. **성적은 늘 기대 대비로, 쌓아서.** 공고 한 건의 낙찰은 대부분 추첨이다. "40건 중 1건"처럼 한 달 낱개만 보여 주지 않고
   "기대 0.8건 · 실제 1건"처럼 기대와 함께, 여러 달을 쌓아 보여 준다. "보장"·"반드시" 같은 말을 쓰지 않는다.
8. **약점은 숨기지 않되 제자리에 둔다.** 표본이 모자라거나 금액을 못 낸 때는 그 칸에 한 문장으로 말한다("이 지역은 지난 3달
   공고가 적어 금액을 내지 않았어요"). 화면 머리마다 단서를 반복하지 않는다.

## 쓰는 법

- 새 글을 쓰면 [`ext-korean-humanizer`](../../.agents/skills/ext-korean-humanizer/SKILL.md)로 번역투·AI 말투·쉼표 과다·명사 과다를
  스스로 한 번 짚는다. 고칠 때도 뜻·숫자는 그대로 둔다.
- 이 표에 없는 낱말을 새로 들일 때는 같은 화면과 같은 일의 다른 화면에서 이미 쓰는 말을 grep으로 찾아 그 말을 쓴다. 갈리면
  이 표에 한 줄 더하고 쓴다. 코드 이름·주석·ADR에서 쓰던 말을 화면 글로 옮겨 적지 않는다.
- 리뷰어는 바뀐 화면 글을 이 표와 대어 본다([`REVIEW.md`](../../REVIEW.md) 1절 화면 문구 줄). 낱말을 바꿀 때는 그 글을 찾는
  시험·e2e도 grep한다 — 특히 "없음" 단언이 옛 글로 남으면 늘 통과한다.

## 쓰지 않는 말 (연구·코드 말) — 초안

| 쓰지 않는다 | 대신 (초안) | 까닭 |
| --- | --- | --- |
| 검증 · 검증했어요 · 고를 때 쓰지 않은 회차 | (화면 본문에 쓰지 않음 — 근거 열기 안에서 "지난 N달 공고로 시험해 봤어요") | 방법 검증은 사장님 질문이 아니다 |
| 회차 | 공고 | 우리 데이터 모델 말(`AuctionAttempt`)이다 |
| 무작위 · 무작위 자리 · 운 | (쓰지 않음 — 성적은 "예전 방식이었다면 N건"과 견준다) | 비교 기준이 우리 실험 설계다 |
| 기대 · 기대 낙찰 | 평균이라면 · 보통이면 N건 | "기대값"은 통계 말이다 |
| 예정가격 추첨 평균 · 적분 | (쓰지 않음) | 계산 방법이다 |
| …판 (`2026-10-10판` 같은 규칙 버전) | (운영자 화면에만) | 계산 버전은 재현용 기록이다(루트 AGENTS 7). 아버지 말 "판(시장)"은 이것과 다르며 쓸 수 있다 |
| 아침 갱신 · 맞춤 금액 · 전국 공식 (방법 이름) | N월 값 (하나만) | 방법 이름을 고르게 하지 않는다(원칙 3) |
| 1등 자리 · 자리 · 빈자리 | 낙찰되는 금액 · 이 금액이면 1등 | 우리 분석 말이다 |
| 사정률 (단독으로) | 예정가격이 기초금액의 몇 % 였는지 (필요할 때만) | eaT 화면 말이지만 사장님이 숫자로 판단하는 값이 아니다. 운영자 화면에서는 쓸 수 있다 |
| 표본 · n · 건수 띠 (`1,184회차 중 24회`) | "지난 3달 공고 120건을 봤어요" 같은 문장 | 숫자 띠는 읽히지 않는다(원칙 6) |
| 참고로만 보세요 · 뚜렷한 차이가 나지 않았어요 | (근거 열기 안에 한 문장, 또는 금액을 내지 않음) | 쓸 수 없는 값이면 내지 않는다(원칙 8) |
| 운영자 전용 (사용자 화면 안의 표지) | (운영자 화면을 따로 둔다) | 사용자 화면에 운영자 칸이 섞이면 답이 여럿이 된다 |

## 어조 — 판정 대기

지금 화면은 해요체("확인하지 못했어요")이고, [`../COPY-GUIDE.md`](../COPY-GUIDE.md)는 합니다체("정해집니다")를 적었다. 한 화면
안에서는 섞지 않는다. 어느 쪽으로 맞출지는 화면 문구를 고치는 issue에서 사용자가 정한다.
