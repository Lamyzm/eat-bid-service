# PLAN-REFACTOR — 기초공사 계획 (2026-08-28 · architect)

전수검사(`AUDIT-SOURCE`·`AUDIT-PIPELINE`·`AUDIT-SERVE`·`AUDIT-STRINGS`)와
설계(`SPEC-SSOT`·`SPEC-SCHOOL-ID`)·부채(`DEBT`) 위에 얹는 **순서와 판정**만.
근거는 그 문서들에 있다. **여기는 무엇을 언제, 무엇을 보면 끝났는지만 본다.**

## 0. 감사가 바꾼 전제 — **재파싱이 필요한 게 훨씬 적다**

레이크에 **이미 있는데 서빙이 안 읽는 것**: `institution_code` 100% · `sido_code` 100% ·
**`areas[].sgg_cd` 97.8%** · **`bids.valid` 100%** · `bid_at` 100% · `is_qualification_review` 100%.

**→ A-8·A-9·자격 코드 대조·판정 8곳 통합·시장지도 PK가 전부 재파싱 없이 닫힌다.**
재파싱이 진짜 필요한 건 **`SIGUNGU_CD`(소재지)와 `SHIPPER_CD`** 둘뿐이고,
**재수집**이 필요한 건 `P_PRGRS_STAT_CD` 구멍(공고의 92.9%만 받는다) 하나다.

## 2. 순서 제약 — 어긴 순서로 하면 손해가 난다

```
S-2(update_lake 지역코드) ──► 재파싱          ※ 안 고치면 재파싱해도 다음 날 증분이 다시 비운다
자격 코드 적재(sgg_cd)   ──► ?region= 배선    ※ 역순이면 지역제한 공고가 0건이 된다 (S-3: 완전일치 통과 0/121)
purr_cd 적재 + 카운터    ──► 문턱 제거         ※ 역순이면 문턱 제거가 A-8을 고치는 게 아니라 숨긴다
front 표기(작은 n)       ──► 로더 문턱 제거     ※ 화면이 말할 준비가 먼저다
7a(정의 n=1)            ──► 판정 8곳 통합 ──► 화면 중복 제거
X20(purr_cd 키)         ──► 원자화             ※ 역순이면 원자화 테이블을 두 번 만든다
R10(zod 현행화)         ──► 웹 로컬타입 제거 ──► react-query ──► Swagger 타입
```

## 7. 원자화 — **X20 뒤에** (리더 요구 ②)

**자격 판정이 문자열인 진짜 이유가 이것이다** — 조인할 테이블이 없으니 배열을 꺼내 문자열로 맞춘다.

| 지금 (jsonb) | 풀면 | PK |
|---|---|---|
| `firms.regions` | `firm_region` | `(biz_no, sgg_cd)` |
| `open_auctions.allowed_regions` | `open_auction_area` | `(bid_no, sgg_cd)` + `pdlc_cd` |
| `school_auctions.categories` | `auction_category` | `(bid_id, category)` |
| `schools.cat_counts`·`by_cat_floor` | `school_floor_stat` | `(purr_cd, category, floor_rate)` |

- **§5-5와 충돌하지 않는다**: 컬럼 추가 + 새 테이블이고 `schools.id` 형식을 안 건드린다.
  기존 jsonb 컬럼은 **호환용으로 남긴다**(`by_floor`와 같은 취급).
- **순서: X20이 먼저다.** 원자화 PK에 `purr_cd`를 쓰려면 그게 먼저 있어야 한다.
  역순이면 `school_id` 기반으로 만들었다가 **두 번 만든다.**
- 완료 판정: `eligibleFor`가 **문자열 비교 0회**, 자격 질의가 조인 1회로 끝남.

## 8. 이 계획이 못 하는 것

1. **§0-1(알고리즘 복사) 재발을 구조로 못 막는다.** grep 가드뿐이고 `864e5`류는 오탐으로 뺐다.
2. **A27(같은 질문을 다른 엔드포인트로)을 막는 게 "배치"뿐이다.**
3. **비율 폐기선을 세 번 세웠고 세 번 다 폐기했다.** 세 번째는 **주소 파서로 코드북을 채점하는 순환**이었고
   99.194%로 통과까지 했다. **A7의 완료 판정도 "행 수"로 적혀 있다 — 같은 함정일 수 있다.**
4. **`valid`의 원본 검증은 재파싱으로도 안 닫힌다.** `EXCL_RSN`이 22,673 중 12건이다.
   3,745,456건의 무효 판정을 대조할 원본이 없다 — **계산값으로 남고, 그렇게 표기하는 것 외에 방법이 없다.**
5. **`bids.rank`가 무엇의 순위인지 데이터가 말해주지 않는다.** 배선하지 않는다.
6. **버퍼가 없다.** 9/15 관측창까지 안 끝나면 10월이다.
7. **🔴 확인 없이 단정하는 것 — 이번 주 최대 실패원이고, 이 계획이 못 막는다.**
   리더가 오늘 세 번(차단 이력 전제 · 없는 결함을 고치다 분석판을 죽임 · `전남광주통합특별시`를 없는 이름이라 단정),
   내가 세 번(`PDLC_NM`을 품목으로 · 소재지로 · `_SGG_CANON`을 코드 증거로),
   critic이 두 번(같은 인용 · 개명을 코드 분열로).
   **리더가 그 실수를 하면 팀 전체가 그 위에서 움직인다** — 내가 §2-c 결정 ①의 근거를 그렇게 받았다.
   지금 있는 장치는 ⚠ 표기와 서로 밟기뿐이고, **둘 다 사람이 하는 것이다.**
