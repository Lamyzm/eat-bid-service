# C4 모델

이 문서는 목표 아키텍처의 경계를 C4의 Context, Container, Component, Deployment 관점으로
기록한다. 실제 배치 흐름은 [runtime-and-deployment.md](runtime-and-deployment.md)를 따른다.

## Level 1 — System Context

```mermaid
flowchart LR
    user[급식 납품업체 운영자]
    admin[eatbid 운영자]
    eat[eaT/NeaT 공개 시스템]
    auth[인증 제공자]
    system[eatbid\n입찰 분석·운영 워크스페이스]

    user -->|공고 탐색, 분석, 사업자별 기록| system
    system -->|사실·분석·업무 상태| user
    admin -->|재처리, 격리 검토, 운영| system
    system -->|공개 데이터 요청| eat
    eat -->|XML/공고·개찰·코드 데이터| system
    system <-->|사용자 인증| auth
```

시스템 경계 밖의 NeaT 투찰 화면에서 사용자가 직접 제출한다. eatbid는 투찰 자동화 시스템이
아니며 사용자 자격을 정부를 대신해 확정하지 않는다.

## Level 2 — Containers

```mermaid
flowchart TB
    user[사용자 브라우저]
    web[Web\nNext.js]
    api[Server\nNestJS modular monolith]
    wf[Dataplane jobs\nPython image on Argo Workflows]
    pg[(PostgreSQL\ningest/core/app/mart)]
    r2[(R2\nimmutable raw)]
    eat[eaT endpoints]
    argo[Argo Workflows]
    argocd[Argo CD]
    ghcr[GHCR]
    git[GitHub monorepo]

    user --> web --> api
    api -->|read core/mart, write app| pg
    wf -->|capture| eat
    wf -->|raw objects| r2
    wf -->|run metadata, publish facts/marts| pg
    argo -->|starts pods from one template| wf
    git -->|CI builds immutable images| ghcr
    git -->|GitOps manifests| argocd
    argocd -->|deploys web/server/templates| web
    argocd --> api
    argocd --> argo
    ghcr --> web
    ghcr --> api
    ghcr --> wf
```

| 컨테이너 | 책임 | 쓰기 권한 |
|---|---|---|
| Web | App Router route composition/private presentation, shell, capability, resource별 API와 사용자 상호작용 | DB 직접 접근 없음; Nest public API만 소비 |
| Server | 인증/권한, 업무 규칙, query facade, app command | `app`; `core`/`mart` read-only |
| Dataplane | discover/capture/normalize/validate/project/replay | R2 raw, `ingest`, 제한된 `core`/`mart` |
| PostgreSQL | canonical facts, user state, derived analytics | 역할별 분리 |
| R2 | source response evidence와 backup/export | append-only service credential |
| Argo Workflows | 데이터 작업 DAG, 재시도, 동시성, 이력 | Kubernetes workflow resources |
| Argo CD | 선언된 배포 상태 동기화 | 앱 데이터 작업 실행 안 함 |

## Level 3 — Web components

```mermaid
flowchart TD
    route[app\nroute lifecycle + RSC composition]
    local[route-private\n_model + _ui + _lib]
    shell[shell\nproviders + navigation + chrome]
    capability[capabilities\nreusable user intents + orchestration]
    resource[api resources\nrequests + Query Options]
    routing[routing\ntyped screen path builders]
    transport[api/_transport\nHTTP + Problem Details]
    shared[shared\nconfig + UI primitives]
    contracts[packages/contracts\nbrowser-safe Zod operation subpaths]
    api[Nest public API]

    route --> shell
    route --> local
    route --> capability
    route --> resource
    route --> routing
    local --> resource
    local --> shared
    local --> routing
    shell --> shared
    shell --> routing
    capability --> resource
    capability --> shared
    capability --> routing
    resource --> transport
    resource --> shared
    resource --> contracts
    routing --> contracts
    transport -->|validated HTTP| api
```

- **app:** Next route graph, metadata, loading/error/not-found와 Server Component composition
- **route-private:** 한 segment에만 필요한 presentation model, UI와 interactive leaf
- **shell:** theme/query/toaster provider, navigation과 application chrome
- **capabilities:** 독립된 intent와 command/permission/feedback lifecycle을 가진 재사용 사용자 여정
- **api:** 같은 HTTP resource의 request, runtime parser, Query Options와 client/server public entry
- **routing:** 반복되는 동적 화면 URL을 generated `Route`로 검증하는 작은 resource별 builder
- **api/_transport:** endpoint를 모르는 status, Problem Details, JSON과 `AbortSignal` 처리
- **shared:** 범용 config/lib/UI primitive

Web은 하나의 deployable이다. 이 경계는 microfrontend가 아니라 변경 이유와 의존 방향을 드러내는
modular-monolith 경계다. cross-slice import는 작은 `index.ts`/`server.ts`를 통과하며 capability끼리 서로의 내부를
참조하지 않는다. Server Component가 기본이고 browser API, event, form 또는 query subscription이
필요한 leaf만 Client Component다. 상세 규칙은
[frontend-application-foundation.md](frontend-application-foundation.md)와 ADR 0023을 따른다.

HTTP operation은 `packages/contracts`의 framework-neutral semantic path와 implementation owner에서 Nest
adapter path/version, OpenAPI template와 Web request builder를 파생한다. Web은 browser-safe resource
subpath만 소비한다. Next 화면 URL은 `app/` file-system과 generated route type이 권위이며 반복되는
동적 URL만 작은 resource별 builder를 둔다. API registry와 화면 route를 같은 상수 목록으로 합치지 않는다.

## Level 3 — Server components

```mermaid
flowchart LR
    http[HTTP/API boundary]
    auth[Identity & access]
    procurement[Procurement]
    institutions[Institutions]
    suppliers[Suppliers]
    eligibility[Eligibility]
    workspace[Workspace]
    intelligence[Intelligence]
    contracts[Contracts]
    operations[Operations]

    http --> auth
    http --> procurement
    http --> institutions
    http --> suppliers
    http --> eligibility
    http --> workspace
    http --> intelligence
    http --> operations
    contracts -. shared API types .-> http
    eligibility --> procurement
    eligibility --> institutions
    eligibility --> suppliers
    workspace --> procurement
    workspace --> suppliers
    intelligence --> procurement
    intelligence --> institutions
```

- **Procurement:** AuctionAttempt/revision/relation/submission/award 읽기 모델
- **Institutions:** Organization, 외부 식별자, 코드/지역 관계
- **Suppliers:** legal SupplierParty와 source account
- **Eligibility:** 확인 가능한 조건의 tri-state 평가와 근거
- **Workspace:** 사업자별 BidWorkItem, 사용자 기록/확인/복기
- **Intelligence:** 버전된 mart query와 근거 설명
- **Contracts:** DB와 독립적인 HTTP/event DTO
- **Operations:** ingestion freshness, quarantine, mart build 상태의 운영용 read surface

모듈은 한 프로세스 안에서 명시적 application interface로 협력한다. 다른 모듈 테이블을
임의 SQL로 수정하지 않는다. 독립 배포가 필요한 근거가 생기기 전에는 네트워크 경계를 만들지 않는다.
각 module의 HTTP controller는 application use case만 호출하고, Drizzle adapter는 infrastructure
경계 뒤에 둔다. Nest가 DI/lifecycle을 소유하며 Effect 실행과 HTTP 횡단 관심사의 상세 경계는
[backend-application-foundation.md](backend-application-foundation.md)를 따른다.

## Level 3 — Dataplane components

```mermaid
flowchart LR
    discover[discover\nrequest plan + IDs]
    capture[capture\nHTTP + archive]
    normalize[normalize\ntyped records]
    validate[validate\ncontracts + completeness]
    project[project\ncore revisions]
    mart[build marts]
    replay[replay\nselect raw + versions]

    discover --> capture --> normalize --> validate --> project --> mart
    replay --> normalize
```

단일 immutable 이미지가 `eatbid discover|capture|normalize|validate|project|replay` 명령을
제공한다. 단계별 이미지나 임시 파일 계약을 만들지 않고 DB run/observation ID로 연결한다.

## Level 3 — 의미 값과 계약 components

```mermaid
flowchart TB
    source[Pydantic source contract] --> normalize[normalize adapter]
    hub[packages/contracts\nZod atoms + values] --> ingest[ingestion/v1 wire]
    hub --> public[api/v1 wire]
    ingest --> jsonschema[versioned JSON Schema]
    jsonschema --> generated[generated Pydantic v2]
    normalize --> generated
    ddl[packages/db\nDrizzle DDL] --> db[(PostgreSQL exact storage)]
    generated -->|Argo dataplane publish| db
    db <--> adapter[Drizzle row adapter]
    adapter <--> domain[packages/domain\nsemantic values]
    public <--> codec[Zod codecs]
    codec <--> domain
    public --> http[Nest Standard Schema/OpenAPI]
    public --> web[Web API resource\nfetch-boundary runtime parser]
```

`packages/domain`은 시간·금액·비율·수량·좌표의 framework-free 의미와 불변식을 소유한다.
`packages/contracts`는 canonical interchange와 public API의 Zod wire schema를 소유한다. source
Pydantic은 eaT 원본을 소유하고 normalized Pydantic은 versioned JSON Schema에서 생성한다.
`packages/db`는 저장 형식과 migration을 소유한다. Python dataplane은 product server HTTP를 거치지
않고 제한된 role로 발행하며 adapter와 cross-language round-trip fixture가 의미 보존을 검증한다.
“하나의 진실 원천”은 모든 것을 한 파일에 모으는 것이 아니라 같은 질문의 소유자를 하나로 유지한다는
뜻이다. 상세 규칙은
[time-and-value-contracts.md](time-and-value-contracts.md)를 따른다.

구현 경계는 이름까지 고정한다. `AuctionRecord`는 server application 내부 read port이고 공개 wire는
Zod에서 추론한 `AuctionV1Response`다. PostgreSQL row의 `Date | string` 수용과 즉시 Temporal 변환은
`apps/server/src/modules/procurement/infrastructure/drizzle/drizzle-auction-reader.ts`의 `AuctionRow`,
`postgresInstant`, `mapAuctionRow`만 담당한다. ambient 현재 시각은
`packages/domain/src/time/clock.ts`의 exported top-level `systemClock`만 취득한다. 같은 이름의 nested 선언은
exception이 아니며 row adapter의 `AuctionRow`와 `postgresInstant`도 top-level symbol에만 묶인다.

ADR 0023은 이 Level 3 흐름을 Web의 API resource까지 연결한다. legacy 화면은 canonical public
operation이 생긴 vertical slice만 교체하며 없는 market/analysis/work-item 계약을 Web에서 추측하지 않는다.
누락 좌표를 이름 lookup으로 채우는 작업은 별개이며 CRS/provenance를 가진 Argo workflow/backfill로
다룬다.

## Level 4 사용 원칙

클래스 다이어그램을 전역 문서로 고정하지 않는다. 복잡한 aggregate나 알고리즘을 구현할 때만
해당 모듈 문서에서 Level 4를 추가한다. 핵심 불변식은 코드가 아니라
[domain-and-data.md](domain-and-data.md)의 모델과 DB 제약이 기준이다.
