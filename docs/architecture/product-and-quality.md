# 제품 범위와 품질 속성

## 1. 제품 명제

eatbid는 **정부 원본에 기반한 입찰 분석 엔진과, 그 분석을 공고 발견·다사업자 투찰 준비·
결과 복기에 연결하는 급식 입찰 운영 워크스페이스**다.

사용자는 여러 법적 사업자를 한 워크스페이스에서 운영할 수 있다. 하나의 작업 항목은
`Workspace × SupplierParty × AuctionAttempt`다. 이 단위를 지키면 같은 공고라도 사업자별
자격 판단, 검토 상태, 적어둔 금액, 실제 소스에서 관측된 제출 결과가 섞이지 않는다.

## 2. 핵심 사용자 흐름

1. 최신 공고와 변경·재입찰을 발견한다.
2. 선택한 법적 사업자 관점에서 지역 등 확인 가능한 조건을 평가한다.
3. 기관·품목·기초금액·낙찰하한·경쟁 강도·자사 이력을 근거와 표본 수와 함께 분석한다.
4. 검토할 공고를 사업자별 작업 항목으로 만들고 사용자가 판단한 값을 적어둔다.
5. 사용자가 NeaT에서 직접 입력한 뒤 확인 상태를 남긴다.
6. eaT 원본에서 제출·개찰·낙찰 결과를 관측해 작업 항목과 대조하고 다음 판단에 쓸 이력을 만든다.

`BidWorkItem`의 기본 상태는 다음과 같다.

```text
discovered
  → shortlisted
  → value_recorded
  → neat_entry_confirmed_by_user
  → submission_observed_from_source
  → reconciled
```

사용자가 적어둔 값과 eaT/NeaT에 실제 제출된 값은 다른 사실이다. UI와 DB 모두 이를 합치지 않는다.

## 3. 분석 능력

첫 제품 버전에서 지원해야 할 분석 축은 다음과 같다.

- 기관·기관유형·지역별 공고/개찰/낙찰 이력
- 품목 분류와 기초금액 구간별 결과 분포
- 낙찰하한과 예정/기초가격 관련 관측 분포
- 참여 업체 수와 시장 두께
- 업체별 참여·낙찰 이력과 워크스페이스 소유 사업자의 복기
- 과거 시점에 알 수 있었던 데이터만 사용하는 공고 재생(replay)
- 기관/품목의 발주 주기와 다음 관측 시점에 대한 사실 기반 캘린더

모든 분석 결과는 최소한 `sample_n`, 코호트/기간, 원본 실행 또는 릴리스,
`computation_version`, `built_at`, `as_of`를 포함한다. 숫자만 제공하는 분석은 기능 미완성이다.

## 4. 의도적으로 하지 않는 일

- 특정 투찰가 추천 또는 예정가 예측
- 점수·등급·강자 배지처럼 근거를 가리는 단일 판정
- 사용자를 대신한 NeaT 자동 입력/제출
- 지역 일치만으로 전체 자격 충족이라고 단정
- 원본에 없는 품목/지역/기관 코드를 이름 추측으로 발명
- 범용 데이터레이크, 실시간 이벤트 플랫폼, 독립 마이크로서비스를 목적 없이 도입

자격 평가는 `matched | not_matched | unknown`의 세 값이다. 일부 조건만 확인했다면
“지역 조건 일치”처럼 확인한 범위만 말한다.

## 5. 품질 속성 시나리오

| 우선순위 | 속성 | 합격 조건 |
|---:|---|---|
| 1 | 무손실 | 성공한 capture의 응답 바이트는 canonical 공개 전에 R2에 보존되고 content hash로 검증된다. |
| 2 | 추적성 | 모든 `core` revision과 `mart` 결과를 raw observation, 파서/규칙 버전, 실행 ID까지 역추적할 수 있다. |
| 3 | 완전성 | 목록 응답의 `TOT_CNT`와 수집 건수를 실행 단위로 대조하며 불일치 실행은 발행하지 않는다. |
| 4 | 재현성 | 같은 raw 집합과 같은 코드 버전으로 normalize/project하면 동일한 canonical 결과가 나온다. |
| 5 | 멱등성 | 동일 요청·관측·revision을 재실행해도 중복 업무 사실이나 작업 항목이 생기지 않는다. |
| 6 | 원자성 | 부분 수집이나 일부 파싱 성공이 현재 공개 스냅샷을 덮어쓰지 않는다. |
| 7 | 신선도 | 영업시간 중 열린 공고의 source-to-core 지연 p95는 초기 목표 35분 이하로 측정한다. |
| 8 | 정직성 | 알 수 없는 값은 `unknown`/격리 상태로 노출되고 이름·주소 추측으로 대체되지 않는다. |
| 9 | 복구성 | raw와 사용자 상태는 백업되고 정기 restore drill을 통과한다. `core`/`mart`는 raw로 재구성 가능하다. |
| 10 | 이식성 | 로컬 k3d와 후속 Kubernetes 환경이 동일 이미지와 WorkflowTemplate을 실행한다. |

신선도 35분은 운영 측정을 시작하기 위한 **초기 SLO**다. 소스 제한과 사용자 업무시간을
측정한 뒤 ADR로 조정한다. 단일 노드 k3d를 고가용성이라고 표현하지 않는다.

## 6. 성공 지표

- 근거 없는 문자열 ID/조인 수: 0
- 검증되지 않은 수집 실행의 canonical 발행 수: 0
- raw observation으로 역추적 불가능한 신규 canonical 행 수: 0
- 출처/표본/기준시점이 없는 신규 분석 카드 수: 0
- 단위·통화·분모가 정의되지 않은 신규 공개 수치 수: 0
- 동일 실행 재시도 후 논리적 중복 수: 0
- 사용자가 적어둔 값과 source-observed submission을 동일 필드로 저장한 사례: 0
