### 8-② `bids.bid_at` 판정 정정 — 동률 낙찰을 설명하지 못한다

### 9-① 파생 발견: 하한율 이상값에 방어가 없다 — 라이브에 값이 틀린 학교가 있다

`_num` 은 `_price` 와 달리 **범위 검사를 하지 않는다.** 결과:

```
floor_rate = 0.001 인 회차 5건  (전부 개찰완료 · 기관·시군구 있음 → 그대로 적재됨)
```

라이브 DB:

```
school_id = 상주시|상주공업고등학교   (경상북도 상주시, n_auctions 5)
  5회차 전부 floor_rate = 0.001
  by_floor 키가 "0.001" 하나뿐:
    {"n":5, "mean":79.29, "p":[55.78, 57.5, 93.86, 94.44, 94.87],
     "dense":{"lo":55.78,"hi":55.88,"pct":20}, "recur":[]}
```

**이 학교는 문턱 ⑥(5회 이상)을 정확히 통과해서 화면에 있다.** 낙찰률이 55.78~94.87로 흩어져 `mean 79.29` 는 아무것도 뜻하지 않고, `dense` 는 "55.78~55.88 구간에 20%"라 말하는데 그 20%는 **n=1**이다. 하한율이 0.001이면 **모든 투찰이 `valid=true`** 가 되므로 `n_valid` 도 참여 수를 그대로 세고, 낙찰률 55.78% 같은 값이 정상처럼 실린다.

**처방:** `floor_rate` 에 `_price` 와 같은 범위 방어(예: `50 < v <= 100`)를 걸거나, 범위 밖이면 `None` 으로 두고 그 사실을 적재 요약에 세라. **규모는 5회차·1학교로 작지만, 화면에 나가는 값이 통째로 무의미하다.**

### 9-② 파생 발견: 적격심사는 하한율 축에서 거의 완전히 갈린다

```
겹치는 값: 84.245 하나뿐 — 적격심사 1,912 vs 일반 27
```

`by_floor`·`by_cat_floor` 는 하한율이 키라서 **이미 분리돼 있다.** 오염은 `84.245` 버킷에 섞인 **일반 27회차**뿐이며, 방향이 §1-A 가 걱정한 것과 반대다. **하한율을 넘어 합산하는 값**(`med_field`·`market_regions`·`cat_counts`·`n_auctions`)에만 적격심사가 섞인다.

## 10. 정정 — `areas` 빈 목록의 피해 방향이 반대였다 (2026-08-28 18:59)

§1-A·§9 D5 와 초기 보고에서 나는 *"지금 `isUnrestricted` 가 빈 목록을 무제한으로 통과시킨다"* 고 썼다. **`open_auctions` 에 대해서는 틀렸다.**

`fetch_open.py:66` 에 폴백이 있다:

```python
allowed=allowed or ([a.get("sigungu")] if a.get("sigungu") else []),
```

**`001`/`002` 회차는 `areas` 가 100% 비어 있으므로**(실측 2,549/2,549 · 2,552/2,552) 이 폴백이 **항상** 발동해 `[소재지]` 를 채운다. 그래서:

- `open_auctions.allowed_regions` 는 **절대 비지 않는다** (라이브 116건 중 빈 목록 **0건**)
- `isUnrestricted` 의 ① 경로(`list.length === 0`)는 **`open_auctions` 에서 한 번도 실행되지 않는다**
- 대신 `eligibleFor` 가 자격을 **그 한 곳으로 좁힌다**

> **피해는 "아무나 볼 수 있게 된다"가 아니라 "낼 수 있는 사람이 못 본다"다.** 지역 제한이 아닌 방식으로 낸 공고가 학교 소재지 업체에게만 보인다. 레이크 기준 `001`/`002` 는 **109개 시군구**에 흩어져 있다.

**두 사실이 이걸로 다시 설명된다:**
1. team-lead 가 본 *"라이브 121건 중 빈 목록 0건"* — 진짜 없는 게 아니라 **폴백이 덮은 것**이다
2. `QLFC_LMT_YN='Y'` 566건이 오늘 화면에 안 나타나는 이유 — **다른 해로 바뀌어 나타나고 있다**

**빈 목록의 ① 경로가 실제로 도는 곳은 `school_auctions` 가 아니다**(거기엔 `allowed_regions` 컬럼 자체가 없다). 즉 **지금 ① 경로는 사실상 죽은 분기**이고, 폴백을 지우는 순간 **살아나면서 전원 통과로 뒤집힌다.** → 폴백 제거와 `allowed_basis` 분기는 **반드시 같은 배포**여야 한다(`PATCH-WIRING.md` §2-6).

**못 가른 것:** 라이브 116건 중 `allowed == [소재지]` 6건이 폴백 산물인지 진짜 단일 지역 제한인지 **JSON 만으로는 못 가른다.** `003` 회차에도 `areas` 가 자기 시군구 하나뿐인 경우가 **8,377건(003 중 4.5%)** 실재하기 때문이다.
