# UX 검증 로그 — 상설 사용자 검증관(ux)

매 배포마다 같은 사람이 같은 일을 하러 온다는 가정으로 화면을 다시 본다.
전문가 눈이 아니라 **쓰는 사람 눈**으로만 판정한다. 코드는 건드리지 않는다.

## (a) 페르소나

**기본 페르소나 — "김해 축산 62세 사장"**

| 항목 | 내용 |
|---|---|
| 하는 일 | 김해에서 학교급식 축산 납품. 사업자 2개(신성유통·오뚜기축산) |
| 컴퓨터 | PC로만. 엑셀은 쓴다. 웹 서비스는 낯설다 |
| 모르는 말 | 중앙값·분포·표본·리허설·리플레이·앰버·동가 — 통계/영어 용어 전부 |
| 아는 말 | 투찰·개찰·기초가·하한율·밀림·낙찰·무효 (조달 실무 용어) |
| 급한 것 | **"얼마 쓰노"** 하나. 나머지는 다 곁가지 |
| 읽는 법 | 표를 먼저 본다. 그림은 참고. 긴 설명문은 안 읽는다 |
| 실수 반응 | 눌렀는데 결과가 다르면 다시 안 누른다. 물어보지도 않는다 — 그냥 안 쓴다 |

## (b-2) 검증 방식 규약 (2026-08-28 강화)

**손으로 만지는 검증만 인정한다.** 아래는 매 라운드 의무.

| # | 규약 | 이유 |
|---|---|---|
| 1 | `take_snapshot`으로 접근성 트리를 먼저 잡고, **uid 기반 `click`/`fill`/`hover`로 실조작**. `evaluate_script`로 상태를 직접 건드리는 우회 금지 | 실사용자와 다른 경로를 타면 검증이 무의미. 버튼이 실제로 눌리는지까지가 검증 |
| 2 | 과제 시작 `performance_start_trace` → 종료 `performance_stop_trace`. **LCP·인터랙션 지연 기록** | "느려서 못 쓰겠다"도 UX 결함이다 |
| 3 | `list_console_messages` + `list_network_requests` — 실패 요청·**1초 이상 느린 API**를 잡아 사장 체감과 연결 | 화면이 멈춘 것처럼 보이는 이유는 대개 뒤에 있다 |
| 4 | 화면마다 `take_screenshot(fullPage)` 증거 보존 + **"몇 판을 스크롤해야 하는지" 수치 기록** | 길다는 인상을 숫자로 |
| 5 | `emulate`로 **1920 / 1280 두 폭 비교** (PC 우선이되 노트북 1280에서 잘리는 것 확인) | 사장 책상은 1920, 아들 노트북은 1280 |

`evaluate_script`는 **읽기 전용 계측**(스크롤 판수 계산, DOM 존재 확인)에만 쓴다. 조작은 언제나 uid로.

**측정값 기록 형식**: 과제표에 `LCP 1.8s · 최장 인터랙션 320ms · 느린 API 1건(rounds 1.4s)`처럼 병기.

## 2. "지금 무엇을 보고 있나"가 한 문장으로 읽히는가 — **안 읽힌다**

오늘 화면 맨 위 세 줄이 **서로 다른 맥락**을 말한다:
- 헤더: `내 자격 지역 (2)` — 어느 두 곳인지 안 보임
- 제목: `오늘`
- 부제: `어제 전국 289건 개찰 · 최다 전주시(57건)` — 내 지역(김해·창원)과 **무관한 전국 이야기**

분석판은 더 심하다. "지금 보는 것"을 알려면 **4곳을 따로 봐야 한다**: 하한 탭(90/88) + 기간 탭(전체) + 렌즈 탭(흐름) + 공고 컨텍스트 배너. 한 문장으로 요약해 주는 곳이 없다.

## 3. 첫 3초의 눈 vs 가야 할 곳

오늘 화면에서 **눈이 실제로 가는 순서**(크기·색 기준):
1. `1건` (30px, 최대) — 개수일 뿐 **할 일을 가리키지 않음**
2. `8,389,260 원` (24px, 초록) — 시선을 가장 강하게 끄는데 이건 **하한 금액**(내가 넣을 금액이 아님)
3. `이 값으로 갱신` (초록 버튼)

**가야 할 곳**은 "얼마 쓸지 정하기"인데, 히어로는 개수를, 두 번째로 눈에 띄는 초록 큰 숫자는 **내 값이 아닌 하한선**을 가리킨다. 경쟁 요소: 30px 숫자 1개 · 24px 초록 금액 1개 · 초록 버튼 2개 · 빨강 뱃지 1개 · 첫 화면 숫자 **15개 이상**.

## 4. 같은 것을 세 번 말한다 — 어지러움의 실체

첫 화면(800px) 안에서 **진례중학교 공고 하나**가 세 구역에 나온다:
1. 히어로 `오늘·내일 마감 1건 / 진행 중 1건 · 바구니 1건`
2. `투찰 바구니` — 진례중학교 + 값 입력칸 + 갱신/해제/✕
3. `진행 중 공고 1건` — 진례중학교 카드 (하한금액·최근낙찰·구간·참여수·버튼 3개)

블록이 셋이니 "할 일이 세 개"로 보이지만, 읽고 나면 **전부 같은 공고 하나**다. 공고가 1건일 때 이 중복이 가장 도드라진다.

## 5. 지역 다중 선택 UX — **불명확**

- 2개 설정 시 헤더가 `내 자격 지역 (2)`로 축약 → **어느 두 곳인지 화면 어디에도 없음** (1개일 때는 "· 김해시"로 보였다)
- 헤더 드롭다운은 **단일 선택**(내 자격 지역 / 개별 시군구)이라 "김해+창원 중 창원만 잠깐 빼기" 같은 조합이 불가
- 조합을 바꾸려면 `내 사업자` 화면까지 가야 함 — 구경용 조작인데 정체성 설정 화면을 열어야 하는 구조

## 6. 어지러움의 3대 원인 (결론)

**① 같은 것을 여러 번 말한다** — 오늘 화면의 공고 1건이 3블록에 반복. 정보량이 아니라 **중복**이 부피를 만든다.

**② 히어로가 할 일을 가리키지 않는다** — 가장 큰 글씨가 개수("1건"), 가장 눈에 띄는 색 숫자가 내 값이 아닌 하한선. 시선이 가는 곳과 결정해야 할 곳이 어긋난다.

**③ 상태 축이 흩어져 있고 요약되지 않는다** — 지역·품목·기간·정렬·하한·렌즈가 화면마다 다른 위치에 놓이고, "지금 이 조합으로 보는 중"을 한 줄로 말해 주는 곳이 없다. 분석판 56조합이 극단.

### 지역 UX 개선안
- 헤더 표시를 **이름 나열**로: `김해 + 창원 (내 지역)`
- 드롭다운에 **체크박스 다중 선택** 도입 — 내 자격 지역 안에서 개별 토글이 가능해야 "오늘은 김해만" 같은 조작이 설정 화면 왕복 없이 됨
- 타지역 구경 중일 때만 앰버 강조(현행 유지)
