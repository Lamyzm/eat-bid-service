# UX 검증 로그 — 상설 사용자 검증관(ux)

매 배포마다 같은 사람이 같은 일을 하러 온다는 가정으로 화면을 다시 본다.
전문가 눈이 아니라 **쓰는 사람 눈**으로만 판정한다. 코드는 건드리지 않는다.

---

## (a) 페르소나

**기본 페르소나 — "김해 축산 62세 사장"**

| 항목 | 내용 |
|---|---|
| 하는 일 | 김해에서 학교급식 축산 납품. 사업자 2개(신성유통·오뚜기축산) |
| 컴퓨터 | PC로만. 엑셀은 쓴다. 웹 서비스는 낯설다 |
| 모르는 말 | 중앙값·분포·표본·리허설·리플레이·앰버·동가 — 통계/영어 용어 전부 |
| 아는 말 | 투찰·개찰·기초가·하한율·밀림·낙찰·무효 (조달 실무 용어) |
| 급한 것 | **"얼마 쓰노"** 하나. 나머지는 다 곁가지 |
| 읽는 법 | 표를 먼저 본다. 그림은 참고. 긴 설명문은 안 읽는다 |
| 실수 반응 | 눌렀는데 결과가 다르면 다시 안 누른다. 물어보지도 않는다 — 그냥 안 쓴다 |

**보조 페르소나(필요 시)** — "서울 공산 45세 사장": 참여 80곳 판, 여러 학교 동시 투찰, 속도 우선.

## (b) 표준 과제 3개 (매 라운드 동일하게 재실행)

| # | 과제 | 성공 판정 |
|---|---|---|
| ① | 내일 마감 공고에 **얼마 쓸지 정하기** | 넣을 금액을 스스로 정하고 저장까지 끝냄 |
| ② | 지난달에 **왜 떨어졌는지** 알아보기 | 진 이유(밀림/무효)와 차이를 말로 설명할 수 있음 |
| ③ | **이번 달 납품** 확인 | 이번 달 납품 건수·금액을 찾아냄 |

각 과제마다 기록: 성공/부분/실패 · 클릭 수 · 스크롤 판수 · 중도 포기 여부 · 막힌 지점.

## (c) 라운드 0 — 기준선 (2026-08-28, 커밋 df247ed 기준)

### 과제 결과

| 과제 | 결과 | 클릭·스크롤 | 막힌 지점 |
|---|---|---|---|
| ① 얼마 쓸지 | **실패(치명)** | 2클릭 + 스크롤 3판 | 계산기가 화면 두 판 아래. 판단 근거를 못 읽음. 저장 버튼이 기록을 삭제 |
| ② 왜 떨어졌나 | **부분 성공** | 2클릭 + 스크롤 2판 | 3단 스택은 이해. 월 지정 불가, 같은 학교 두 줄의 정체 불명 |
| ③ 이번 달 납품 | **성공** | 1클릭, 3초 | 없음 |

### 결함 (치명 3 · 상 4 · 중 3)

| ID | 심각도 | 결함 | 사장의 말 |
|---|---|---|---|
| U1 | 치명 | 투찰함 버튼이 토글 — 저장하려고 누르면 기록이 삭제됨 | "저장할라꼬 눌렀디만 없어져뿟네? 내 아까 넣은 거 어데 갔노?" |
| U2 | 치명 | 같은 공고에 금액 3개(8,389,260 / 8,394,387 / 8,393,921)가 라벨 없이 병존 | "어느 돈을 넣으라는 소린지…" |
| U3 | 치명 | 분석판 기초금액이 그 공고 금액이 아님(9,321,400 vs 7,889,600) | (모르고 틀린 금액으로 계산할 위험) |
| U4 | 상 | "밀림5·낙찰5·무효8"을 해석 못 함 | "재생이 뭐꼬? 비디오도 아이고. 무효가 8이면 이 값 쓰면 안 된다는 소린가?" |
| U5 | 상 | 같은 학교 회차 수가 화면마다 다름(18회 vs 20건) | "어느 게 맞노" |
| U6 | 상 | 내 성적 첫 화면에 "무효(하한미달) 578회"가 빨간 큰 글씨, 설명은 맨 아래 각주 | "내가 578번을 헛짓했다고? 이거 맞나?" |
| U7 | 상 | 모르는 말 산재 — 리허설·리플레이·앰버·중앙값·동가·재생·분포·5%/95% | "이게 뭔 소린지…" |
| U8 | 중 | 계산기가 화면 두 판 아래 (읽을거리가 먼저, 할 일이 나중) | "돈 얼마 넣는지부터 보여주면 될 낀데" |
| U9 | 중 | 투찰 내역에 사업자 구분 없음 — 같은 날 같은 학교 두 줄 | "내가 두 번 넣었나? 어느 게 우리 회사꺼고?" |
| U10 | 중 | 첫 문장이 남의 동네("최다 전주시"), 지역 기본값 "전체 지역" | "내는 김해 사람인데 왜 맨 위에 전주 얘기가 뜨노" |

**기타(하)**: 납품 브레드크럼 영어("홈 / delivery") · 달력 전부 노란색이라 경고처럼 보임 · 분석판 저장 버튼 회색 이유 불명 · "1건/1건/1건" 세 곳 반복 · "추천가는 없습니다"가 "그라믄 내보고 우짜라고"로 읽힘.

### 딱 하나만 남긴다면
- **오늘**: 마감 임박 카드 1장(학교·마감·넣을 금액 한 줄)
- **공고 상세**: 투찰 계산기를 맨 위로 — 지금은 순서가 정확히 거꾸로
- **내 성적**: 3단 스택 표 (KPI "무효 578회"는 설명 없이는 공포)
- **납품**: 정산 표 — 손댈 것 없음

### 라운드 0 이후 조치 (리더 결재분)
- IA 3안 적용(커밋 60b3b1f): 분석판 공고 컨텍스트 주입 → U3 해소 예상, 몰림 중복 제거
- front 작업 중: U1(저장 토글) · U2(금액 라벨) · U4(리허설 문장화) · U8(계산기 최상단)

## (d) 라운드 기록 양식

```markdown
## 라운드 N — YYYY-MM-DD (커밋 XXXXXXX)

### 회귀 확인 (직전 라운드 결함)
| ID | 직전 상태 | 이번 상태 | 판정 |
|---|---|---|---|
| U1 | 치명 | ? | 해소 / 부분 / 미해소 / 악화 |

### 표준 과제
| 과제 | 결과 | 클릭·스크롤 | 직전 대비 | 막힌 지점 |
|---|---|---|---|---|
| ① 얼마 쓸지 | | | 개선/동일/회귀 | |
| ② 왜 떨어졌나 | | | | |
| ③ 이번 달 납품 | | | | |

### 새 결함
| ID | 심각도 | 결함 | 사장의 말 |
|---|---|---|---|

### 딱 하나만 남긴다면
(화면별 한 줄)

### 총평
(2~3줄. 쓰는 사람이 이 화면을 계속 열겠는가에 대한 답)
```

**기록 규칙**
- 결함 ID는 U 접두사 + 통산 일련번호(재사용 금지). 해소돼도 번호는 남긴다.
- 사장의 말은 지어내지 말고, 실제로 막힌 지점에서 나올 법한 한 마디만 짧게.
- "고쳤다"는 front의 보고가 아니라 **내가 그 화면에서 과제를 다시 해봐야** 확정한다.
- 회귀(전에 되던 게 안 됨)는 새 결함보다 항상 심각도 한 단계 위로 본다.
