# UX 검증 로그 — 상설 사용자 검증관(ux)

매 배포마다 같은 사람이 같은 일을 하러 온다는 가정으로 화면을 다시 본다.
전문가 눈이 아니라 **쓰는 사람 눈**으로만 판정한다. 코드는 건드리지 않는다.

**기본 페르소나 — "김해 축산 62세 사장"**

| 항목 | 내용 |
|---|---|
| 하는 일 | 김해에서 학교급식 축산 납품. 사업자 2개(신성유통·오뚜기축산) |
| 컴퓨터 | PC로만. 엑셀은 쓴다. 웹 서비스는 낯설다 |
| 모르는 말 | 중앙값·분포·표본·리허설·리플레이·앰버·동가 — 통계/영어 용어 전부 |
| 아는 말 | 투찰·개찰·기초가·하한율·밀림·낙찰·무효 (조달 실무 용어) |
| 급한 것 | **"얼마 쓰노"** 하나. 나머지는 다 곁가지 |

| 실수 반응 | 눌렀는데 결과가 다르면 다시 안 누른다. 물어보지도 않는다 — 그냥 안 쓴다 |

## (b-2) 검증 방식 규약 (2026-08-28 강화)

**손으로 만지는 검증만 인정한다.** 아래는 매 라운드 의무.

| # | 규약 | 이유 |
|---|---|---|
| 1 | `take_snapshot`으로 접근성 트리를 먼저 잡고, **uid 기반 `click`/`fill`/`hover`로 실조작**. `evaluate_script`로 상태를 직접 건드리는 우회 금지 | 실사용자와 다른 경로를 타면 검증이 무의미. 버튼이 실제로 눌리는지까지가 검증 |
| 2 | 과제 시작 `performance_start_trace` → 종료 `performance_stop_trace`. **LCP·인터랙션 지연 기록** | "느려서 못 쓰겠다"도 UX 결함이다 |
| 3 | `list_console_messages` + `list_network_requests` — 실패 요청·**1초 이상 느린 API**를 잡아 사장 체감과 연결 | 화면이 멈춘 것처럼 보이는 이유는 대개 뒤에 있다 |
| 4 | 화면마다 `take_screenshot(fullPage)` 증거 보존 + **"몇 판을 스크롤해야 하는지" 수치 기록** | 길다는 인상을 숫자로 |
| 5 | `emulate`로 **1920 / 1280 두 폭 비교** (PC 우선이되 노트북 1280에서 잘리는 것 확인) | 사장 책상은 1920, 아들 노트북은 1280 |

`evaluate_script`는 **읽기 전용 계측**(스크롤 판수 계산, DOM 존재 확인)에만 쓴다. 조작은 언제나 uid로.

**측정값 기록 형식**: 과제표에 `LCP 1.8s · 최장 인터랙션 320ms · 느린 API 1건(rounds 1.4s)`처럼 병기.

## 2. "지금 무엇을 보고 있나"가 한 문장으로 읽히는가 — **안 읽힌다**

오늘 화면 맨 위 세 줄이 **서로 다른 맥락**을 말한다:
- 헤더: `내 자격 지역 (2)` — 어느 두 곳인지 안 보임
- 제목: `오늘`
- 부제: `어제 전국 289건 개찰 · 최다 전주시(57건)` — 내 지역(김해·창원)과 **무관한 전국 이야기**

분석판은 더 심하다. "지금 보는 것"을 알려면 **4곳을 따로 봐야 한다**: 하한 탭(90/88) + 기간 탭(전체) + 렌즈 탭(흐름) + 공고 컨텍스트 배너. 한 문장으로 요약해 주는 곳이 없다.

## 3. 첫 3초의 눈 vs 가야 할 곳

오늘 화면에서 **눈이 실제로 가는 순서**(크기·색 기준):
1. `1건` (30px, 최대) — 개수일 뿐 **할 일을 가리키지 않음**
2. `8,389,260 원` (24px, 초록) — 시선을 가장 강하게 끄는데 이건 **하한 금액**(내가 넣을 금액이 아님)
3. `이 값으로 갱신` (초록 버튼)

**가야 할 곳**은 "얼마 쓸지 정하기"인데, 히어로는 개수를, 두 번째로 눈에 띄는 초록 큰 숫자는 **내 값이 아닌 하한선**을 가리킨다. 경쟁 요소: 30px 숫자 1개 · 24px 초록 금액 1개 · 초록 버튼 2개 · 빨강 뱃지 1개 · 첫 화면 숫자 **15개 이상**.

## 4. 같은 것을 세 번 말한다 — 어지러움의 실체

첫 화면(800px) 안에서 **진례중학교 공고 하나**가 세 구역에 나온다:
1. 히어로 `오늘·내일 마감 1건 / 진행 중 1건 · 바구니 1건`
2. `투찰 바구니` — 진례중학교 + 값 입력칸 + 갱신/해제/✕
3. `진행 중 공고 1건` — 진례중학교 카드 (하한금액·최근낙찰·구간·참여수·버튼 3개)

블록이 셋이니 "할 일이 세 개"로 보이지만, 읽고 나면 **전부 같은 공고 하나**다. 공고가 1건일 때 이 중복이 가장 도드라진다.

## 5. 지역 다중 선택 UX — **불명확**

- 2개 설정 시 헤더가 `내 자격 지역 (2)`로 축약 → **어느 두 곳인지 화면 어디에도 없음** (1개일 때는 "· 김해시"로 보였다)
- 헤더 드롭다운은 **단일 선택**(내 자격 지역 / 개별 시군구)이라 "김해+창원 중 창원만 잠깐 빼기" 같은 조합이 불가
- 조합을 바꾸려면 `내 사업자` 화면까지 가야 함 — 구경용 조작인데 정체성 설정 화면을 열어야 하는 구조

## 6. 어지러움의 3대 원인 (결론)

**① 같은 것을 여러 번 말한다** — 오늘 화면의 공고 1건이 3블록에 반복. 정보량이 아니라 **중복**이 부피를 만든다.

**② 히어로가 할 일을 가리키지 않는다** — 가장 큰 글씨가 개수("1건"), 가장 눈에 띄는 색 숫자가 내 값이 아닌 하한선. 시선이 가는 곳과 결정해야 할 곳이 어긋난다.

**③ 상태 축이 흩어져 있고 요약되지 않는다** — 지역·품목·기간·정렬·하한·렌즈가 화면마다 다른 위치에 놓이고, "지금 이 조합으로 보는 중"을 한 줄로 말해 주는 곳이 없다. 분석판 56조합이 극단.

### 남은 인지부하 상위 3건 + 처방

**1위 — CLS 0.50 (화면이 뜨면서 글자가 밀린다)**
R3의 0.71보다 낫지만 R2의 0.19보다 훨씬 나쁘다. 사장이 누르려는 순간 버튼이 움직이는 크기다.
→ **처방**: 카드 높이를 **고정 스켈레톤**으로 예약(마감 임박 8장은 개수가 정해져 있으니 자리를 미리 잡을 수 있다). 히어로 배너와 상태 한 줄도 로딩 전 높이를 확보할 것.

**2위 — 칩 배지의 기준이 서로 다르다 (U36)**
`내 지역 전체144` 옆에 `정읍시10` `전주시8`이 나란히 있으면, 같은 줄의 숫자가 각각 전국·지역을 가리키게 된다. R4에서 다른 숫자는 전부 맞춘 만큼 이 하나가 더 도드라진다.
→ **처방**: 배지를 **내 지역 합(18)**으로. 전국 수는 아래 "전국 128건 더 보기"가 이미 말하고 있으니 칩에서 뺄 것.

**3위 — 값을 넣어도 그 값이 맞는지 카드가 말해주지 않는다 (U37 + U34)**
카드에서 완결시키는 구조로 바꾼 대가로, 판단 근거(리허설 문장·하한 경고)는 공고 상세에만 남았다. 89.5를 넣어도 무효 경고가 없고, 90.099를 넣으려 하면 조용히 잘린다.
→ **처방**: 카드 입력칸 아래 **한 줄**만 추가 — 하한 미만이면 `하한 90 아래라 무효` (빨강), 정상이면 `이 값이면 과거 N회 중 M회 먹었을 값`. 소수점은 3자리까지 허용하고, 절삭할 때는 조용히 자르지 말고 입력 자체를 막을 것.

### 딱 하나만 남긴다면
- **오늘**: 마감 임박 8장 카드 — 이번 라운드에 제자리를 찾았다
- **공고 상세**: 계산기 + 3탭 (계산기 입력칸 복원만 고치면 완성)
- **내 성적**: KPI 2칸 + 접힘 (숫자까지 참값이 됐다)
- **납품**: 정산 표 (5라운드째 무결점)

### 총평
**통과다.** 라운드 3에서 잡은 5건이 스텁 없는 실환경에서 전부 재현 확인됐고, 특히 소수점 왕복(타이핑→저장→새로고침→뱃지)과 지역 2곳 동시 표시는 사장이 실제로 하는 순서 그대로 눌러서 확인했다. 숫자 정합성은 이번 라운드에서 처음으로 **화면 전체가 한 소스로 말한다**(18 = 8 + 10, 146 = 18 + 128).
남은 것은 성격이 다르다. U34(3자리 절삭)와 U37(하한 경고 없음)은 **고치다가 생긴 새 구멍**이고, U35는 이전에 통과했던 항목이 다시 열린 것이다. 셋 다 카드·계산기 한 줄 수준의 작업이라 다음 라운드에서 정리 가능하다.
어지러움에 대한 답: **오늘 화면은 이제 안 어지럽다.** 남은 흔들림은 시각(CLS)과 숫자 기준 하나(칩 배지)다.

## 3. 차트 품질 총평 — "평면적"의 정체

사용자 말이 정확하다. 원인은 셋이다.

1. **세로가 없다** — 분석판 차트가 622×159. 높이 159px에 12단계 값을 담으니 막대 차이가 뭉갠다.
2. **축이 없다** — y축·그리드가 없어 "13과 8이 얼마나 다른가"를 눈으로 못 읽는다. 막대 위 숫자를 읽어야만 안다 = 차트가 아니라 **숫자 나열에 색칠한 것**.
3. **색이 하나다** — 모든 막대가 같은 세이지 그린. 크기·구간·내 위치에 따른 위계가 없다. DESIGN이 정한 4색 판정(낙찰=primary/밀림=앰버/무효=destructive/내 값=코발트)이 이 차트엔 **적용되지 않았다**.

여기에 **화면마다 문법이 다르다**: 공고 상세는 strip-chart(하한선·구간 음영·직접 라벨), 분석판은 히스토그램(축 없음), 시장 지도는 지도 버블(하드코딩 hex). 세 화면이 서로 다른 시각 언어를 쓴다.

## 4. 지금 가장 싸구려로 보이는 화면 3개

### 1위 — **웰컴 / 로그인**
돈을 낼지 정하는 **첫 화면**인데, 1280×900에서 콘텐츠가 세로 400px 안에만 있고 나머지는 검정 공백이다. 제품이 무엇을 보여주는지 증거가 하나도 없다(차트·표·숫자 스크린샷 0개). 게다가 **로그인 버튼조차 없다**. 카피는 좋은데 카피만 있다.
→ 실제 strip-chart 미리보기 1개 + "오늘 마감 N건" 실시간 숫자 + Google 로그인 버튼.

### 2위 — **분석판**
이 제품이 파는 것이 판단 재료인데, 그 재료를 보여주는 화면의 차트가 **y축 없는 159px 납작 막대**다. 색은 단색, 두 차트의 문법이 다르고, 파란 선 색은 하드코딩이며 다크에서 검정 채움이 안 보인다. 참여 업체 표는 헤더만 남아 있다. h1은 다른 화면보다 4px 작다.
→ 차트 높이 240px+, y축·그리드, chart-colors 통일, 표 Empty, h1 2xl.

### 3위 — **학교 찾기**
0개 학교인데 표 헤더와 범례만 덩그러니 남아 화면의 60%가 빈 검정이다. 여기에 브레드크럼이 세로로 깨져 좌상단에 글자가 쌓인다. "만들다 만 화면"으로 읽힌다.
→ Empty 컴포넌트, 브레드크럼 G1 수정, 히어로 승급.

**다음 작업 순서는 이 셋 → 전역 G1(브레드크럼) → G4(히어로) 순을 권한다.** G1은 4개 화면에 동시에 걸려 있어 단가 대비 효과가 가장 크다.
