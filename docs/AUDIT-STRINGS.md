## 1. 신규 라이브 결함 3건 (실측)

### 🔴 S-1. `market_regions` PK가 시도를 뺐다 — 시장 지도가 도시를 뒤섞는다

`load_postgres.py:398` `on conflict (sigungu,category) do update set …`
집계 키는 `(sido, sgg, cat)`(`:349`)이고 `sido`를 insert도 한다(`:400`). **그런데 충돌 대상에서 뺐다.**

라이브 실측 — `select sido, sigungu, category, per_year from market_regions where sigungu='남구'`:
```
대구광역시 | 남구 | 공산 | 17
부산광역시 | 남구 | 기타 | 25
대구광역시 | 남구 | 김치 | 78
인천광역시 | 남구 | 농산 | 17
인천광역시 | 남구 | 수산 | 17
울산광역시 | 남구 | 축산 | 34
```
**6행이고 각각 다른 도시다.** 4개 시도 × 품목이면 최대 24행이어야 하는데 품목당 1행만 남았고, **어느 도시가 살아남는지는 insert 순서가 정한다.**

사장이 "남구"를 열면 **공산은 대구, 축산은 울산, 농산은 인천인 프랑켄슈타인**을 본다. 나머지 도시의 시장 데이터는 조용히 파괴됐다.

**규모: 여러 시도에 걸친 시군구명 51개**(`동구`·`중구` 각 6개 시도, `남구` 5, `강서구`·`서구` 4…). `market_regions` 568행.
**성격: 정체성 칸에 표시명을 넣었다.** A-8과 같은 죄이고 **규모가 더 크다.**
**대응 코드: `SIDO_CD`(레이크에 `sido_code`, 100%) + `SIGUNGU_CD`(레이크에 없음 → 재파싱).**

## 4. 문자열이 **맞는** 자리 — 바꾸지 마라

가르는 게 이 조사의 본체다. 아래는 정체성이 아니라 **화면 상태·구조**이고 문자열이 옳다.

| 자리 | 이유 |
|---|---|
| `eatbid.lens`·`auctionTab`·`kpiOpen`·`scopeOpen` (localStorage) | 화면 상태. 사용자당·브라우저당 |
| `LENSES`·`PERIODS`·`TABS`·`STATUS` 상수 | 화면 구조. 설계 §3-1이 "웹에 남긴다"로 이미 판정 |
| `lake.py` `year=`/`month=` 파티션 · `part-{ns}` 파일명 | 저장 레이아웃. **20자리 제로패딩이 정렬=쓰기순서를 만든다** — 의도된 설계 |

## 8. 정정 — `bids.rank`는 가격 순위가 아니다 (audit-pipeline 지적 · 독립 검증함)

§5-A에서 나는 `bids.rank`(100% 채움)를 **"동가·순위"** 배선 후보로 올렸다. **틀렸다. 배선하면 안 된다.**

`audit-pipeline`이 원시 400회차 표본으로 `RNK=1`의 최저가 일치율 26%를 냈고, **레이크 전량으로 독립 검증했다:**

```
rank=1 행 185,371 중 그 회차 최저가인 것   52,209 (28.2%)
won  행 185,175 중 그 회차 유효최저가인 것 183,002 (98.8%)   ← 대조군

won & rank<>1      14,702   (낙찰인데 1등이 아님)
rank=1 & not won   14,898   (1등인데 낙찰 아님)
```

**`won`은 최저가와 98.8% 일치하고 `rank=1`은 28.2%다.** RNK는 가격 순위가 아니다(자격심사·추첨 순위로 보이나 **데이터만으로는 확정 못 한다**).

**처방:** 서버가 지금 쓰는 `min(bid_rate) filter(win_rate is not null and bid_rate > win_rate)` 2등 복원이 **맞다.** `RNK2`·`RNK3`·`TOTAL_NUM`을 재파싱으로 더 얻어도 **의미가 확정되지 않는다** — 원본 제공자에게 묻거나 쓰지 않는다. **5-B 우선순위에서 `RNK2/RNK3/TOTAL_NUM`을 뺀다.**

**⚠ 덤으로 적었던 가설은 틀렸다 — §9에서 정정.** 남는 1.2%를 적격심사로 추정했는데 **실측하니 100% 동가였다.**

### 이건 내가 내 규칙에 걸린 것이다

`RNK`는 **이름이 순위고, 100% 채워져 있고, 정수다.** `.claude/rules/reading-the-source.md` **R3("이 필드는 무엇에 대한 값인가")**가 정확히 이걸 막으려고 쓴 규칙인데, **나는 그 규칙을 쓴 문서 바로 다음 문서에서 묻지 않고 배선 후보에 올렸다.**

지역 넷(`PDLC_NM` 2회·`_SGG_CANON`·`SIGUNGU_CD`)과 `MLFD_CLASS_CD`·`RBID_YN`에 이은 **여섯 번째**이고, **처음으로 규칙이 있는 상태에서 났다.**

→ `.claude/rules/README.md`의 *"못 막는다 ③ — 규칙을 만든 그 회차에 같은 실수를 한다"*에 **세 번째 실증**으로 넣는다. 그리고 R3에 한 줄 더 붙일 값어치가 있다: **"`_CD`·`_NO`·`RNK`처럼 이름이 스스로 정체를 주장하는 필드가 가장 위험하다 — 이름이 검사를 대신해준다고 느끼게 만든다."**

## 9. 잔차 1.2%의 정체 — 내 가설 정정 · 신규 A-16 (금액)

`audit-pipeline` 지적을 받아 재측정했다. **내 적격심사 가설은 틀렸다.**

### 9-1. 잔차는 **100% 동가**다 — "최저가 낙찰"은 예외 없이 성립한다

```
낙찰행 186,575 · 유효최저와 불일치 2,173
  그중 유효최저에 동가가 서 있는 것  2,173 (100.0%)
  그중 적격심사                        172 (  7.9%)   ← 동가의 부분집합
동가를 일치로 세면 최저가 모델 성립률   100.00%
```

`audit-pipeline`은 비-적격심사 2,001건에서 동가 100%를 봤고, **적격심사 172건까지 포함해도 100%다.** 즉 **적격심사가 원인이 아니라는 게 더 확실해진다.**

**정정: §8의 *"남는 1.2%가 A8일 가능성이 높다"*를 철회한다.** 농축비 7.4배(7.9% vs 1.06%)는 실재하지만 **"적격심사라서 낙찰자가 달라진다"는 성립하지 않는다.** A8은 다른 근거로 세워야 한다.

**대신 더 나은 사실이 남는다: 불일치가 아니라 동가다.** 최저가 모델은 예외 없이 맞고, 갈리는 건 **동가에서 누가 이기느냐**뿐이다.

### 9-2. `bid_at`도 배선 후보에서 뺀다 (audit-pipeline 자진 철회 · 동의)

`normalize.py:257` 주석이 *"D6: 동률 낙찰 판정에서 제출시각이 필요하다"*고 선언하는데:
```
동가로 갈린 회차 3,726 · bid_at 채움 100% · 낙찰자가 최빠른 곳 1,853/3,721 = 49.8%
```
**동전 던지기다. 선착순이 아니다.** `bid_at`을 배선하면 **설명력 없는 값을 순서처럼 보여주게 된다.** §5-A에서 뺀다.

> 이건 헌법과 오히려 맞는 결론이다 — **동가 승자 결정 규칙을 우리는 모른다.** SIM이 이미 "동가 위험은 사실로 말한다"로 잡아뒀고, **모르는 걸 순서로 위장하지 않는 게 맞다.**

### 9-3. 🔴 A-16 — **낙찰 금액이 원본보다 1.77% 높다. 전 행이 어긋난다**

`bids.bid_amount`(원본 `BID_CALC_AMT`)가 미적재라 서버가 `base_price * bid_rate / 100`으로 금액을 만든다. **낙찰 행만 측정:**

```
낙찰행 186,955 · bid_amount 있음 186,954 (100.0%)
1원 초과 어긋남 186,870 / 186,954 (100.0%)   ← 예외가 없다

원본 합계  3,629,850,507,537
계산 합계  3,694,091,996,693
차이          64,241,489,156  (+1.770%)
```

**일방향으로 1.77% 높다. 반올림 오차가 아니라 체계적이다**(원인은 data 좌석 몫 — 단가×수량 반올림인지, 부가세 처리인지).

**걸리는 곳:**
- `app.module.ts:495` — `/api/firms/bids?summary=1` → `winSum` → **`record/page.tsx` 낙찰 금액 KPI**
- `app.module.ts:661` — `/api/firms/top` → `winSum` → **`firms/page.tsx` TOP 업체 낙찰액**
- 웹 손계산 지점들(`DEBT.md` §2 2.1) — `record/page.tsx:75` 등

**SIM-USERFLOW의 "최근 12개월 계약 2.96억"이 이 경로에서 나온다.** 1.77%면 약 **524만원**이 실제보다 높게 표시된다.

**성격: 금액을 사실로 표시하는데 원본과 다르다.** 헌법("사실을 말한다")에 걸리고, **대응 컬럼이 원본에 100% 있는데 안 실었다.** `bids.valid`와 같은 모양이다.

→ **X33: `firm_bids.bid_amount` 적재 + `winSum`을 `sum(bid_amount)`로.** 재파싱 불필요(레이크에 있다). **5-A 배선 목록에 추가한다.**

### 9-4. `floor_rate_from_text` — audit-pipeline 지적 수용

*"의도한 방어가 통과했다는 사실이 어디에도 안 남는다"*가 맞다. 매 적재마다 재계산하고 아무도 안 읽으니 **언젠가 어긋나기 시작해도 알 방법이 없다.**
→ **R21 적재 요약에 `floor_rate_from_text 불일치 N건` 한 줄.** 지금 0건인 것이 기록으로 남아야 나중에 1건이 의미를 갖는다.

### 9-5. 규칙 반영 — R3에 두 줄

`RNK`(이름이 순위)·`BID_DT`(주석이 용도를 선언) 둘 다 **이름·주석이 검사를 대신해준다고 느끼게 만든 자리**다. `audit-pipeline` 제안을 받아 `.claude/rules/reading-the-source.md` R3에 붙인다:

> - **우리가 단 주석도 주장이다.** `normalize.py`의 D1~D8은 **검증된 사실과 추정이 같은 서식으로 섞여 있다.** `bid_at`의 D6이 그 예이고, D3(`valid` 무효 = 1e13 sentinel)도 실측하면 무효의 99.4%가 하한미달이고 sentinel은 0.6%다

## 10. D1~D8 판정 반영 · 신규 A-17 (범위 방어) — audit-pipeline 2차

### 10-1. 동가 승자는 **레이크 어떤 컬럼으로도 설명되지 않는다** — 이제 측정으로 뒷받침된다

```
동가 회차 3,726
  낙찰자가 bid_at 최빠른 곳         1,853 / 3,721 = 49.80%
  낙찰자가 draw_numbers 최소 보유   1,867 / 3,656 = 51.07%
```
**둘 다 동전 던지기다.** `bid_at`·`draw_numbers` 모두 배선 후보에서 뺀다(§5-A 갱신).

**이건 축소가 아니라 소득이다.** 헌법이 *"예측하지 않는다"*이고 SIM이 *"동가 위험은 사실로 말한다"*로 잡아뒀는데, **지금까지 그 "모른다"가 근거 없는 겸손이었다. 이제 측정된 사실이다.** 화면이 "동가는 무엇이 가르는지 우리가 모른다"고 말할 수 있게 됐다.

### 10-2. 🔴 D5 반증이 내 S-3 측정의 빈칸을 드러낸다

`normalize.py` D5 주석: *"99.9%가 지역 제한 있음"* → **실측 97.46%. 제한 없는 공고 4,770건(2.54%) — 25배다.**

**내 S-3 측정에 빈칸이 있다.** 나는 라이브 121건을 `무제한 통과 65 / 완전일치 0 / 접두일치 20`으로 갈랐는데, **그 65건은 `UNRESTRICTED_TOKENS`(`"전체"` 문자열) 경로다.** `isUnrestricted`에는 경로가 **둘**이다:
```ts
if (list.length === 0) return true;                 // ① 빈 목록 = 무제한
return list.some(a => UNRESTRICTED_TOKENS.some(...)) // ② 토큰 매치
```
**나는 ②만 셌고 ①을 안 갈랐다.** D5가 말하는 4,770건이 ① 경로의 크기이고, **"제한 정보가 없다"를 "제한이 없다"로 읽는 자리**다. 두 해석은 다르다 — 수집 실패로 `areas`가 비었을 때도 ①이 무제한으로 통과시킨다.

→ **S-3 처방(코드 대조)에 ①의 처리도 함께 정해야 한다.** `areas`가 비어 있으면 **무제한이 아니라 "자격 미상"**일 수 있다. `areas` 채움률이 97.8%이므로 **빈 2.2%가 진짜 무제한인지 수집 결측인지 갈라야 한다.** X28에 붙인다.

### 10-3. 🔴 A-17 — `_num`에 범위 방어가 없어 라이브 값이 무의미한 학교가 있다

```python
# normalize.py:88-94   _num  — 범위 검사 없음
# normalize.py:98-102  _price — MIN_PRICE < v < MAX_PRICE 있음
```
**같은 파일 안에서 방어가 비대칭이다.** 결과로 `floor_rate = 0.001` 회차 **5건**이 그대로 적재됐다(라이브 `school_auctions` 확인 — **비정상 하한율은 이 값이 유일**).

`audit-pipeline` 실측: `상주시|상주공업고등학교`(n_auctions 5 — **문턱 5회를 정확히 통과**)의 `by_floor` 키가 `"0.001"` 하나이고
```
{"n":5,"mean":79.29,"p":[55.78,57.5,93.86,94.44,94.87],"dense":{"lo":55.78,"hi":55.88,"pct":20}}
```
**화면에 나가는 값이 통째로 무의미하다.** `mean 79.29`는 55.78~94.87 흩어진 값의 평균이고 `dense`의 20%는 **n=1**이다.

**그리고 오염이 번진다:** `valid = floor_rate <= rate <= 100`(`normalize.py:243`)이므로 **하한율이 0.001이면 그 회차 전 투찰이 유효가 되어 `n_valid`도 오염된다.**

→ **X34: `floor_rate`에 범위 방어 한 줄.** 규모는 1학교·5회차로 작지만 **성격이 F2(문턱)의 반대다** — 문턱은 정상 데이터를 버렸고, 이건 비정상 데이터를 통과시켰다. **`_price`에 있는 방어가 `_num`에 없는 게 원인이고, 판정의 기준값(`floor_rate`)이 무방비다.**

### 10-4. 적격심사 오염 방향 정정 (audit-pipeline 발견 수용)

내가 §9-1에서 A8을 "다른 근거로 세워야 한다"고만 적었는데, **그쪽이 실제 오염 지점을 찾았다.**

하한율이 갈린다 — 적격심사는 `84.245·82.995·80.495·86.245·87.995`, 일반은 `90·88`. **겹치는 건 `84.245` 하나(적격심사 1,912 vs 일반 27)뿐이다.**
→ **`by_floor`는 하한율이 키라 이미 갈려 있다.** 내가 걱정한 "분포에 섞인다"는 대부분 성립 안 한다.
→ **실제 오염은 두 곳뿐이다:** ① `84.245` 버킷의 일반 27회차 ② **하한율을 넘어 합산하는 값** — `med_field`·`market_regions`·`cat_counts`·`n_auctions`.

**A8의 근거가 이걸로 좁고 정확해졌다.**

### 10-5. 주석 규약 — audit-pipeline 안 채택 (내 안보다 낫다)

내가 `⚠ 미측정` 표시를 제안했는데 **그쪽 안이 더 낫다:**

> **"측정: 2026-08-28 · 전량"** 을 붙인다. `⚠ 미측정`은 **붙이는 걸 잊으면 조용히 사실처럼 보이지만**, 측정 표시는 **없으면 없는 게 보인다.**

**이게 이 리포 전체의 논리와 같다** — 조용한 실패보다 시끄러운 실패, 빈칸을 보이는 게 규칙으로 메우는 것보다 낫다(F1·F2). **부재가 눈에 띄는 쪽을 고른다.**

**그리고 D8이 그 규약의 첫 사례다** — 확증 4개 중 **유일하게 스스로 근거를 밝힌 항목**이고("라이브 실측으로 확인"), **반증된 셋은 전부 근거 없이 단정한 자리**다. 표기 유무가 신뢰도와 실제로 상관했다.

→ `.claude/rules/reading-the-source.md` R4에 붙인다.
