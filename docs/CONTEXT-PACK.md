# 입찰 인텔리전스 — 컨텍스트 팩 (기획 토론용 총종합)

## 0. 제품 한 줄
학교급식 조달 공급업체를 위한 조달 인텔리전스 — **"판단은 당신이, 재료는 전부 우리가."** 매일 아침 투찰 결정을 한 화면에서 끝내게 한다.

### 스탠스 (제품 헌법)
사람들이 원하는 건 그 안에서의 '자기 추측'이다. 우리는 예측값을 출력하지 않지만, **사용자가 스스로 추측·판단할 수 있게 재료를 최대로 제공한다** — 아버지가 학교 차트를 응시해 자기 최적 위치를 스스로 찾았듯, 사용자도 이 화면을 보고 스스로 감을 잡는다.
- 판단 재료 맥시멀리즘: 자주 걸린 값·몰린 구간·흐름·단골 업체·하한 범위를 패턴이 읽히게 밀도 있게.
- 면책 문구는 구석 한 줄로 최소화. 방어적 톤 금지.
- 금지는 단 하나: 우리가 특정 금액을 **추천·예측으로 출력**하는 것 (근거: 아래 §2 — 그건 수학적으로 거짓이 되므로).

## 1. 사용자
- 1차: 아버지(50~60대 축산 납품업자, 김해, 사업자 2개 운영). 매일 아침 공고 확인→학교 차트 열람→금액 결정→투찰. 기존에 자기만의 차트 툴을 씀. 노안 — 작은 글씨 못 읽음.
- 2차(유료화): 전국 급식 납품업체 (부분 크롤에서만 2,969곳 확인, 전국 5천~1만 추정). 시장엔 가짜 "낙찰 예측" 툴 판매자들이 있음.

## 2. 불변 원칙 (검증된 사실 — 어기면 안 됨)
- **낙찰가 예측 불가**: 예정가 = 기초가 × R, R은 순수 난수(평균0.999, sd0.0076). 22개 방법+5폴드 OOS로 증명. → 우리가 "추천가/예측값"을 출력하는 것만 금지. 사용자의 자기 판단을 돕는 재료 제공은 오히려 최대화.
- **용어 규칙**: 은어 금지. 얇은판→업체 10곳 이하 / 뜯김→밀림 / 밴드→잘 나온 구간 / R→예정가 추첨 / gap→차이 / 재현값→자주 걸린 값(아버지 표현). **모든 문장은 사전지식 없이 혼자 서야 함** ("전화로 들었을 때 되묻지 않는가" 테스트).
- 숫자 우선: 표·차트 위에 값이 직접 보여야 함. 60대 가독성(본문 16px+, 라벨 13px+).

## 3. 검증된 사실 = 화면에 쓸 재료
- **잘 나온 구간**: 승자의 57~83%가 하한율 바로 위 0.10폭에 착지 (하한별로 분리해야 함: 90/88/84.245).
- **자주 걸린 값**: 0.01 단위 반복 낙찰률 (예: 장유고 90.03×6). 2회 이상만 의미.
- **발주 주기**: 학교 77%가 25~35일 월간주기, 개찰일 21~25일 몰림 67% → "다음 발주 예보" 가능 (행정 일정 = 진짜 예측 가능한 유일한 것).
- **자격 레이더**: 공고의 허용지역 목록 기준. 김해 밖(창원 진해용원고 등)에서 연 20건+ 자격 공고 존재 — 소재지 필터만 쓰면 놓침.
- **판 두께**: 업체 승률차의 97%는 어느 두께의 판에 있냐(지속성 0.97). 시장지도의 근거. 단 같은 학교도 회차별 두께는 불안정(CV 0.85).
- **인컴번시 없음**: 직전 낙찰자 반복 2.9% < 무작위 7.3%. "이 학교 강자" 프레임 금지. **단, '단골 참여 업체'(누가 자주 오는가) 로스터는 별개** — 낙찰 예측이 아니라 경쟁 상황 인식으로는 정직함.
- **밀림/미달 분해**: 진 이유 = 투찰률<하한(무효) vs 그 외(더 낮은 업체에 밀림). 커트라인=하한율 상수 (예정가 기준 정규화).
- **내 투찰 버릇**: "N번 중 M번 밀림 → 대체로 높게 씀" — 유일한 행동 교정 가치. 아버지가 3초 만에 납득한 카피.
- **가구 합산**: 사업자 2개 합치면 승률 1.9배 (3,925투찰/75낙찰). 계정=사업자 N개 묶음이 기본 구조.
- **시장 지도**: 통영 5곳/35.3건·창원 34.9·김해 21.6(기준선). 기대낙찰=연공고÷업체수, 김해 실측과 일치 검증.

## 4. 가용 데이터/API (현재 클러스터)
- GET /api/open (자격 레이더, anchorAmount·schoolId 포함) · /api/schools (+q,limit) · /api/schools/:id/auctions · /api/schools/:id/my-bids · /api/schools/forecast · /api/market · /api/firms/{record,timeline,lookup} · /api/results (투찰 표시분 결과)
- 원천: parquet 레이크 (전 공고·전 투찰·전 업체) — **로더 확장으로 추가 가능한 것**: 학교별 단골 참여업체 로스터, 공고별 참여업체 목록, 학교별 기초가 추이, 품목 분류.
- 제약: 열린 공고 스냅샷은 CronJob 갱신(현재 1일 1회). 개찰 결과는 익일 반영.

## 5. 현재 화면 (급조 상태 — 비판 대상)
- 오늘: 결과 알림 + 공고 카드(기준금액·관심/투찰 표시) + 발주 예보 리스트
- 학교 찾기: 검색 + 4열 표 / 학교 상세: 기준금액 입력 → 잘나온구간 카드 → 산점도(회차별) → 내 전적 표
- 내 성적표: KPI 5장 + 월별 ComposedChart + 최근 낙찰 표
- 시장 지도: 랭킹 표 + 지역 상세(승자 칩·연도추이·월별·학교 표)
- 문제 예시: 공고 카드→학교 이동이 약함(공고 자체 상세 화면 없음), 차트가 "일단 그림" 수준(무슨 질문에 답하는지 불명), 예보가 밋밋한 리스트.

## 6. 유료화 3단 (합의된 방향)
A. 코어 루프 완성(아침에 열면 결정까지) → B. 습관 고리(어제 결과 자동 반영·발주 예보) → C. 알림. 가격 스토리: 월 3~5만원, 낙찰 1건 마진의 1/20.

## 7. 명세 대상 화면 (7개 + 차트 공통 규격)
① 오늘(홈) ② **공고 상세(신설 — 클릭 시 진짜 이동: 기준금액+과거 하한범위+학교 기록 요약+단골 참여 업체+내 전적+투찰 표시)** ③ 학교 상세 ④ 학교 찾기 ⑤ 내 성적표 ⑥ 시장 지도 ⑦ 내 사업자(온보딩). 차트마다: "이 차트가 답하는 질문 한 줄"이 없으면 탈락.
