## #1 (2026-08-27) ⑥ 시장 지도 + ⑦ 온보딩 화면 명세

### ⑥ 시장 지도 (낙찰 구역) — "어느 동네 판이 비어 있나"
비드큐에 없는 화면 = 우리 차별화. 원본 시장지도.html의 검증된 서사 이식.
- 라이브러리: react-leaflet + OpenStreetMap 타일. 시군구 중심좌표 번들(정적 JSON) v1, 학교 지오코딩 v2
- 메인: 전국 지도 + 시군구 버블 (크기 = 연간 공고 수, 색 = 기대낙찰(공고/업체))
  + ★ 내 본거지 표시(자격 지역), 열린 공고 핀
- 클릭 → 지역 상세 패널: 공고량·업체 수(판 두께)·연도별 흐름 막대·월별 물량·단골 로스터
- 카피(원본 이식): "낙찰을 예측하지 않습니다. 공고량·업체 수·계약 규모를 정리한 판입니다.
  참가 자격은 사무소 소재지 기준이라, 다른 지역은 사무소를 내야 들어갑니다."
- 데이터: market_regions 테이블 보유(시군구×품목 n·기대낙찰). 좌표만 추가하면 됨
- 가치: 확장 검토(2호 사무소) 의사결정 재료 = 상위 요금제 후보

### ⑦ 온보딩 — "사업자번호 하나로 6년이 뜬다"
비드큐 가입 페이지 문법(사회적 증거→무료가입) + 우리 온보딩 폭탄.
1. 랜딩 /: 스케일 숫자(9.6만 공고·630만 투찰) + 입력창 하나 "사업자번호 10자리"
2. 입력 → /api/firms/lookup: "OOO님, 기록이 이미 있습니다 — 참여 N회 · 낙찰 M회"
   + 진단 한 줄("최근 12개월 2등 9번, 차이 0.047") + 미니 도트(내 vs 승자)
3. "사업자 하나 더?" — 세대주 합산 제안: "두 개면 시야가 1.9배"
4. 관심 지역·품목 선택 → 오늘 화면으로. 알림 채널(카톡) 자리 예약
- 구현: /dashboard/my 확장이 아니라 별도 /welcome 플로우. 기존 lookup·record API 재사용
