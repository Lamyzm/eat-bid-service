# 수집 모드별 날짜 창 (2026-09-03 실측)

## 1. 결론

세 모드는 같은 WorkflowTemplate에서 `--start-date`와 `--end-date`만 달리해 실행한다. 창 의미가
입찰기간 겹침이므로 창을 오늘 하루로 두면 지금 열려 있는 공고가 정확히 나온다.

| 모드 | 창 | 근거 |
|---|---|---|
| `poll-open` | `[오늘, 오늘]` | 겹침 필터이므로 오늘 입찰기간이 열려 있는 공고 전부 |
| `daily-reconcile` | `[오늘-6, 오늘]` | 마감 뒤 변경이 +5일에서 멎는다 |
| `backfill` | 사람이 지정한 구간 | 재현 가능한 과거 수집 |

## 2. daily-reconcile 창을 7일로 정한 근거

창 `20260820..20260826`에서 1,000행을 받아 `LAST_CHG_DT`와 `BID_END_DT`의 날짜 차를 셌다.
상태 분포는 낙찰 783, 유찰 144, 공고취소 64, 진행중 8, 저장중 1이다.

| 마감 대비 | 건수 | 누적 |
|---|---|---|
| 마감 이전 | 64 | 6.4% |
| 당일 | 879 | 94.3% |
| +1일 | 44 | 98.7% |
| +2일 | 1 | 98.8% |
| +3일 | 8 | 99.6% |
| +4일 | 1 | 99.7% |
| +5일 | 3 | 100.0% |

변경은 +5일에서 완전히 멎는다. 7일 창은 관측된 최대치에 이틀의 여유를 둔다. 1일 창이면 98.7%를
잡지만 나머지 1.3%의 낙찰 결과를 영영 놓친다.

이 표본은 8월 하순 한 주다. 학기 주기의 다른 구간에서 꼬리가 길어지는지는 확인하지 않았다.

## 3. 창별 규모

`TOT_CNT` 기준이다. 2026-09-03은 학기 주기의 저점이고 8월 하순이 피크다.

| 창 | `TOT_CNT` |
|---|---|
| `20260903..20260903` (오늘 하루) | 85 |
| `20260902..20260903` (2일) | 93 |
| `20260828..20260903` (7일) | 648 |
| `20260820..20260826` (피크 주) | 14,000 |
| `20260825..20260825` (피크 하루) | 7,231 |

`PAGE_SIZE`가 1000까지 받아들여지므로 목록 조회는 피크에도 15페이지 이내다. 부담은 목록이 아니라
상세 재호출이며 그것은 `LAST_CHG_DT` 비교로 좁힌다.

## 4. 확인하지 않은 것

- 다른 계절 구간에서 마감 뒤 변경 꼬리가 7일을 넘는지.
- `PAGE_SIZE` 상한.
- 피크 주에 `poll-open`을 30분 간격으로 돌릴 때의 실제 상세 재호출 건수.
