# 원본 필드를 쓰기 전 — 역사적 사고 기록

이번 주 가장 비싼 실수가 전부 여기서 났다. **원본에 값이 있다는 것과 그 값이 우리가 생각한 것이라는 건 다른 얘기다.**

---

## R1. `코드 → 이름`이 함수인지 **세어본다**

코드처럼 생긴 필드를 키로 쓰기 전에, **한 코드가 두 이름을 갖는 경우가 있는지 실제로 센다.**

```sql
select count(*) from (select CODE from T group by CODE having count(distinct NAME) > 1)
```

**치른 값 — 네 번 틀렸다:**

| 필드 | 형식 검사 | 실제 |
|---|---|---|
| `MLFD_CLASS_CD` | `_CD` 접미사 · 53.2% 채움 · 두 자리 숫자 — **셋 다 통과** | **코드가 아니다.** 60개 중 45개가 여러 이름(`02`→공산품 477·축산물 107·육류 81). 품목 목록 안의 **순번**이다 |
| `PDLC_NM` (1차) | 100% 채움 | 품목인 줄 알았다 → 아니었다 |
| `PDLC_NM` (2차) | 252종 · `시도/시군구` 형식 | 소재지인 줄 알았다 → **응찰 자격**이었다 |
| `_SGG_CANON` | — | 코드 분열의 증거로 인용했다 → **주소 문자열 잡음**의 증거였다 |

**통과한 것:** `PURR_CD` → 기관명 **0 / 6,590**. 그래서 학교 정체성 키로 쓸 수 있다.

> **"전부 id 있을걸"은 위험한 가정이다.** 학교(`PURR_CD`)·지역(`SIGUNGU_CD`)은 있었고 **품목은 없다.** 없는데 있다고 믿고 갈아타면 **60개 순번을 6개 품목으로 쓰는** 사고가 난다.

## R2. 키를 바꾸기 전 **역방향도** 잰다

한 방향만 보고 "더 안정적인 키"라고 판단하지 않는다. **양쪽을 다 센다.**

**치른 값 — `SHIPPER_CD`:**
```
한 SHIPPER_CD → 두 BIZ_NO :  0 / 5,366   ← 이것만 보면 "더 안정적"
한 BIZ_NO → 두 SHIPPER_CD : 23 / 5,343   ← 실제로는 더 잘게 쪼갠다
```
**업체 키를 `SHIPPER_CD`로 바꾸려던 걸 이 역방향 측정이 막았다.** 바꿨으면 23개 사업자의 이력이 쪼개져 A-8(학교 반토막)과 같은 죄를 새로 지었다.

**덤:** 같은 측정이 *"`biz_no` 재발급 위험"*도 닫았다. 재발급이 있었다면 **한 `SHIPPER_CD`가 두 `biz_no`를 갖는 형태**로 나타난다 — 0건이다.

## R3. **"이 필드는 무엇에 대한 값인가"**를 묻는다

채움률·고유값·형식을 확인해도 이 질문은 안 나온다. **따로 물어야 한다.**

> **이 필드가 붙어 있는 대상이 무엇인가 — 공고인가, 발주처인가, 응찰 자격인가, 표시명인가.**

**치른 값 — 다섯 번, 전부 "지역처럼 생긴 값"에서:**

| 축 | 원본 | 무엇에 붙나 |
|---|---|---|
| 소재지 | `SIDO_CD`·`SIGUNGU_CD` | 공고 |
| **응찰 자격** | `PDLC_NM`·`SGG_CD` | 자격 조건 |
| **표시명** | `DOG_ADDR` | 그때의 이름 |
| 행정 코드 | 코드 값 | 불변 정체성 |

**넷이 전부 한글 지명으로 표기된다.** `PDLC_NM`은 형식 검사 셋을 다 통과하고 축이 틀렸다.

같은 함정이 지역 밖에도 있다:
- **`RBID_YN`** — `'Y'`가 **91.7%**다. *"이것이 재입찰이다"*가 아니라 **"재입찰을 허용한다"**는 권한 플래그다
- **`MLFD_CLASS_CD`** — 분류 코드가 아니라 순번(R1)

> **축이 겹쳐 보이는 건 이 데이터의 성질이지 부주의가 아니다.** 부주의라면 "조심하자"로 끝나겠지만 구조적이라 **질문 한 줄이 실제로 막는다.**

---

## R4. 픽스처는 **실데이터에서** 뽑는다

지어낸 예시를 근거로 설계하지 않는다.

**치른 값:** `tests/test_normalize.py:73`의 `{"PDLC_NM":"한우"}`가 *"자격이 지역×품목 쌍일 수 있다"*는 가설을 낳았고, 설계 문서 여러 절이 거기 걸렸다. 실측하니 **`전남광주/전체` 표기 8건의 실제 소재지가 전북 군산 4건·경기 4건** — 가설이 틀렸다.

**그때 피해가 0이었던 이유는 하나뿐이다** — 설계자가 그 문단에 **⚠ "측정 전에 인용하지 마라"**를 달아뒀다. **가설을 세우는 것은 값싸고, 표시 없이 인용하는 것이 비싸다.**

→ **근거가 약한 문단에는 그 자리에 표시를 남긴다.**
