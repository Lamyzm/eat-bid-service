# EATGO 공개 정보구조와 FAQ 증거

- 확인일: 2026-08-31
- 공개 원문: [EATGO FAQ](https://eatgo.kr/home/faq_list.php)
- 범위: 로그인 전 좌측 navigation, 공개 FAQ 답변, 공개 marketing modal
- 제한: 분석 detail은 모두 로그인으로 redirect되어 메뉴명과 FAQ 밖의 실제 계산·화면·데이터 품질은 검증하지 못했다.

이 navigation은 EATGO가 단일 `AI 입찰가` 기능이 아니라 다음 폐루프를 제품으로 판매한다는 증거다.

1. 식자재 자동견적
2. 입찰금액 발급 또는 코칭
3. 견적과 실제 낙찰 연결
4. 계정별 성적·효과 증명
5. 학교·지역·경쟁·가격 시장 분석
6. 낙찰 후 납품학교 관리

메뉴 수와 2단 flyout 자체는 채택 근거가 아니다. `AI 분석` 안에 효과 검증, 개인 업무, 시장 탐색,
리포트가 모두 들어가 있어 사용자가 업무 단계보다 기능명을 먼저 해석해야 한다.

## 2. FAQ로 확인한 기능·계산 주장

### 자동견적

- 공고 상품명을 표준코드에 매칭하고 상품 master와 연결한 뒤 시세 기반 가격을 산출한다고 설명한다.
- 사용자가 등록한 단가를 우선하고 미등록 품목만 외부 시세로 보완한다.
- 혼합 공고도 품목별 `내 단가 / 시세 적용` 출처를 표시한다고 설명한다.
- 외부 가격 source로 KAMIS, 공영도매시장 경락가, 축산물품질평가원, 한국육류유통수출협회,
  나라장터 계약단가를 열거한다.

### 입찰 전략

FAQ는 다음 입력을 종합한다고 주장한다.

1. 기초가격 대비 과거 낙찰 비율의 14일 가중 평균
2. 참여자 수 group
3. 경쟁사 투찰 밀도와 겹침 회피
4. 지역·업종별 shift
5. 다계정 portfolio 분산

`실전 백테스트`, `랜덤 투찰 대비 평균 4배 이상의 낙찰률`도 주장하지만 표본, 기간, cohort,
baseline random 정책, 검증 방식은 공개 FAQ에 없다. 제품 사실이 아니라 검증되지 않은 marketing claim으로
취급한다.

### 효과 검증

- `지역별 예상 낙찰율`: 최근 공고를 simulation하고 지역·업종별 결과를 추첨 대비 배수로 표시
- `시스템 낙찰(내 계정)`: 발급값이 실제 개찰 결과의 낙찰 구간이었는지 과거 공고까지 계정별 누적
- `견적→낙찰 추적`, `견적 성적표`, `나의 견적현황`: navigation상 별도 화면

추천가보다 이 closed-loop proof가 상업적으로 더 중요하다. 사용자는 결과가 안 좋을 때 `왜 돈을 내는가`를
묻기 때문에 시스템 산출 이력과 실제 결과를 연결해 효과를 보여 주는 화면이 retention 장치가 된다.

### 가격

- 농산·수산·축산: 업종별 월 550,000원
- 공산품: 월 770,000원, 기본 5개 시군구, 추가 지역당 110,000원
- 종합: 월 990,000원, 기본 5개 시군구, 추가 지역당 110,000원
- 성과형: 가입비 990,000원 + 제시값 또는 부분 수정값 낙찰 시 낙찰금액 2%

이는 단순 분석 구독보다 `견적 원가 절감 + 입찰 운영 + 낙찰 후 효과 추적`을 함께 묶어 높은 가격을
정당화하는 구조다.

## 3. 공개 정보의 불일치와 미검증 항목

- FAQ 자동견적 답변은 `120만 건 이상 상품`, marketing modal은 `2,700만 식자재`라고 표현한다.
  서로 다른 분모일 수 있지만 정의가 공개되지 않아 동일 정확도 주장으로 합치면 안 된다.
- `100% 자동 매칭`, `평균 99.1점`, `랜덤 대비 4배`는 표본·분모·기간·실패 포함 여부가 없다.
- 학교별·지역별·경쟁 지도·가격 trend·AI report 화면은 로그인 redirect로 detail을 확인하지 못했다.
- navigation 존재를 구현 완료, 데이터 최신성, 분석 신뢰성의 증거로 사용하지 않는다.

## 4. EATBID 제품에 반영할 것

EATGO의 메뉴를 복제하지 않고 업무 폐루프를 가져온다.

```text
오늘
  마감·예외·결과 요약
공고
  발견 → 자격 확인 → 작업함
분석
  기관·지역·품목·경쟁·가격 evidence
성과
  후보/결정 revision → 실제 제출 → 개찰 결과 → 복기
견적·납품
  원가/견적 → 발주문서 → 납품학교 운영 (후속 단계)
```

- V1 분석은 현재 공고에서 시작하고 같은 `AuctionAttempt`의 결과·복기로 닫힌다.
- `시스템 낙찰 효과` 대신 실제로 기록된 candidate revision, source-observed submission, outcome을 연결한다.
- `낙찰 확률`과 추천가를 marketing hero로 두지 않는다. 관측 표본·분모·기간·계산 version을 먼저 보인다.
- 장기 가격을 높이려면 분석 chart 수가 아니라 자동견적, 문서, 납품과 같은 시간 절감 workflow가 필요하다.
