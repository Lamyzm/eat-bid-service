# SPEC — 품목 축 전역화

사용자 지적: *"축산 공산 나눠져 있거든. 모든 화면이 이 부분 기획을 제대로 안 했네."*
지역 축은 전역화(헤더 칩·`useRegion`·상태 줄)했으나 **품목 축은 화면마다 제각각**이고 오늘 화면엔 아예 없다.
결함 실증: 축산만 하는 사장에게 **김치·농산 공고가 `자격 충족`**으로 뜬다 — 자격 판정이 지역만 본다.

**리더 권고에 동의한다.** 근거: 두 축은 성격이 같다. 지역은 *사무소 소재지* 기준 자격, 품목은 *취급 품목* 기준 자격이고
**둘 다 "내 사업자"에서 파생**된다. 축을 따로 관리하면 같은 결함이 재발한다.
모델: `내 사업자 → (지역 집합, 품목 집합) → 전역 필터`, 둘러보기(임시 override)도 대칭.

## 1. 전수 조사 — 화면별 현재 품목 처리

| 화면 | 지금 | 문제 | 전역화 판정 |
|---|---|---|---|
| **오늘** | **없음** (카드에 품목 배지만 표시, 필터·자격 판정 모두 지역만) | **김치 공고에 `자격 충족` = 거짓말**. 33건 클러스터에 남의 품목이 섞임 | ✅ **전역 필수(1순위)** |
| 공고 상세 ② | 배지 표시만, `open.category` | 헤더 배지 `자격 충족`이 품목 미반영(오늘과 동일 결함) | ✅ 전역(자격 문구) |
| 분석판 | 회차 행·월별 렌즈에 품목 컬럼, **필터는 하한만** | 축산 사장이 공산 회차까지 섞인 분포를 봄 → S-1과 같은 분모 오염 | ✅ 전역 기본 + 공고 컨텍스트 우선(§5) |
| 낙찰(속보·월별) | **로컬 칩 6개**(`cat` state) + 월별 보드는 품목이 열(축) | 로컬 상태라 화면 이동 시 초기화 | ⚠️ **부분 예외** — 속보는 전역, 월별 보드는 품목이 축이라 전량 표시 |
| 학교 찾기 | **로컬 칩 6개**(필터 내부) | 전역 불일치 | ✅ 전역 |
| 내 성적 | 표 컬럼으로 표시만, 필터 없음 | 품목별 성적을 못 봄(사장은 축산/공산 성적을 따로 본다) | ✅ 전역 |
| 납품 | 정산 표 컬럼 표시만 | 〃 | ✅ 전역 |
| **시장 지도** | **로컬 칩 5개**(`cat` state, API 파라미터) | — | ❌ **예외(비교가 목적)** — §2 |
| 퍼널 | 무관 | — | ➖ 해당 없음 |
| 내 설정(사업자) | **품목 개념 자체가 없음** | 전역화의 근원이 비어 있음 | ✅ **여기서 시작**(품목 집합 등록) |

## 2. 전역화 대상 / 예외

**전역 적용(기본)**: 오늘 · ② · 분석판 · 낙찰 속보 · 학교 찾기 · 내 성적 · 납품
**예외 2개 — 이유 명시 + 전역 상태와의 관계 표기 의무**

| 예외 | 왜 | 전역 상태 표기 |
|---|---|---|
| 시장 지도 | **품목 비교가 화면의 목적**(축산 시장 vs 공산 시장). 전역 1개로 고정하면 화면 존재 이유가 사라짐 | 진입 시 전역 품목으로 초기화 + 다른 품목 선택 시 `공산 둘러보는 중 · 내 품목은 축산` (지역 "구경 중"과 동일 문법) |
| 낙찰 월별 보드 | 품목이 **표의 열(축)** 이라 전량 표시가 정보 구조 | 표 상단 `내 품목: 축산·공산` 표기 + 내 품목 열만 배경 강조 |

## 3. UI — 헤더 예산 (1280에서 이미 넘침)

**결론: 헤더에 품목 칩을 나열하지 않는다.** 지역 칩(2~3개)만으로 이미 브레드크럼이 깨졌다.

- **채택안: 헤더에 필터 요약 버튼 1개** → 팝오버에서 지역·품목을 함께 조작
  ```
  헤더:  [ 김해시 · 축산 ▾ ]        ← 컨트롤 1개 (현행 지역 칩 2~3개를 흡수 = 순감)
  팝오버: 지역  [전체][김해 12][창원 5]
          품목  [축산][수산][공산][농산][김치]   ← 다중 선택(내 품목 기본 체크)
          [내 사업자 기준으로 되돌리기]
  ```
- **컨트롤 예산**: 헤더 순증 **−1 ~ 0**(지역 칩 2~3 → 요약 버튼 1). 팝오버 내부는 화면 컨트롤로 계산하지 않음(모달 규칙)
- 화면 상태 줄(기존 지역 한 줄)에 품목 병기: `김해시 · 축산 기준 · 공고 12건` — **신규 컨트롤 0**
- 둘러보기 중이면 요약 버튼 앰버(지역과 동일 규칙)
- 화면별 로컬 칩(낙찰·학교 찾기·시장 지도)은 **제거**(지도는 예외 유지) → 실제로는 컨트롤 **−15개 이상 순감**

## 4. 자격 표기의 정직성

품목 자격을 **확실히 아는 경우와 모르는 경우**를 문구로 가른다. 모르면 단언 금지.

| 상태 | 문구 | 조건 |
|---|---|---|
| 지역·품목 모두 확인 | `자격 충족 (지역·품목)` | 사용자가 품목 집합을 명시 등록 + 공고 품목이 그 안 |
| 지역만 확인 | **`지역 자격 충족 · 품목은 확인하세요`** | 품목 집합 미등록(현 전 사용자) — **기본값** |
| 품목 불일치 | `내 품목 아님(김치)` 회색 처리 + 목록에서 접힘 | 품목 집합 등록됨 + 불일치 |
| 지역 불일치 | 기존대로 미표시 | |
- 오늘 화면 기본 동작: **내 품목 외 공고는 숨기지 않고 접어둔다** — `다른 품목 5건 보기` 한 줄(재료는 다 있다 원칙)
- 근거 표기: 자격 배지 hover/보조문 `사무소 소재지(김해) 기준 · 품목은 등록하신 축산·공산 기준`

## 5. S-1(품목별 분모)과의 연결 — 우선순위 규칙

data가 `by_cat_floor`·`cat_counts`·`school_roster_cat`으로 분모를 갈랐다. 규칙:

1. **공고 컨텍스트가 항상 우선** — ②(공고 상세)와 그 공고에서 진입한 분석판은 **그 공고의 품목**으로 고정.
   전역이 축산이어도 공산 공고를 보고 있으면 공산 분모. 표기: `이 공고 품목: 공산 기준 · 34회`
2. **컨텍스트가 없으면 전역** — 학교 찾기·직접 진입한 분석판·내 성적·납품은 전역 품목 집합
3. **전역이 다중(축산+공산)일 때** — 분포·리허설은 **품목별로 분리 표시**(합산 금지, S-1의 교훈).
   분석판 상단에 품목 탭 `[축산 34회] [공산 21회]`
4. **표본 n은 항상 품목 기준으로 표기** — `축산 34회 기준`(합산 55회로 부풀리지 않음)

## 6. 마이그레이션 — 두 갈래 대비

`user_biz`에 품목 컬럼 없음. data가 "사업자 품목 자격을 데이터로 알 수 있는가" 조사 중.

**ⓐ 데이터로 알 수 있다** (firm_bids의 내 투찰 이력 품목 분포로 유도)
- 스키마: `user_biz.categories jsonb` (null = 미확정)
- 온보딩/설정에서 **자동 제안 + 사용자 확정**: `기록상 축산 1,204회 · 공산 88회 — 취급 품목을 골라주세요 [축산][공산]`
  (자동 확정 금지 — 지역 자격 유도 때와 같은 함정: 이력은 소재지/취급의 증거이지 정의가 아님)
- 임계: 특정 품목 투찰 ≥20회면 후보로 제시, 그 미만은 회색

**ⓑ 사용자가 직접 골라야 한다**
- 동일 스키마, 제안 없이 체크박스만. 온보딩 3단계에 추가(지역 선택 바로 옆), 설정에서 변경
- 미등록 상태 = **전 품목 표시 + `품목은 확인하세요` 문구**(§4 기본값) — 잘못된 자격 단언보다 안전

**공통 (두 갈래 모두)**
- 기존 사용자 데이터 소실 경로 없음(컬럼 추가만, null 허용)
- 미등록자는 현행과 동일 동작 + 정직한 문구로만 바뀜 → **품목 등록 없이도 서비스가 성립**
- 등록 유도: 오늘 화면 상태 줄에 `품목을 등록하면 내 공고만 볼 수 있습니다 →` 1줄(컨트롤 0)

## 7. 구현 크기·순서
1. (front, 하) **자격 문구 정직화** — `지역 자격 충족 · 품목은 확인하세요`. **오늘 즉시 가능, 거짓말 제거가 최우선**
2. (data, 하) `user_biz.categories` 추가 + 품목 자격 조사 결과 반영
3. (front, 중) 헤더 필터 요약 버튼 + `useCategory` 훅(useRegion 대칭) + 로컬 칩 제거
4. (front, 중) 전역 적용 7화면 + 예외 2화면 표기
5. (front, 하) 분석판 품목 탭(S-1 분모 연결)
