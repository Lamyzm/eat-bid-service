# SPEC — 오늘 일괄 표 (사업자 2칸)

sim §7 실측이 제품의 모양을 바꿨다: 아버지는 **2개 사업자로 670회차 중 90.3%를 중복 투찰**하고(1,275엔트리),
값은 정밀 계산이 아니라 **구간 산포 배치**(8/24 실물 33건 = 17개교 × 2사업자, 88.677~91.598 산포, 건마다 다른 값),
하루 부하는 **중앙값 9건 · p90 32건 · 최대 54건**. 그런데 **우리 UI엔 사업자 축이 없다.**

→ 제품 성격 재정의: **분석 도구가 아니라 사무 자동화 + 놓침 보험.**
값 정하기를 "돕는" 것은 마이너스다 — 15초/건 산포 찍기를 1~3분 근거 정독으로 바꾸면 노동이 늘어난다.
**이 표의 성공 기준은 하나: 하루 33건을 지금보다 빠르게 끝내는가.**

---

## 0. 선행 조건 (충족 전 착수 금지)

1. **S-1 품목 혼합 분모** (data P4 진행 중) — 일괄 표는 짓는 순간 오염된 구간·통계를 그대로 물려받는다.
   표에 학교별 참고 수치(최근 낙찰·구간)를 곁들이는 순간 틀린 재료가 33건에 동시 노출된다.
2. **장중 공고 폴링** — 현재 크롤은 일 1회 03시. **공고 수명 최소 0일**(당일 게시·당일 마감)이라
   03시 스냅샷에 없는 공고는 표에 아예 안 뜬다. 놓침 보험을 표방하면서 놓치는 구조 = 제품 신뢰 즉사.
   폴링(≥1시간 간격) 전까지는 표 상단에 `03시 기준 목록입니다` 고지 의무.

---

## 1. 구조 — 행 = 공고, 열 = 사업자

```
오늘 마감 33건                                    [03시 기준 · 새로고침]
학교          품목  기초금액      하한   신성유통    오뚜기축산   NeaT
장유고        축산  16,399,100   90    [90.05  ]  [90.31   ]   ☐ ☐
주촌초        공산   9,321,400   90    [88.68  ]  [        ]   ☐ ☐
관동중        축산  13,497,900   90    [90.02  ]  [91.60   ]   ☑ ☐
...
합계 33건 · 값 입력 41/66칸 · NeaT 입력함 12/41
```

- **1행 = 1공고**, 사업자 수만큼 값 칸(2개 = 아버지 케이스). 빈 칸 = 그 사업자로는 안 넣음(정상 상태)
- 값 칸 옆 **NeaT 체크박스**(§4 안전장치 ②) — 사업자별 1개씩
- 참고 수치는 **기초금액·하한만**(사실, 계산 재료). 구간·최근 낙찰은 **행 확장(▸)에서만** — 기본 접힘.
  이유: 산포 찍기 리듬을 근거 정독으로 바꾸지 않기 위해. 필요한 사람만 편다
- 정렬: 마감 시각 → 학교명. 필터: 품목 칩(기존 재사용)

## 2. 입력 리듬 — 키보드만으로 끝난다 (실패 기준)

15초/건이 깨지면 이 기능은 실패다. 마우스 왕복 금지.

| 키 | 동작 |
|---|---|
| 숫자 입력 | 즉시 반영(디바운스 300ms 자동 저장, 저장 버튼 없음) |
| `Tab` | 오른쪽 칸(같은 행 다음 사업자 → 다음 행 첫 사업자) |
| `Enter` | 아래 행 같은 사업자 칸 (열 단위 산포 찍기 = 실제 동작에 최적) |
| `Shift+Tab` / `↑` | 역방향 |
| `Space`(체크박스 포커스) | NeaT 입력함 토글 |
| `Ctrl+D` | 위 칸 값 복사(연속 학교에 유사 값 흩뿌릴 때) |

- 값 형식: `90.05` 직접 입력만. **자동 제안·플레이스홀더 추천값 없음**(헌법)
- 하한 미만 입력 시 칸 테두리 적색 + 행 끝에 `하한 90 미만` — 차단하지 않음(전략적 낮은 투찰은 사장의 선택)
- 저장 단위: `user_mark(bidNo, bizNo, rate)` — **현 스키마는 bizNo 축이 없다 → PK에 bizNo 추가 필요**(§3)

## 3. 사업자 축

- 출처: `workspace_biz`(워크스페이스) / `user_biz`(계정) / 게스트는 `eatbid.bizNos` — **기존 3경로 그대로 읽음**
- **1개**: 열 1개 표(같은 구조, 폭만 좁음). 표 자체는 동일 컴포넌트
- **3개 이상**: 열 3까지 표시 + 초과분은 가로 스크롤(열 고정: 학교·품목). 현실 분포상 2가 대다수
- **0개**: 표 대신 기존 카드 유지 + "사업자를 등록하면 값을 입력할 수 있습니다"
- **U9 동시 해소**: 지금까지 사업자별 값이 어디에도 안 보였다 → 이 표가 유일한 사업자 축 화면이 된다.
  스키마 변경(`user_mark` PK에 bizNo 추가)은 내 성적·채점에도 사업자 구분을 열어준다

## 4. 출시 차단 조건 — 안전장치 3 (없으면 짓지 않는다)

최대 리스크는 법이 아니라 **오인**이다. 일괄 표가 완성되면 "다 저장했다 = 다 넣었다"로 착각해
NeaT를 안 열고 클러스터 33건을 통째로 날릴 수 있다. 한 달 장사가 사라진다.

**① 명칭 격하 (canon 준수)**
- 폐기: "투찰 저장", "투찰함", "저장" 단독 사용
- 채택: 값 칸은 라벨 없는 입력(암묵), 저장 상태 표시는 **`적어둠`** / 표 제목은 **`오늘 마감 33건`**
- 완료 표현은 오직 NeaT 체크 문구에만: **`NeaT에 입력함`**
- 금지어 추가(COPY-GUIDE): 저장=제출로 읽히는 "투찰 저장·제출·등록·접수"

**② 행별 `NeaT에 입력함` 사용자 직접 체크 + 마감 전 미확인 경고**
- 값이 적힌 칸에만 체크박스 활성(값 없으면 비활성)
- 상단 카운터 상시: `값 41칸 · NeaT 입력함 12칸` — **숫자 차이가 곧 경고**
- 마감 3시간 전 미체크분: 표 상단 적색 띠 `NeaT 미확인 29칸 · 마감 3시간 전` + 알림 1회(배치 #7 ②)
- 체크는 **사용자 신고**일 뿐 검증이 아님을 문구로 명시(다음날 개찰 결과로 사후 확인됨)

**③ 상시 문구 (표 상단 고정, 스크롤해도 유지)**
> **이 표는 값을 적어두는 곳입니다. 투찰은 공공급식통합플랫폼(NeaT)에서 직접 하셔야 합니다.**
> 우리는 대신 넣지 않습니다.
- 회색이 아니라 **본문 색**으로. 접기 불가. 첫 방문 시 1회 모달 확인(다시 보지 않기 가능하나 상단 띠는 영구)

## 5. U28 컨트롤 예산 — p90 32건인 날

현재 오늘 화면: 컨트롤 32개 · 스크롤 1.97판. 표 도입 후:

| 항목 | 처리 |
|---|---|
| 기존 카드 그리드 | **표로 대체**(카드당 컨트롤 3~4개 × N → 행당 입력칸 2 + 체크 2). 카드 폐기 = 순삭 |
| 헤더 컨트롤 | 품목 칩(기존) + [새로고침] 1개 = **7개 이내 유지** |
| 33건 행 | 행 컨트롤은 표 스크롤 안(가상 스크롤 불필요, 33행은 DOM 감당) — **페이지 스크롤은 표 높이 60vh 고정으로 1.2판 이내** |
| 발주 예정·개찰 결과 | 표 아래 접힘 섹션 2개(기본 접힘) — 클러스터 날엔 표가 화면을 지배 |
| 순증 컨트롤 | 새로고침 1 + 상시 문구 0(텍스트) = **+1**, 카드 폐기로 실제로는 대폭 감소 |

계측: `batch_row_input`(칸 입력), `neat_check`, `batch_time`(첫 입력~마지막 입력 경과) —
**목표: 33건 완료 시간이 기존 대비 감소.** 늘어나면 롤백.

## 6. 실패 시나리오 3

- **F1 미투찰 사고(§4가 방어)**: 표만 채우고 NeaT 미실행 → 클러스터 전량 손실. 방어 3중 + 다음날 개찰 결과로
  "적어둔 값이 실제 투찰에 없음"을 감지해 사후 경고(`적어둔 33칸 중 12칸만 실제 투찰로 확인됨`)
- **F2 리듬 저하**: 표가 카드보다 느리면(포커스 이동 버벅, 자동저장 지연) 사장은 엑셀·수첩으로 돌아간다.
  방어: 키보드 전용 경로 완성 전 출시 금지, batch_time 계측으로 판정
- **F3 03시 스냅샷 누락**: 당일 게시·당일 마감 공고가 표에 없어 놓친다 — 놓침 보험이 놓침의 원인이 됨.
  방어: 폴링 필수(선행 조건 2), 그 전까지 `03시 기준` 고지 + [새로고침] 버튼으로 수동 재조회

## 7. 크기·순서
- 선행: S-1 완료 + 폴링(또는 고지·수동 새로고침으로 임시 출시)
- data 중(`user_mark` PK에 bizNo 추가 + 배치 upsert API) / front 상(표·키보드 네비·안전장치 3)
- **9/12 준비 마감 기준 우선순위: 안전장치 3 > 키보드 리듬 > 참고 수치 확장** — 뒤 둘이 미완이면 출시 연기, 앞이 미완이면 착수 금지
