## 채택된 방법론 (2026-08-27 확정)

### A. 상업성 게이트 (통과 전 다음 단계 투자 금지)
- G1 사용 검증: 아버지가 시키지 않아도 3회 연속 투찰에서 먼저 엶 → 전제: cloudflared 접속(사용자 계정 대기)
- G2 지불 의사: 남 사장 1명이 "얼마면 쓰겠다" 구두 (김해 축산 단골 = 후보군). Mom Test 화법 — "쓰시겠어요?" 금지, "지난달 투찰 때 뭐가 제일 답답했어요?"부터
- G3 첫 결제: 계좌이체라도 1명 → 그때 Clerk·요금제(무료/월 2.9만, "구경 공짜·결정 도구 유료")
- 게이트 측정용 이벤트 로그(화면 열람) 필수 — 자체 테이블, 외부 SaaS 불필요

### B. 디자인 절차
- 레퍼런스 보드: 토스증권·트레이딩뷰·네이버페이증권·카카오뱅크·비드큐 스크린샷 대조 후 작업
- DESIGN.md 제정(토큰·카드·표·차트·칩 패턴) — 화면 간 미세 불일치 제거
- **PC 우선** (사용자 확인: 투찰은 보통 PC로 함) — QA 뷰포트 1280/1920, 모바일은 후순위
- 화면당 히어로 숫자 1개: ②=하한 금액, 분석판=리허설 판정, 성적=낙찰률

### C. 구축 후보는 여정의 빈칸에서만
- 요새(완성): 공고 발견·판단/투찰·복기
- **다음 대형 구축 = "낙찰 후" 구간**: 계약·납품 일정표 + 월 정산 요약 — 매일 열 이유
- 그다음: 월간 시장 리포트(구독 갱신 정당화), 알림 v2(G1 이후), 2호 사무소 시뮬(후순위)

### 즉시 실행 순서
1. 이벤트 로그 심기(화면 열람 추적)
2. PC 뷰포트 QA 패스 + DESIGN.md 제정
3. cloudflared(사용자 Cloudflare 계정 필요) → 아버지 G1 시작
4. 낙찰 후 구간(납품 일정표) 스펙 → critic 심사 → 구현
