# 재파싱 후 화면 확인 목록

**왜 이 문서가 있나**: 게이트 A 는 레이크·DB 기준이다. **DB 가 초록인데 화면이 그대로면 우리는 또 속는다** —
"만들었다와 돈다 사이"에서 오늘만 다섯 번 났다. 이 목록은 **화면에서** 확인한다.

**기준값 측정 시각**: 2026-08-29 (재파싱 전, 폴링 반영된 상태)
**측정 방법**: 라이브 API 직접 조회. 아래 각 항목의 "지금" 열이 그 값이다.
⚠ **`/api/schools` 는 서버 상한이 500** 이라 학교 관련 수치는 **전수가 아니라 표본**이다. 재파싱 후에도 같은 조건(limit=500)으로 재야 비교가 성립한다.

## 1. 지역 필터 — 이름 오염이 가장 직접 드러나는 자리

| 확인 | 지금 | 통과 기준 |
|---|---|---|
| `/api/wins/regions` 개수 | **153** | 줄어야 한다. `급식실` 류가 빠지면 감소 |
| 그중 오염 항목 | **0건** (`급식실`·`학교` 포함 없음) | 계속 0 |
| 최소 표본 `n` | **5** (영종구) | 유지. 문턱을 다시 세우면 신설 지역이 또 잘린다 |

**보는 법**: 드롭다운을 열어 `급식실`·`학교`·괄호가 든 항목이 있는지 눈으로 훑는다.

## 2. 자격 판정 — 사장이 낼 수 있는 공고 수

| 확인 | 지금 | 통과 기준 |
|---|---|---|
| 열린 공고 | **111** | 유지 |
| `unrestricted`(무제한) | **61** | 유지. 크게 변하면 허용지역 파싱이 바뀐 것이니 근거를 물어야 한다 |
| 오염된 시군구를 가진 열린 공고 | **`급식실` 1종 존재** | **0** |
| `schoolId` 에 구분자 없는 행 | **0** | 계속 0 |

**화면**: 오늘 화면에서 자격 지역을 **의정부시**로 두고 목록 수를 센다.
**지금 값**: 의정부 기준 = 무제한 61 + 의정부 소재 0 = **61건**
**통과 기준**: 재파싱 후에도 **0건이 되지 않는다.** 0이면 `unrestricted` 판정이 깨진 것이다.

## 3. 지도 — 좌표가 붙지 않는 지역

| 확인 | 지금 | 통과 기준 |
|---|---|---|
| `/api/market` 고유 (시도\|시군구) | **246** | 줄어야 한다(빈 시도가 사라지면) |
| **빈 시도 행** | **2건** — `(빈시도)\|고양시`, `(빈시도)\|덕진구` | **0건** ← 재파싱으로 해소돼야 하는 자리 |
| 지도 `좌표 없음 N곳` | **7곳** (인천 5 + 빈시도 2) | **5곳으로 감소**. 인천 5곳(미추홀·검단·제물포·서해·영종)은 좌표 소스가 2017 스냅샷이라 **재파싱으로 안 풀린다** |

**화면**: 시장 지도 하단 `좌표 없음 N곳` 줄과 그 옆 버튼 목록.
**주의**: 7 → 5 가 아니라 **7 → 7 이면 빈 시도가 안 고쳐진 것**이고, **7 → 0 이면 좌표표가 어디선가 바뀐 것**이라 둘 다 물어봐야 한다.

## 4. 학교 id 형태 — 동결 설계의 전제

| 확인 | 지금(표본 500) | 통과 기준 |
|---|---|---|
| 구분자 `\|` 없는 id | **0** | 계속 0. 1건이라도 생기면 `parseSchoolId` 가 학교명 전체를 이름으로 본다 |
| `\|` 2개 이상(학교명에 구분자 포함) | **0** | **계속 0** ← 별칭표·URL 이 여기서 깨진다 |
| URL 위험문자(`% # ? / & +` 공백) | **0** | 계속 0. 생기면 인코딩 왕복 테스트에 그 케이스를 추가한다 |
| 이름이 중복인 학교 종류 | **4종** | 줄거나 유지 |

**⚠ 재파싱 후 반드시 다시 잴 것**: 위 네 줄은 전부 **표본 500** 기준이다.
새 키 형식이 코드 기반으로 바뀌면 이 표의 전제 자체가 바뀌므로, **형식이 바뀌었는지부터** 확인한다.

**화면**: 낙찰 속보와 오늘 발주 예정에서 학교 링크를 **실제로 눌러** 분석판이 뜨는지 본다.
(어제 이 경로가 이중 인코딩으로 죽어 있었다. `학교를 찾지 못했습니다` 가 보이면 즉시 보고)

## 6. 🔴 재료 없음 — **이 문서에서 가장 중요한 지표**

| 확인 | 지금 | 통과 기준 |
|---|---|---|
| 과거 기록이 없는 열린 공고 | **38 / 111 (34%)** | **크게 줄어야 한다**(재적재로 학교 이력이 붙는다) |

**이 숫자 하나가 게이트 A 와 화면 사이를 잇는다.**
게이트 A 는 레이크·DB 기준이라 **DB 가 전부 초록이어도 이 수가 그대로일 수 있다.**
그러면 재적재가 화면까지 도달하지 않은 것이고, **DB 초록은 통과가 아니다.**

> **이 수가 안 줄면 다른 지표가 전부 통과해도 실패로 판정한다.**

**화면**: 오늘 카드에서 `이 학교는 지난 개찰 기록이 아직 없습니다` 문구가 몇 장에 뜨는지 센다.
**보는 순서**: 다른 확인보다 이걸 먼저 본다. 여기서 막히면 나머지를 볼 이유가 없다.

## 7. 확인 순서 (10분)

1. **오늘 화면의 `기록 없음` 카드 수부터 센다**(§6). 안 줄었으면 여기서 멈추고 보고한다
2. `/api/stats` 를 찍어 0번 표와 대조 — 다르면 어디가 움직였는지 안다
3. 오늘 화면: 자격 지역 **의정부** → 목록 수(기대 61 근처) · `추정` 뱃지 수
3. 헤더 지역 드롭다운: 오염 항목 육안 확인
4. 시장 지도: `좌표 없음 N곳`
5. 낙찰 속보 → 학교 링크 클릭 → 분석판이 뜨는지
6. 학교 id 형태 재측정(limit=500 동일 조건)

**하나라도 어긋나면 그 자리에서 멈추고 보고한다.** 화면이 조용히 맞아 보이는 게 가장 위험하다.

## 8. ⚠ 동결 설계에 영향을 주는 발견 — 오염이 `schoolId` 안에 있다

측정 중 확인했다. 파싱 쓰레기가 시군구 **컬럼에만** 있는 게 아니라 **id 문자열 자체**에 박혀 있다.

```
schoolId: "급식실|혜성여자고등학교"     ← 열린 공고 5건이 이 id 를 쓴다
```

그래서 **별칭표를 언제 뜨느냐가 설계 변수**가 된다.

| 시점 | 결과 |
|---|---|
| **재파싱 전에 뜬다** | 오염된 id(`급식실\|…`)가 별칭표에 그대로 들어간다. 다만 **그게 실제로 발급됐던 URL** 이라 옛 링크가 산다 |
| **재파싱 후에 뜬다** | 표는 깨끗하지만, 재파싱 전에 발급된 URL 은 **재파싱 시점에 이미 죽는다**(그 id 가 DB 에서 사라지므로) |

**권고**: **두 시점을 다 뜬다.**
1. 재파싱 **직전** 스냅샷 → `옛키(오염 포함) → 학교 식별자`
2. 재파싱 **직후** 스냅샷 → `중간키 → 새 코드키`
두 표를 합성해 하나로 만든다. 어느 쪽도 규칙이 아니라 **관측된 목록**이라 `Map.get` 한 번으로 끝나고,
"이름으로 비교"가 생기지 않는다는 원칙은 그대로다.

**지금 필요한 조치**: `data` 가 재파싱을 시작하기 **전에** `SELECT id FROM schools` 스냅샷을 파일로 떠 둬야 한다.
안 뜨면 그 시점 값은 영영 복구할 수 없다. **재파싱 시작 전에 처리돼야 하는 유일한 항목이다.**
