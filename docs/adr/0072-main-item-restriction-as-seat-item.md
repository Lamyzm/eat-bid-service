# 0072 — 품목 제한이 없는 공고는 "품목 제한 없음" 자리가 받는다

- Status: Accepted
- Date: 2026-11-05
- Supersedes: [ADR 0071](0071-market-seat-and-auction-amount-assignment.md) 결정 1의 "품목 `code_value` 하나"와 결정 2의
  "품목 코드가 없는 공고에는 시범 동안 금액을 내지 않고 비율만 잰다". 0071의 나머지 결정과 기각안("품목 없는 공고를 지역만으로
  배정")은 그대로다.
- 관련 작업: EAT-370(이 결정과 수집), 후속 배정 규칙 r2·금액 잠금 교체 이슈
- 승인: 사용자(제품 소유자) 결정, 2026-11-05 원인 조사 뒤 "ㅇㅇ"·"ㄱㄱ"

## Context

0071 규칙대로면 품목 코드가 없는 공고에는 금액이 나가지 않는다. 2026-09~10 오뚜기축산·신성유통이 넣은 공고 163건 가운데
22건(13%)이 그렇고, 전국은 약 3분의 1이다. 대부분 학교 소액 수의 견적이고 제목에는 "육류"가 분명히 있다.

원인은 데이터 오류가 아니다. 품목 코드는 eaT 상세 `ds_info.MAIN_ITEMS`(주요 품목)에서 만들고, 이 칸은
`ds_info.MN_TRMT_LMT_YN`(주요 취급 품목으로 참가를 제한하는가)과 정확히 같이 움직인다. 2026-09 전수 183,777건에 예외가
없다(`docs/AUDIT-SOURCE.md` §4). 학교가 품목 제한을 걸지 않으면 `N`이고 품목 칸이 빈다. 2026-11-05 R2 원문으로 아버지 22건과
2026-10 전국 표본 400건이 전부 `N`임을 확인했다. 품목은 제목과 담당자가 친 구매 줄(`ds_itemList.MLFD_CLASS_NM`)에만 남는데, 이
둘은 품목 필터 입력으로 쓸 수 없는 자유 입력이다(`docs/audit-source/SOURCE-FIELDS.md` T6).

같은 조사에서 한 번도 읽지 않던 `ds_info.CERT_KND_CD`(인증 종류)를 찾았다. 품목이 있는 공고에서는 041=육류(31/31),
043=수산(16/16), 045=김치(7/7), 046=가금(11/11)으로 거의 1:1이다. 그러나 품목 없는 공고 400건 중 041~046이 붙은 것은 45건(11%)뿐이고
999가 57건, 빈칸이 298건이다. 아버지 22건은 041이 7건, 999가 13건, 빈칸이 2건이다. 같은 학교(김해신안초)가 10월엔 999, 11월엔 041을
썼다. 품목이 아니라 학교가 고른 인증 조건으로 보이고, 이름 칸이 없어 뜻을 확정할 수 없다.

## Decision

1. **`MN_TRMT_LMT_YN`을 원천 코드로 저장한다.** 코드 체계 `eat:main-item-restriction`(소유 aT), revision role
   `main_item_restriction`이다. Y/N 그대로 받고 우리 말로 바꾸지 않는다. parser eat-v6부터 관측하며, 옛 version 개정본에는 연결이
   없고 그것은 "미관측"이지 `N`이 아니다(ADR 0038).
2. **자리의 품목 칸은 품목 원자 하나 또는 "품목 제한 없음"(`eat:main-item-restriction`의 `N`) 하나를 가리킨다.** 두 체계를
   섞지 않는다. 공고 쪽 짝은 role `item`의 원자들과, role `main_item_restriction`이 `N`인 경우 그 code value 하나다. 걸침 판정은
   0071과 같이 (지역, 그 값) 짝의 정확 일치다. `Y`는 자리가 되지 않는다 — `Y`인 공고는 품목 원자가 있고 그 원자 자리가 받는다.
3. **둘 다 없는 공고(옛 version 개정본)는 0071대로 금액을 내지 않는다.** 재처리로 eat-v6 개정본이 생기면 다음 요청부터 걸친다.
4. **`CERT_KND_CD`는 저장만 하고 자리 판정에 쓰지 않는다.** 코드 체계 `eat:certification-kind`, role `certification_kind`다.
   뜻이 확인되면 "품목 제한 없음" 자리를 더 잘게 나눌 재료가 된다. 따로 넣으면 parser 버전과 재처리를 한 번 더 해야 해서 같은
   version에 싣는다.

## Consequences

- 김해 육류 업체는 (김해, 육류)·(김해, 가금류)·(김해, 품목 제한 없음) 세 자리로 자기 공고를 모두 받는다. 다른 품목 자리를 산
  업체가 이 공고를 가져갈 수 없다 — 0071이 지역만 배정을 기각한 이유가 그대로 지켜진다.
- 대신 "품목 제한 없음" 자리는 그 지역의 육류·김치·가공식품 소액 견적을 모두 한 업체에 준다. 값은 품목 자리와 따로 정한다
  (PDR-0010의 가격 결정에 남김).
- `market_seat.item_code_value_id`는 이름과 달리 두 체계 중 하나를 가리킨다. DB FK는 `code_value`까지만 막으므로 체계 검사는
  자리를 만드는 운영자 경로가 진다(금액 잠금 교체 이슈).
- 2026-08 이전 마감 공고에는 전국에 품목 코드가 없다(그 전 개정본은 품목 투영 전 version이다). 이 결정과 별개로, eat-v6 배포 뒤
  replay-pipeline 재처리로 함께 채운다. 운영 작업이라 제출은 사용자 결정이다.

## Rejected alternatives

- **제목·구매 줄에서 품목을 짐작.** 학교마다 같은 뜻을 다르게 쓰고 월·용도가 섞인다(T6). 틀리면 남의 자리 공고 금액을 다른
  업체에 보여 준다.
- **`CERT_KND_CD`를 품목으로 매핑.** 품목 없는 공고의 11%만 덮고, 뜻이 확인되지 않은 코드를 다른 체계와 같다고 보는 일이다(AGENTS 6).
- **품목 없는 공고를 지역만으로 배정.** 0071이 기각한 그대로다.
- **"품목 제한 없음"을 `eatbid:auction-item` 원자에 하나 더하기.** 품목이 아닌 것을 품목 어휘에 넣으면 우리가 그 정의를
  소유하게 되고, 원천이 말한 사실(제한 안 함)과 우리 분류가 한 체계에 섞인다.
