# 0065 — 공고 시도의 최신 개정본은 관측 순서로 고른다

- Status: Accepted
- Date: 2026-10-11
- Supersedes: [domain-and-data.md](../architecture/domain-and-data.md)의 "`최신`은 `auction_revision_id` 최대값이며 replay가
  관측 시각을 되돌려도 append 순서는 단조롭다" 문장(열린 공고 스냅샷 절). 다른 ADR의 결정은 바꾸지 않는다.
- 관련 작업: EAT-333, EAT-335(ADR 0064 개찰 결과 줄, PR #176의 배포 선행 조건)
- 승인: 총괄 Tech Lead 결정(사용자 위임, 2026-10-11)

## Context

공고 상세·명단·지역 범위 조회와 mart 빌드 넷(회차 요약, 낙찰률 분포, 열린 공고 스냅샷의 상세 열, 최신 관측 미반영)은 한
공고 시도의 "최신 개정본"을 `auction_revision_id` 최대값으로 골랐다. 개정본 번호는 **투영 순서**다.

| 관측 (운영 DB 읽기, 하한율 90) | 값 |
|---|---|
| 2024-01~2026-08 달마다 번호 기준이 틀린 회차 | 0~44 |
| **2026-09** 번호 기준이 틀린 회차 | **11,162건 중 10,849건** — 명단이 보이는 회차가 번호 기준 3,661, 관측 시각 기준 9,963 |
| 관측 번호 기준이 틀린 회차 | 모든 달 0 (관측 번호 순 = 관측 시각 순) |
| 9월 번호 최대 개정본의 출처 | daily-reconcile이 9월 중순에 받은 관측 15,778개를 9-21~10-02에 늦게 정규화·투영한 것 |

9월 중순 재대조 발행이 실패해 남아 있던 관측을 재처리 전진(EAT-274)이 뒤늦게 다시 앉혔다. 그 사이 같은 공고는 더 늦은
관측으로 낙찰·명단까지 투영돼 있었는데, 늦게 들어온 옛 관측이 더 큰 번호를 얻어 "최신"이 됐다. 재처리는 빠진 발행을
메우는 올바른 동작이다. 틀린 것은 "append 순서가 단조롭다"는 전제다. 개찰 결과 줄(ADR 0064)이 생기면 같은 일이 성수기마다
일어난다 — 결과 줄이 10시에 앉힌 낙찰 뒤에, 8시에 시작해 몇 시간 걸린 정시 수집 회차가 낙찰 전 관측을 투영한다.

## Decision

1. **최신 개정본은 `observation_id desc, auction_revision_id desc`로 고른다.** 관측 번호는 raw를 받은 순서이고 모든 달에서
   관측 시각 순과 같았다. 같은 관측을 다시 해석한 개정본이 여럿이면 나중 해석을 쓴다(ADR 0015의 재해석).
2. **규칙은 언어마다 한곳에 둔다.** 서버는 `infrastructure/drizzle/latest-revision-order.ts`의 `latestRevisionOrder`, dataplane
   mart는 `mart/latest_revision.py`의 `latest_revision_order`다. 최신을 고르는 모든 조회가 이것을 쓰고, mart 단위 시험이 네
   빌드 SQL에 번호만으로 고르는 정렬이 남지 않았는지 본다.
3. **mart 계산 판을 `mart-r12`로 올린다.** 9월 회차 요약이 바뀌므로 재현성 규칙(AGENTS 7)상 새 build다. 서버는 활성 build를
   판과 무관하게 읽고, 과거 기록 mart는 다음 예약(07:40·12:40·16:40·20:40)이 새 판으로 다시 만든다.
4. **재처리는 고치지 않는다.** 실패한 발행을 다시 앉히는 일은 그대로 필요하다. 읽기가 관측 순서를 따르면 늦게 앉은 옛
   관측은 이력으로만 남는다.

## 기각한 대안

- **투영 때 옛 관측의 개정본을 만들지 않거나 번호를 앞당기기.** 이미 쌓인 9월 개정본 15,778개가 남고, 재처리의 이력 보존
  (AGENTS 3, "관측과 해석을 분리")을 깬다. 번호는 정체성이지 시간 축이 아니다.
- **관측 시각(`fetched_at`)으로 정렬.** 서버 역할은 ingest를 읽지 못하고(ADR 0032), core의 `observation_id`가 같은 순서를 준다.

## 결과

- 공고 상세·명단 화면이 9월 회차를 낙찰 전 상태로 보이던 일이 멈춘다. 맞춤 금액의 시장 조회는 EAT-324에서 이미 이 규칙이었다.
- 배포 첫날 과거 기록 mart가 새 판으로 한 번 전부 다시 만들어진다(빌드는 원래 전량이다).
- 분석 스크립트(`tools/m1/revalidate-2026-10/sql`)의 옛 질의는 기록으로 남기며 고치지 않는다. 새 분석은 같은 규칙을 쓴다.
