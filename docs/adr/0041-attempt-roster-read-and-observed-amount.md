# 0041 — 회차 명단 읽기와 관측 제출금액의 표시 경계

- Status: Accepted
- Date: 2026-09-08
- Supersedes: 없음. ADR 0029·0033의 관측 보존을 유지하고 공개 읽기 의미를 보완한다.
- 관련 작업: EAT-114

## 배경

최소 MVP에서 과거 회차의 참여 수를 눌러 업체·제출금액·원천 순위·낙찰과 2등 값을 확인한다.
수집 계약의 `submission.amount`는 `BID_CALC_AMT` 관측이며 제출금액으로 단정할 수 없다.
[기존 전수 조사](../evidence/normalization/2026-09-04-eat-v2-renormalization.md)는 이 값의
1e13대 자리표시자와 같은 행 `EFT_ALL_AMT`의 차이를 확인했다. 회차 5271의 dev 명단에서도
`10000000043768.00`과 `43120180.00`이 함께 보존되어 있었다.

## 결정

1. 공개 회차 명단은 선택한 `AuctionAttempt`와 revision의 core 사실을 읽는다.
   revision 미지정은 현행 공고 조회와 같은 최신 revision이며 응답에 선택 revision을 명시한다.
   지정한 revision이 다른 회차에 속하면 404다. 명단·낙찰·라벨은 한 SQL snapshot에서 읽는다.
2. 명단의 공개 `submittedAmount`는 `EFT_ALL_AMT` 관측 하나만 사용한다.
   원천 값이 없으면 null이며 `BID_CALC_AMT`, 금액×비율, 이름이나 순위에서 복원하지 않는다.
   `BID_CALC_AMT`는 별도 `sourceCalculatedAmount`로 보존한다. 계산용 값의 크기로
   무효·철회·하한 미달 여부를 새로 판정하지 않는다.
3. 이 선택은 명단의 관측 제출금액 표시 정책이다. 기존 ingestion·core DDL·mart 계산을
   바꾸거나 지급액·계약액·단가로 승격하지 않는다. 금액과 통화, 소수 정밀도를 유지한다.
4. 업체명과 상태 라벨은 그 제출의 observation에 연결된 label observation만 읽는다.
   같은 업체의 최신 이름으로 과거를 덮지 않는다. 숫자 ID로 참조하고 사업자번호는 공개 명단에서 제외한다.
5. 명단 수는 정규화된 submissions 배열과 core 행 수를 검증한다. sourceRosterSize는 다른
   원천 블록의 값이라 대체하거나 같다고 강제하지 않는다. 2048행 상한 초과·행 손실·중복 좌표·
   명단 밖 낙찰 좌표는 실패한다. 빈 배열은 원본 블록 부재와 구별할 수 없어 not-observed다.
6. 순위와 낙찰 상태는 원천 기록을 보존한다. 2등 값은 원천 RNK=2이며 유효 참가자만 재정렬한
   결과가 아니다. 비율은 예정가격 대비 원천 SAJEONG_PCT, 소수 세 자리다.

## 결과와 범위

DB 변경이나 재수집 없이 operation 계약→Nest 읽기→Web 회차 선택으로 연결한다.
전국 전체 명단을 내려주지 않고 선택한 회차 하나만 요청한다. UI는 shadcn 표와 버튼을 사용한다.
기관 다중 비교, 차트 중심 축, 명단 패널의 최종 배치는 별도 디자인 검토이며 이 ADR로 확정하지 않는다.

## 검토한 대안

- amount를 제출금액으로 표시: 자리표시자가 실제 거액 투찰로 보이므로 제외한다.
- effectiveAmount 부재 시 원천 계산값으로 대체: 관측되지 않은 제출금액을 만들어 제외한다.
- 참여 수만 표시: 실제 제출 기록을 검토할 수 없어 최소 읽기 흐름을 충족하지 못한다.
