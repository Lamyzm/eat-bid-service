# 0040 — 기관 이력의 낙찰·차순위 사정률은 관측 범위를 보존한다

- Status: Accepted
- Date: 2026-09-07
- Supersedes: [ADR 0033](0033-bid-submission-partitioning-and-supplier-core.md) §2 중 기관 이력의 낙찰·차순위 응답에 공개 `BidRate` 0~100을 유지한 정책만 대체
- 관련 작업: EAT-102

## 배경

기관 이력의 `winRate`와 `secondRate`는 예정가격을 분모로 하는 원천 사정률이다.
특히 `runner_up_rate`는 원천 `RNK=2`의 관측값이며 유효 투찰 중 두 번째라는 뜻이 아니다.
과거 표본에서 100 초과 낙찰값이 없었다는 사실은 이 두 필드의 영구 상한을 보장하지 않는다.

2026-09-07 22:54 KST에 기관 1361의 이력 조회가 HTTP 503으로 실패함을 확인했다.
DB의 `numeric(15,3)`가 보존한 차순위 관측을 어댑터의 `BidRate`가 거부하고, reader 오류가
의존성 장애로 포장되는 경로다. 응답 Zod에도 같은 제한이 있어 어댑터만 고치면 충분하지 않다.

## 결정

1. 기관 이력 `winRate`·`secondRate`만 기존 `ObservedBidRate` wire를 사용한다.
   단위는 `percentage-points`, 비음수·정수부 최대 12자리·소수 정확히 3자리다.
   100 초과를 허용하며 부동소수점 변환, 절단, 반올림, 행 제외, null 치환을 하지 않는다.
2. domain에도 같은 의미의 `ObservedBidRate`와 생성자를 둔다. DB 어댑터에서 이 타입으로 닫고
   application record와 응답 직렬화까지 유지한다. 상한이 있는 `PercentagePoints`의 하위 타입으로
   만들지 않아 하한율·점유율·bounded ratio 변환에 관측값이 들어가지 못하게 한다.
3. `floorRate`와 기존 `BidRate`, `FloorRate`, `SharePercent`의 범위는 유지한다.
   기초금액 분모의 `awardedBidRate`·`dayFloorRate`는 소수 4자리의 별도 파생값이다.
   낙찰·차순위 중 값이 없으면 기존대로 null이며, 파싱 오류를 null로 바꾸지 않는다.
4. source와 ingestion v2, core·mart DDL 및 계산은 이미 관측 범위를 보존하므로 변경하지 않는다.
   이 수정 때문에 재수집·replay·mart 재빌드를 요구하지 않는다.

## 호환성과 배포

이 변경은 응답 값 범위의 의미 확장이다. 필드·단위·소수 자릿수는 같지만, 이전 스키마를 가진
클라이언트가 100 초과 값을 거부하므로 모든 소비자에게 하위 호환이라고 주장하지 않는다.
저장소의 소비자는 공용 operation과 응답 Zod를 사용하는 Web이다. 이 변경은 `/api/v1`을 유지하고,
Web에 넓어진 응답 검증을 먼저 반영한 뒤 Server를 반영한다. 같은 릴리스라도 Argo의 서로 다른
배포가 원자적이라고 가정하지 않는다. 새 Web은 이전 Server 응답도 읽을 수 있다.

운영 반영 전 외부 독립 소비자 존재를 확인한다. 이전 검증기를 고정한 외부 소비자가 있으면
마이그레이션을 조율하기 전 Server 반영을 멈춘다. 열린 이전 Web 페이지는 새로고침으로 새 소비자를
받을 수 있으므로 배포 후 실제 기관 이력을 다시 열어 확인한다.

## 검증과 남는 경계

- 실제 PostgreSQL fixture → 어댑터 → application → HTTP에서 `101.975`·`102.297`을
  HTTP 200과 정확한 문자열로 검증한다. 원천에서 그 낙찰값을 실측했다고 주장하는 fixture는 아니다.
- 각 관측 필드의 100 초과·최대 정밀도·null을 확인하고 음수·잘못된 scale·정수부 초과를 거부한다.
  `floorRate=100.001`은 계속 거부한다.
- Web의 응답 검증과 과거 회차 표 표시까지 값을 대조한다. 차트의 표시 범위 밖 점을 숨기는
  기존 정책이나 품목 미확인 행의 비교집단 분류까지 해결했다고 주장하지 않는다.
- reader의 다른 변환 오류를 503으로 분류하는 문제는 남는다. 실제 DB 장애의 기존 503 응답을
  유지하고 오류 분류 변경은 별도 작업으로 추적한다.

## 기각한 대안

전역 `BidRate` 상한 완화는 하한율과 관측의 경계를 지운다. 100으로 절단하거나 행을 제외하면
원본 사실과 표본 수를 왜곡한다. `BaseRelativeBidRate` 재사용은 분모를 바꾼다.
DB 정밀도 확대와 재백필은 이미 저장된 값을 거부하는 현재 원인을 해결하지 못한다.
