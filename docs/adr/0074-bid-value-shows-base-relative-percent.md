# 0074 — 사장님 화면의 투찰 값은 기초금액 대비 %로 보이고 사정률을 앞세우지 않는다

- Status: Accepted
- Date: 2026-11-17
- Supersedes: [ADR 0066](0066-recommended-bid-shows-assessment-rate.md) 결정 1·2(사정률을 크게, 기초금액 대비 %와 원 금액을 작게).
  0066 결정 3(정확한 10진 계산, 지어내지 않음)과 0062의 나머지(근거와 함께 냄, 자동 투찰 금지)는 그대로다.
- 관련 작업: #228, [PDR-0011](../product/decisions/0011-work-screen-pass-values-per-business.md)
- 승인: 사용자 결정(2026-11-17, "값은 사정가가 아니라 기초가의 얼마 퍼센트로 해야 해", "아니야, 기초가 대비야")

## Context

0066은 사용자가 eaT에 금액이 아니라 소수를 넣는다는 확인에서 사정률을 크게 보였다. 2026-11-17 사용자는 그 소수가
기초금액 대비 %이고, 사정률은 화면에서 앞세울 값이 아니라고 정정했다. 한 사람이 사업장 여럿의 값을 보고 카톡·전화로
넘겨주므로 화면의 숫자가 곧 넘겨주는 숫자다. 이름 없는 소수를 셋(사정률·기초금액 대비 %·투찰률) 나란히 두면 넘겨주다
섞인다.

## Decision

1. **사장님 화면의 값은 기초금액 대비 % 하나로 크게 보인다.** "88.641%"처럼 % 기호를 붙이고, 하한율 묶음(하한 90%·88%) 머리가
   분모를 말한다. 사정률은 사장님 화면에 내지 않는다.
2. **원 단위 금액은 이 화면의 주 값이 아니다.** 금액은 공고마다 기초금액에 따라 다르고 넘겨주는 값은 %다. 확인용 금액이 필요한
   화면(공고 상세)은 이름을 붙여 작게 둔다.
3. 값은 응답의 `baseRelativeRate`를 그대로 소수 셋째 자리까지 보인다(`entities/bid-figure`의 `baseRelative`). Number로 바꾸지 않는다.

## 결과

- 응답 계약과 서버는 바뀌지 않는다. 화면만 바뀐다.
- 넣을 공고(`/work`, #228)가 먼저 따른다. 공고 상세의 추천 투찰가 칸은 아직 사정률을 크게 보이며, 그 칸을 다시 그리는 일에서 이
  결정을 따른다. 그때까지 두 화면의 큰 숫자가 다르다.
- `apps/web/AGENTS.md`의 "사정률을 앞에" 문장과 `docs/product/ui-words.md` 원칙 5를 이 결정에 맞게 고친다.
