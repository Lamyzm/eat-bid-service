# 0057 — 참가제한지역에 같은 지역 코드가 두 번 오면 한 지역이다

- Status: Accepted
- Date: 2026-09-25
- Supersedes: 없음. [ADR 0056](0056-out-of-contract-auxiliary-observation-is-unknown.md)의 "정체성과 필수 사실은
  관용하지 않는다"를 그대로 두고, 참가제한지역 목록에서 **같은 사실이 두 번 온 경우**가 그 원칙 밖이라는 것을 정한다.
- 관련 작업: EAT-274
- 승인: 사용자(2026-09-24)

## Context

eaT 상세의 `ds_areaList`는 공고의 참가제한지역 목록이다. 정규화는 같은 `PDLC_CD`가 두 번 오면
`duplicate PDLC_CD in ds_areaList`로 그 공고를 격리했고, 발행은 격리가 하나라도 있으면 창 전체를 거부한다
(부분 발행 금지, ADR 0053·0056).

2026-09-23 운영에서 이 격리 하나가 백필 창 넷(2022-09, 2024-07·08·10)의 발행을 막고 있었다. 찾은 공고는
약 59,000건인데 발행은 0건이었다. 자동 재처리(EAT-274)는 창을 제대로 골랐지만, 4시간마다 약 1시간을 돌고
같은 이유로 실패했다. 이 격리는 2026-09-04 재정규화 증거
(`docs/evidence/normalization/2026-09-04-eat-v2-renormalization.md`)에 이미 두 건으로 기록돼 있었는데 아무
결정도 없이 남아 있었다.

R2의 원본을 열어 보니 세 공고(2028251·5445496·5495384)가 모두 같은 모양이었다.

| 공고 | 겹친 코드 | 앞줄 | 뒷줄 |
|---|---|---|---|
| 2028251 | 18591 | `전남광주/화순군` | `전남광주 / 화순군` |
| 5445496 | 18583 | `전남광주/영광군` | `전남광주 / 영광군` |
| 5495384 | 18577 | `전남광주/목포시` | `전남광주 / 목포시` |

기관이 시군구 하나를 먼저 고른 뒤 "전남 전체"를 다시 골랐고, 그 전체 목록에 앞의 시군구가 한 번 더 들어 있다.
두 줄의 `PDLC_CD`·`CTPV_CD`·`SGG_CD`가 모두 같고 라벨만 `/` 앞뒤 공백이 다르다. 이 공백 차이는
census가 이미 기록한 라벨 변형과 같은 부류다(`서울 / 전체`·`서울/전체`).

## Decision

1. **같은 `PDLC_CD`가 다시 오면 같은 지역을 두 번 말한 것이다.** 먼저 온 줄을 남기고 뒷줄을 버린다.
   `eligibilityCodes`와 `eligibilityAreas`가 같은 걸러진 줄을 쓴다.
2. **판정 기준은 코드 하나다.** 지역의 정체성은 코드이고 라벨은 관측이다(AGENTS 2). `PDLC_CD`가 시도와
   시군구를 함께 담으므로(`18577` = 전남광주/목포시) 다른 칸을 더 비교해도 판정이 달라지지 않는다. 실제로
   `SGG_CD`는 전남 전체가 `185` 하나라 구분 능력이 없다.
3. **라벨을 다듬어 고르지 않는다.** 먼저 온 줄의 `PDLC_NM` 원문을 그대로 둔다. 뒷줄 라벨은 raw에 남는다.
   어느 쪽이 "올바른 표기"인지 고르는 것은 매핑 생성기의 일이지 관측의 일이 아니다(ADR 0035).
4. **합침은 조용하지 않다.** ADR 0056 결정 3의 통로(`tolerated` → 실행 로그
   `tolerated-out-of-contract-field`)로 `duplicate PDLC_CD <코드> in ds_areaList kept first row`를 남긴다.

## 왜 추측이 아닌가

AGENTS 3은 불완전하거나 모호한 값을 추측으로 메우지 말고 격리하라고 한다. 여기서는 메울 것이 없다. 참가제한
지역 **집합**은 합치기 전과 후가 같다. 격리가 지키려는 것은 "우리가 모르는 사실을 만들지 않는다"인데, 두 줄이
같은 코드를 말할 때 합쳐서 새로 생기는 사실은 없다. 반대로 코드가 다르면 합치지 않는다. 그건 서로 다른
지역이다.

## Consequences

- 중복이 없는 공고의 canonical 바이트는 그대로다. 봉인 digest 시험(`test_eat_normalize_v2.py`)이 지킨다.
  그래서 parser version을 올리지 않는다. 이전에 격리되던 입력만 새로 정규화된다.
- 배포 뒤 자동 재처리가 막힌 창 넷을 차례로 발행할 수 있다.
- 같은 부류(한 줄의 중복)가 다른 dataset에서 나오면 이 ADR을 근거로 쓰지 않는다. 그 dataset에서 중복이
  같은 사실의 반복인지, 서로 다른 두 사실인지를 먼저 원본으로 확인한다.

## Rejected alternatives

- **격리를 유지하고 창을 포기한다** — 공고 세 건 때문에 약 59,000건을 버린다.
- **부분 발행을 허용한다** — ADR 0056이 이미 기각했다. 이 경우는 부분 발행 없이도 풀린다.
- **라벨 공백을 정규화해 같은지 확인한 뒤에만 합친다** — 라벨은 정체성이 아니다. 라벨이 달라도 코드가 같으면
  같은 지역이고, 라벨 비교를 판정에 넣으면 이름이 정체성 역할을 하게 된다.
