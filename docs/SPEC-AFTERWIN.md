# 스펙 초안 — "낙찰 후" 구간: 납품 달력 + 월 정산 (critic 작성·자기 심사 포함)

작성: critic (2026-08-27). 상태: **초안 — 리더 승인 전 구현 금지.**

## 0. 데이터 판정 (실측)

**납품기간은 이미 우리 손에 있다 — 재크롤 불필요.**
원시 아카이브(F:/Project/eat-bid/data/raw, 102,010개 XML)에 아래 필드가 실려 있는데
normalize.py가 버리고 있었다. 표본 실측(bid 5782007, 김제동초 9월 육류):

| 필드 | 값(표본) | 의미 |
|---|---|---|
| DLVRY_STRT_DT / DLVRY_END_DT | 20260901 / 20260930 | **납품 기간** |
| MEAL_STRT_DT / MEAL_END_DT | 20260904 / 20260930 | 급식 기간 |
| DLVRY_TIME | (있음) | 납품 시각 |

→ 구현 전제: normalize에 4필드 추가 + **raw 재파싱 배치**(크롤 아님, 로컬 파일 재처리)로
레이크 소급. 이 배치는 data 담당, 처리량 10만 파일·로컬 IO라 1~2시간급.

폴백(재파싱 전 임시): 공고명에서 "N월" 파싱(표본상 공고명 대부분 "2026년 9월 …" 형식) +
없으면 개찰월+1. 단, 정식 구현은 반드시 실필드 기준.

## 1. 스펙 — 화면 1장: [나] > 납품 (가칭)

**답하는 질문**: "이번 달 내가 뭘 어디에 납품하고, 얼마를 버는가."
**히어로 숫자**: 이번 달 납품 계약액 합계 (예: "9월 납품 12건 · 2,340만원").

구성 (위→아래):
1. **월 스트립**: 최근 3개월+다음 2개월 탭. 각 탭에 건수·계약액 합.
2. **납품 달력(핵심)**: 월 그리드. 각 낙찰 건을 납품기간 막대로 표시
   (학교명·품목, 클릭=②/분석판). 오늘 세로선. 겹침 = 그날 동시 납품 학교 수.
3. **이번 달 정산 표**: 학교 / 품목 / 납품기간 / 계약액(기초×내 투찰률) / 개찰일.
   합계 행. CSV 저장.
4. **다음 달 예고 줄**: "다음 달 납품 확정 N건 · M원 — 공고 중 P건이 다음 달 물량".

데이터: firm_bids(won=1, 내 사업자) × 납품기간 필드. 계약액 = base_price × bid_rate/100
(실계약액과 다를 수 있음 — "투찰가 기준" 각주 필수, 헌법의 사실 원칙).

무료/유료: 유료 (결정 도구가 아니라 **매일 여는 운영 도구** — 지속결제 엔진의 핵심 후보).

## 2. 자기 적대 심사

**Q1. 과잉인가?** 아니다 — 단, 조건부. 달력 UI는 화려하지만 아버지 페르소나는 표를 읽는다.
**판정: 3번(정산 표)이 본체, 2번(달력)은 보조.** 표 먼저 완성하고 달력은 그 다음. 초안의
우선순위를 이렇게 뒤집을 것.

**Q2. 매일 열 이유가 진짜 되나?** 절반만 참. 납품 "일정" 자체는 사장이 이미 안다(자기가 딴
계약이다). 매일 여는 진짜 이유는 **겹침과 누락** — "다음 주 화요일 3개 학교 동시 납품",
"9월 납품인데 아직 안 끝난 공고". 즉 가치는 달력의 그림이 아니라 **충돌·임박 알림**에 있다.
알림 v2(마감·개찰)와 묶일 때 완성됨. 단독으로도 월 정산 합계는 G2 데모에서 "내 장부"
효과가 큼 — 유지.

**Q3. 데이터가 받쳐주나?** 위 실측으로 **예** — 유일한 리스크: 필드 공백률 미측정(표본 1건).
data가 재파싱 때 공백률을 보고할 것. 공백률 20% 초과 시 공고명 월 파싱 폴백 병행.

**헌법 심사**: 위반 없음 — 전부 확정 사실(낙찰·기간·투찰가). 단 "계약액"이라는 단어는
실계약금액으로 오독될 수 있으니 화면에 "투찰가 기준" 각주 의무.

**게이트 심사**: G1(아버지 사용) 검증에 이 화면이 실질 기여 — 투찰 없는 날에도 열 이유를
만들므로 **G1 지원 기능으로 우선순위 상향** 타당. 단, cloudflared(접속)보다 앞설 이유는 없음.
