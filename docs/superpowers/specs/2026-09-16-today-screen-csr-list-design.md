# 오늘 화면 목록 설계 — CSR 전환·페이지네이션·검색

`2026-09-16-eat-code-vocabulary-design.md`(어휘 층)의 3층이다. 어휘가 서야 필터가 서고, 필터가 서야
목록 크기가 정해진다. 이 문서는 **정해진 크기를 어떻게 보여 줄지**를 다룬다.

## 1. 결정 요약

목록을 **서버 렌더 전량**에서 **CSR + 페이지네이션 + 검색**으로 옮긴다.

```text
지금   RSC가 행을 HTML로 그려 내려보냄       행당 6.0 KB (gzip 950 bytes)
       45행에 445 KB · 상한 200 · 더보기 없음

이후   목록 전용 경량 계약을 클라이언트가 조회  행당 1.1 KB (gzip 28~85 bytes)
       한 판 N행 · 페이지 번호 · 검색으로 건너뜀
```

## 2. 왜 바꾸나 — 전제가 실측으로 깨졌다

지금 구조는 **"조건에 맞는 열린 공고를 전부 한 판에 보여 준다"**는 전제 위에 있다. 2026-09-16 실측이
그 전제를 깼다.

성수기(2026-02-20 09:00) 한 시점에 열려 있던 공고다.

| 보는 범위 | 열린 공고 |
| --- | --- |
| 전국 | 13,297 |
| 전남광주(최대 시도) | 2,240 |
| 서울 | 1,752 |
| 시도 + 품목 하나 + 품목 미상 | 약 1,230 |
| 김해시 + 축산(사용자 실제 조건) | **62** |
| 생활권 시도 둘셋(서울+경기+강원) | 약 3,900 |

**뷰가 감당해야 할 크기는 2,000~5,000행이다.** 상위 사업자 15곳이 전부 시도 1~3개에 집중하며
(실측), 전국을 보는 사업자는 없다.

### 지금 구조로는 불가능하다

| 행 수 | 지금(RSC) HTML | gzip |
| --- | --- | --- |
| 45 | 445 KB | 44 KB |
| 2,000 | 12 MB | 1.9 MB |
| 5,000 | 30 MB | 4.8 MB |

RSC는 같은 데이터를 **두 번** 싣는다 — 마크업으로 한 번(행당 1.8 KB), hydration용 Flight로 한 번
(행당 4.2 KB). 45행 페이지에서 `<script>`가 전체의 62%다.

### CSR이면 사라진다

| | 행당(gzip) | 2,000행 | 5,000행 |
| --- | --- | --- | --- |
| 지금 모양 JSON | 85 bytes | 167 KB | 417 KB |
| **목록 전용 경량 행** | **28 bytes** | **55 KB** | **137 KB** |

**5,000행 CSR(137 KB)이 지금 45행 RSC(445 KB)보다 3배 가볍다.**

## 3. 목록 전용 경량 계약

지금 `OpenAuctionListV1Response`의 행 1,142 bytes가 어디로 가는지 실측했다.

| 필드 | 행당 | 비중 | 목록이 쓰나 |
| --- | --- | --- | --- |
| `orgSummary` | 290 | 25% | `lastRound`가 그중 73% — **목록에선 안 쓴다** |
| `eligibilityAreas` | 204 | 17% | **안 쓴다**(제한지역은 사용자 결정으로 뒤로 미룸) |
| `region` | 189 | 16% | 코드·이름을 네 필드씩 두 번 |
| `organization` | 72 | 6% | 쓴다 |
| `floorRate`·`baseAmount` | 85 | 6% | 쓴다 |

**목록이 쓰지 않는 것이 절반을 넘는다.** 그래서 계약을 가른다.

- **목록 계약**: 행을 그리는 데 필요한 것만. 무거운 파생물(최근 회차·제한지역 명단)을 싣지 않는다.
- **상세 계약**: 행을 열었을 때. 지금 것을 그대로 쓴다.

한 계약이 두 화면을 겸하면 가벼운 쪽이 무거운 쪽의 비용을 낸다. 나누는 기준은 **행을 그리는가**다.

## 4. 페이지네이션 — 5,000행을 한 번에 받지 않는다

받을 수는 있다(137 KB). **그러나 사람이 못 본다.** 한 번에 받는 것은 "닿을 수 있음"을 주지만
"다 봤음"을 주지 않는다.

| | 끝이 보이나 | 한 판이 가벼운가 | 62행일 때 |
| --- | --- | --- | --- |
| 전량 + 가상 스크롤 | 스크롤바로 | 첫 응답이 전체 | 한 판 |
| 무한 스크롤 | **❌ 없음** | ✅ | 한 판 |
| **페이지네이션** | **✅ `9쪽 중 1쪽`** | **✅** | **1쪽뿐이라 안 보임** |

**페이지네이션으로 간다.** 아침에 오늘 낼 것을 고르는 자리라 **다 봤는지를 알아야 한다.** 무한
스크롤은 그 앎을 없애고, 전량 전송은 첫 화면을 느리게 하면서 아무도 안 보는 행까지 파싱한다.

62행인 사용자에게는 페이지가 하나뿐이라 페이지네이션이 **보이지 않는다.** 크기가 커질 때만 나타난다.

## 5. 검색 — 상한 밖으로 가는 길

페이지를 아홉 번 넘기는 것보다 학교 이름을 치는 것이 빠르다. 그리고 검색은 **서버로 보낸다.**

클라이언트 필터는 이미 받은 판 안에서만 찾는다. 그러면 "그 공고가 없다"와 "이 판에 없다"를 화면이
구분하지 못하고 둘 다 빈 결과가 된다. 서버로 보내면 조건 전체에서 찾고 그 결과가 곧 목록이 된다.

찾는 대상 둘이다.

| 대상 | 어디 있나 | 지금 가능한가 |
| --- | --- | --- |
| 기관(학교) 이름 | `mart.open_auction_snapshot.organization_label` | ✅ |
| 공고 제목 | `core.auction_revision.title` | ❌ **mart에 없다 — 실어야 한다** |

제목이 필요한 이유는 어휘 문서 §4.6에 있다. 품목이 원천에 없는 공고도 **제목에는 품목이 적혀 있고**,
eaT 사용자들도 `공고건명`으로 찾는다. 품목 미상 24,970건 중 축산 단서가 있는 제목이 5,612건이다.

### 공고는 엿새 열려 있고 마감만 아침이다

`/today`라는 이름 때문에 하루짜리 화면으로 읽기 쉬운데, 실측은 다르다(89,576 revision).

| 게시 → 마감 | |
| --- | --- |
| 중앙 | **6.4일** |
| p10 / p90 | 4.4일 / 9.5일 |
| 닷새 이상 | **79.5%** |
| 하루 미만 | 0.8% |

마감 시각이 09:00·10:00에 몰리는 것은 **오늘 마감되는 것**의 성질이지 오늘 처음 보는 것이 아니다.
그 공고들은 엿새 전부터 `진행중`에 있었다. 그래서 화면의 작업 집합은 `진행중`이고, `오늘 마감`은
그 안에서 오늘 닫히는 선이며, 달력은 앞으로 닫힐 날을 가리킨다. 사용자는 급하게 훑는 것이 아니라
**엿새 동안 보던 것을 마감이 닥친 날 놓치지 않는 것**이고, 한 건을 분석할 시간이 있다.

같은 이유로 `closes_at > asOf`로 마감 1초 뒤에 행을 지우는 지금 조회는 틀렸다. 엿새를 봐 온 건이
개찰(마감 한 시간 뒤)도 보기 전에 사라진다.

## 6. 화면 뼈대

설계 기준은 PC 1920×1080이다(사용자 실측). 좁은 폭 대응은 후순위다.

```text
┌ 셸 ┬ 왼쪽 기둥(고정·안 접힘) ┬ 본문 ───────────────────────┐
│    │ 조합                    │ ▒ 스티키 ▒                  │
│오늘│  오늘 내 지역     62    │  진행중 62 · 오늘 마감 3    │
│지난│  내 지역 전부    252    │  [검색: 학교·공고]          │
│    │  참여 0곳          9    │  마감 기관 하한 금액 참여   │
│ 나 │  품목 미상 포함   17    │ ─────────────────────────── │
│    │ 내 조합          2/5    │  9월 16일 수요일 · 사흘 뒤  │
│    │  + 이 조건 저장         │   09:00 진영대창초 90% …    │
│    │                         │   …                         │
│    │ ── 조건 ──              │  ◀ 1 2 3 … 9 ▶              │
│    │ 지역  경남 ▾ ☑김해시    │                             │
│    │ 품목  ☑육류 ☑가금류     │                             │
│    │ 금액  [16,000,000] 이상 │                             │
│    │ [기본값으로]            │                             │
└────┴─────────────────────────┴─────────────────────────────┘
```

- **왼쪽 기둥에 조건을 둔다.** `screen-system` §6.4.1이 금지하는 것은 필터를 **숨기는** 것이고, 늘
  펼쳐진 기둥은 숨기지 않는다. 접히는 기둥으로 만들면 그때는 위반이다.
- **상단을 스티키로 둔다.** 한 판이 커지면 스크롤 중에 탭·검색·표 머리가 사라져 자기가 무엇을 보고
  있는지 잃는다.
- **표가 client component가 된다.** `apps/web/AGENTS.md`가 "브라우저 상태나 상호작용이 필요할 때만
  `'use client'`"라고 했고, 이 표는 필터·검색·페이지 이동이 붙는 상호작용 화면이라 조건에 든다.

### 행에서 빼는 것과 넣는 것

사용자 결정이다.

| | 판정 | 이유 |
| --- | --- | --- |
| `하한 82.995`(축 줄) · `11건`(축 줄 오른쪽) | **뺀다** | |
| `N건 중`(묶음 머리 오른쪽) · 순번 열 | **뺀다** | |
| `보통 190 · 19회` | **`보통 190곳`으로 줄인다** | 표본 수는 우리만 가진 재료라 값은 남기고 표현만 줄인다 |
| **하한율 열** | **넣는다** | 404/404 관측되고 5종뿐이다. eaT는 상세에 들어가야 보여 준다 |
| **제목** | **넣는다** | 품목이 미상인 공고에서 유일한 단서다 |

품목으로 이미 걸러 놓으면 품목 열은 같은 값이 반복되어 정보량이 낮다. **기관이 행의 주인공**이고
제목은 그 아래 둔다.

### 화면이 말하지 않는 것

품목이 원천 관측인지 제목 추정인지 **화면에 적지 않는다**(사용자 결정). `apps/web/AGENTS.md`가
"내부 결정과 구현 사정을 설명하지 않는다"고 한 그대로다. 대신 **제목이 행에 있으므로 근거가 이미
화면에 있다** — `축산물A(소,돼지)`가 보이면 왜 육류인지 따로 설명할 필요가 없다.

## 7. 범위 밖

- 어휘(지역 이름·품목 코드·제목 추정). 앞선 문서가 소유한다.
- 참가제한지역. 사용자 결정으로 뒤로 미뤘다.
- 무한 스크롤·가상 스크롤. 페이지네이션으로 간다.
- 좁은 폭(모바일) 최적화. PC가 기준이다.
- 정렬 축 추가. 지금처럼 마감 임박 순 하나로 시작한다.

## 8. 검증 기준

- 목록 응답이 상세 전용 필드를 싣지 않는다. 행당 gzip 바이트를 측정해 기록한다.
- 5,000행 조건에서 한 판 응답 크기와 첫 화면 시간을 측정해 기록한다.
- 페이지를 옮겨도 조건이 유지되고, 조건을 바꾸면 첫 쪽으로 돌아간다.
- 62행 조건에서 페이지네이션이 보이지 않는다.
- 검색이 서버로 가고, 상한 밖 행이 검색으로 닿는다.
- 결과가 잘렸을 때 화면이 전체 수와 보이는 수를 함께 적는다.
- 1920·1440에서 표가 문서를 가로로 밀지 않는다.
- 테스트명 한국어. `pnpm architecture:check -- --changed` 통과.
