# EAT-214 차트 전체보기 구현·대조 계획

- 작업: https://linear.app/eatbid/issue/EAT-214
- 기준 커밋: `baf81ba8f96674fc8c5bfb3a845f779baf952eb0`
- 작업 브랜치: `eat-214-chart-fullscreen`
- 범위: 공고 상세의 흐름 차트와 분포 히트맵 전체보기, 공통 셸의 전체보기 공간 배분.
- 소유 경로: 상세 `_widgets`, 분포 UI, `shared/ui/chart-fullscreen-frame.tsx`,
  `shell/layout/workspace-layout.css`, 관련 Web 테스트와 이 문서. 기존 동작 설명과 충돌을 없애기 위해
  `screen-system.md`, `workspace-dock-implementation.md`, `notice-design-fidelity.md`도 같은 변경에서 갱신한다.

## 요구와 시안의 대조 기준

매 작업마다 명세, 시안, 구현 화면을 대조하고 차이를 기록한다. 기준 시안은
`detail-exploration/g-methods/?revision=region-comparison-2`다. 토스 테마, 평평한 지면,
조건과 범례를 차트 가까이 두는 구성을 유지한다. 기존 시안의 확대는 탐색·공고 헤더를 남기고
차트 높이만 늘린다. 이 동작은 사용자가 이후 명시한 아래 전체보기 요구로 대체한다.

1. 모든 차트는 전체보기에서 브라우저 콘텐츠 뷰포트 전체를 쓴다. 최대 폭, 바깥 여백,
   공통 탐색 헤더·사이드바가 남지 않는다. OS 전체화면 진입은 요구하지 않는다.
2. 차트는 작은 조작부를 제외한 가로·세로 공간을 실제로 다시 계산해 채운다.
3. 흐름의 같은 캔버스, 필터, 축 확대, 범례, 선택 회차, 자료 기준을 유지한다.
4. 전체보기 안에서도 현재 공고 정보와 선택한 과거 회차 기록을 구분해 열 수 있다.
5. 닫기·Escape·뒤로 가기, 원래 초점·스크롤 복귀를 확인한다. 메뉴나 상세가 열린 때에는
   해당 레이어가 먼저 Escape를 처리한다. 숨긴 배경은 스크롤·키보드 탐색 대상이 아니다.
6. 휴대폰에서도 진입할 수 있고 창 크기·회전 변화에 대응한다.

## 구현 경계

- 흐름은 DOM 위치와 URL 상태를 유지한다. 공통 셸은 업무 이름 대신 범용
  `data-workspace-fullscreen` 신호만 읽어 탐색 공간을 본문에 돌려준다.
- 분포는 기존 Base UI Dialog의 초점·배경 차단을 재사용하고 뷰포트 크기와 히트맵 높이를 바꾼다.
- 새 DTO, 데이터 재집계, 기관 대 지역 분석 기능 추가는 다른 MVP 이슈가 소유한다.
- 과거 회차 표의 기존 확대 동작은 이 차트 작업의 대상이 아니다.

## 검증 순서와 증거

1. 기존 1920px 흐름 확대 검사 통과를 확인했다. 실행에는 domain/contracts 사전 빌드가 필요하다.
2. 뷰포트 충족 검사를 먼저 추가해 기존 구현 실패를 확인한다.
3. 같은 계약 fixture 공고 `5796468`, 같은 테마·필터·화면 크기로 전후를 비교한다.
4. 1920/1440/1280/1024/640/375px, 좁고 낮은 회전 화면, 창 크기 변경을 검사한다.
5. 시안은 다른 공고·가상 표본이므로 구성·토큰만 비교한다. 시안의 수치나 점 위치가
   실제 fixture와 같다고 판정하지 않는다.
6. 관련 단위·브라우저 검사와 Web 타입·lint·변경 범위 gate를 통과한 뒤 커밋한다.
   저장소 `pnpm review:ai`와 PR 절차를 따르고 실행 결과·캡처 위치를 아래에 남긴다.

### 실행 결과

- Web 단위 검사: source 519건 + fixture 5건, 실패 0건.
- 브라우저: `chart-fullscreen.spec.ts`, `flow-focus.spec.ts`, `decision-screen.spec.ts` 합계 48건 통과.
  토스 테마에서 전체 뷰포트와 375px→768×375 회전, 축·범례·뒤로 가기 보존을 포함한다.
- Web `typecheck`, `lint`, `build` 통과. lint에는 기존 다른 경로의 경고가 있고 빌드에는
  기존 Google Sans Flex fallback 경고가 있다. 오류로 세지 않으며 경고 없음으로 보고하지 않는다.
- 변경 범위 `architecture:check -- --changed` 12개 통과, 최종 문서의 `quality:check` 3개 통과.
- 실행 중인 확인용 Web: `http://localhost:3215/auctions/89?view=흐름`, 기존 개발 API `localhost:4400` 사용.
  자동 검사의 계약 fixture 포트는 3214/4514이며 실제 개발 자료 검증과 구분한다.
- 실제 개발 공고 89: 인천영종초등학교, 조회 표본 15회·표시 13회. 같은 공고·토스 테마·1440×900에서
  일반/전체보기, 375×812 전체보기를 직접 캡처하고 열어 확인했다.
- 로컬 캡처는 시안 서버의 `detail-exploration/linear-registration/`에 보관한다.

### 한계와 후속 범위

- 실제 개발 API의 오늘 목록 응답은 현재 Web의 `meta.region/item` 계약과 달라 로딩 실패를 확인했다.
  공고 상세 89는 정상 조회된다. 별도 writer가 사용하는 기존 API/오늘 목록은 이 변경에서 수정하지 않았다.
- 개발 API의 로그인 origin은 기존 `localhost:3000`을 사용한다. 문서의 개발 계정으로 그 주소에서
  로그인한 뒤 같은 localhost 쿠키로 3215에 접근했다. 인증 우회나 서버 설정 변경은 하지 않았다.
- 브라우저 모바일 뷰포트·동적 높이 변경은 검사했으며 실제 휴대폰 Safari 장치 검증은 하지 않았다.
- 기관 대 지역 데이터, 신규 분포 차트와 집계 API는 EAT-216/EAT-217 등 후속 이슈다.
