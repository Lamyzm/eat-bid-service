# 무엇을 키로 삼을 것인가

이번 주 A급 사고 넷이 전부 하나의 뿌리에서 나왔다.

---

## K1. **정체성 칸에 시간 의존 값을 넣지 않는다**

> 우리는 **"무엇인가"(정체성)**를 **"무엇이라 불리는가"(표시명)**로 저장해왔다.

이름은 바뀐다. 코드는 안 바뀐다. **이름을 키에 넣으면 개명이 곧 정체성 변경이 된다.**

**치른 값 — 넷:**

| 사고 | 키 | 결과 |
|---|---|---|
| **A-8 분리** | `schools.id = {sigungu}\|{institution}` | 인천 2026-07 자치구 개편으로 **학교 4곳이 두 행으로 쪼개졌다.** 한 학교 이력이 5+5로 반토막 |
| **A-9 병합** | 〃 (`clean_inst` 괄호 절단) | `남산초등학교(진해)`와 `(창원)`이 **한 학교로 합쳐졌다.** 존재하지 않는 학교가 두 학교 이력을 섞어 갖는다 |
| **S-1 시장 지도** | `market_regions` PK `(sigungu, category)` | `남구`가 대구·부산·울산·인천 **넷인데 품목당 1행만 남았다.** 공산은 대구, 축산은 울산, 농산은 인천 — **어느 도시가 살아남는지는 insert 순서가 정했다** |
| **사고 6 (이전)** | `user_mark` PK `(userId, bidNo)` | 사업자 축을 못 담아 **사용자 입력의 46%가 저장조차 안 됐다** |

**넷 다 같은 모양이다: 키가 표현하지 못하는 축(시간·지역·사업자)이 실제로 존재했다.**

### 판정이 갈리는 지점 — "과거를 현재 이름으로 옮기면 왜곡 아닌가"

**아니다. 그 딜레마는 이름을 저장하기 때문에 생기고, 코드를 저장하면 사라진다.**

검단중학교 실측:
```
202606  PURR_CD=144302  SIGUNGU_CD=722  주소=서구
202608  PURR_CD=144302  SIGUNGU_CD=722  주소=검단구
```
**`PURR_CD`도 `SIGUNGU_CD`도 안 바뀌었다. `DOG_ADDR` 텍스트만 바뀌었다.** 코드 722는 한 번도 다른 지역을 가리킨 적이 없고 **그 지역의 이름이 개명됐을 뿐**이다.

그러면 화면이 왜곡 없이 둘 다 말한다:
> 과거 회차 → "722 지역 · **당시 서구**"  ·  현재 → "722 지역 · **현재 검단구**"

**정체성은 코드로, 표시명은 `(코드, 시점)` 조회로.** 헌법("사실을 말한다")과 사용성이 부딪히는 것처럼 보인 이유는 **정체성 칸에 시간 의존 값을 넣었기 때문**이다.

## K2. 사용자가 아는 값을 키에서 빼지 않는다

**치른 값:** `SHIPPER_CD`가 `biz_no`보다 세분화됐다는 걸 확인하고 키 전환을 기각했다(→ `reading-the-source.md` R2). 근거가 하나 더 있었다:

> **사장은 자기를 사업자번호로 안다.** 그가 화면에서 확인하고, 입력하고, 남에게 말하는 값이 그것이다.

정체성 키를 내부 코드로 바꿔도 **사용자가 아는 값은 조회 가능해야 하고, 화면에 남아야 한다.**

## K3. 키를 바꿀 땐 **옛 키를 별칭으로 살린다**

`school_id`가 분석판 URL에 들어간다(`/dashboard/analysis/김해시|임호초등학교`). 키를 바꾸면 북마크·공유 링크가 죽는다.

**처방(X20): 컬럼 추가 → 정본 선정 → 별칭 테이블 → 리다이렉트.** 이 순서면 **URL이 죽는 범위가 0**이다. 리다이렉트를 빼면 **id 5개가 죽는다**(A-8 2 + A-9 3).

**관련 라이브 결함 — 폴백이 별칭 노릇을 하면 안 된다:**
```ts
// analysis/[id]/page.tsx — id 가 안 맞으면 검색 결과 첫 학교로 조용히 대체
const school = schools.find(s => s.id === decoded) ?? schools[0] ?? null;
```
**URL은 A인데 화면은 B다. 오류도 없다.** A-8·A-9·A-11이 전부 이 폴백으로 흘러든다. **404가 훨씬 낫다.**

## K4. 문자열이 **맞는** 자리도 있다 — 전부 코드로 바꾸지 마라

가르는 게 이 규칙의 절반이다.

| 문자열이 맞다 | 이유 |
|---|---|
| `eatbid.lens`·`auctionTab`·`kpiOpen` | **화면 상태.** 정체성이 아니다 |
| `LENSES`·`PERIODS`·`TABS`·`STATUS` | **화면 구조** |
| `lake.py`의 `year=`/`month=` 파티션 · `part-{ns:020d}-{uuid}` | **저장 레이아웃.** 20자리 제로패딩이 *정렬 = 쓰기순서*를 만드는 의도된 설계 |
| `archive.py` 샤드(`bid_no[1:5]` · md5 2자리) | **파일 분산**, 정체성 아님 |
| 외부 API 요청 필드명(`P_CTPV_CD` 등) | 우리가 못 정한다 |
| **품목명**(`축산`·`수산`…) | **대응 코드가 없다**(R1). `category.ts` 어휘 SSOT가 유일한 답 |

## K5. 표시명을 로직에 쓰지 않는다

**치른 값:** `app.module.ts`가 `'낙찰'|'하한미달'|'밀림'` 한글 라벨을 만들고 **바로 다음 줄에서 그 문자열을 되읽어** `valid`·`runnerUp`을 계산한다. 웹도 8곳에서 그 문자열을 비교한다.

**COPY-GUIDE가 문구를 바꾸면 계산이 바뀐다.** 표시명이 로직이 된 자리다.

→ 내부는 enum, 한글은 **렌더 시점에만** 붙인다.
