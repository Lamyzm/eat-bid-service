# 우리가 세운 기준이 원본에 있는 것을 없앤다

**이 프로젝트에서 가장 많이 반복된 사고다. 한 주에 여섯 번 났다.**
전부 형태가 같다 — **원본은 값을 줬는데, 우리가 세운 기준이 그중 일부를 잘라냈고,
잘린 것은 아무 소리도 내지 않았다.**

## 여섯 번

| 우리가 세운 기준 | 잘라낸 것 | 어떻게 드러났나 |
|---|---|---|
| `REGION_CODES = range(1, 18)` | **시도코드 18 = 58,459건** 을 한 번도 수집 안 함 | 주석의 `5광주 13전남`(없는 코드)을 믿었다. 우연히 `config.py` 를 열어보고 |
| `_SIDO_MAP["전북특별자치도"] = "전북특별자치도"` | 한 도가 두 행으로 갈림 | 지도에 같은 도가 두 번 |
| `len(opened) < 5` 학교 제외 | **학교 2,152곳** | 학교 수를 세어보고 |
| `n >= 20` 지역 표본 문턱 | **신설·소규모 지역 10곳**(영종구 n=5 …) | 드롭다운에 영종구가 없다는 신고 |
| `P_PRGRS_STAT_CD = 007` 만 수집 | **공고의 7.1%**(유찰·취소·저장중) | 상세 응답의 `ds_bidHistory` 에 흔적이 남아 있었다 |
| 손으로 만든 좌표표 136키 | **시군구 60곳**이 지도에서 사라짐 | 버블 수를 세어보고 |

**여섯 중 어느 것도 예외나 경고를 내지 않았다.** 전부 조용히 통과했고,
**누가 숫자를 세어보기 전까지 아무도 몰랐다.**

## 왜 자꾸 나는가

**기준을 세울 때는 항상 그럴듯한 이유가 있다.**

- `n >= 20` → *"표본이 적으면 통계가 의미 없다"* — 맞는 말이다
- `len(opened) < 5` → *"회차가 너무 적으면 보여줄 게 없다"* — 맞는 말이다
- `range(1, 18)` → *"시도는 17개다"* — **그때는 맞았다**

**문제는 이유가 틀린 게 아니라, 기준이 원본을 대신 판정한다는 것이다.**
원본은 영종구를 줬다. 우리가 "너무 적다"고 판정해서 없앴다.
**사장이 영종구에서 입찰하는데 우리 화면에 영종구가 없다.**

그리고 **그 판정은 미래를 모른다.** `range(1, 18)` 은 2026-07 에 틀린 값이 됐고,
`n >= 20` 은 **새로 생긴 지역을 영원히 못 통과하게** 만든다 — 신설 지역은 정의상 회차가 적다.
**우리 기준이 정확히 우리가 가장 알고 싶은 것을 거른다.**

## 규칙

### T1 — 자르지 말고 세어서 같이 내려보내라

문턱을 **낮추는 게** 아니라 **없애는 게** 처방이다.

```ts
// ✗  회차가 적은 지역을 없앤다
.having(sql`count(*) >= 20`)

// ✓  회차가 적다는 사실을 같이 내려보낸다
select region, count(*) as n ... // 화면이 n 을 보고 정한다
```

> **회차가 적은 것은 사실이고, 사실을 숨기는 대신 `n` 을 함께 내려보낸다.**

**판정을 화면 끝으로 미뤄라.** 데이터 층에서 자르면 **위층은 그게 없었다는 것조차 모른다.**

### T2 — 상수로 범위를 적지 마라. 데이터에 물어라

```python
# ✗  17 은 우리가 아는 숫자다
for code in range(1, 18):

# ✓  원본이 주는 목록이 곧 범위다
for code in sorted(config.REGION_CODES.values(), key=int):
```

**행정구역·품목·상태값은 전부 바뀐다.** 우리가 아는 개수를 코드에 적는 순간
**개편이 일어난 날 조용히 틀린 값이 된다.** 개편은 예고 없이 오지 않지만
**우리가 그날 그 상수를 기억하고 있을 리 없다.**

### T3 — 기준을 넣을 거면, 그 기준이 **뭘 잘랐는지 세어서 로그로 남겨라**

정말로 잘라야 할 때가 있다. 그럼 **잘린 양이 보여야 한다.**

```python
skipped = [s for s in schools if len(s.opened) < 5]
if skipped:
    print(f"  !! 회차 5회 미만으로 제외: {len(skipped)}곳")
```

**이 한 줄이 있었으면 2,152 를 첫날 봤다.** `failing-loudly.md` 의 같은 처방이다 —
**조용한 제외는 조용한 실패다.**

## 검사 — 새 기준을 넣기 전에 물어라

1. **이 기준이 지금 몇 개를 자르나?** 세어봤나, 아니면 "얼마 안 될 것"이라 짐작했나
2. **새로 생긴 것이 이 기준을 통과할 수 있나?** 신설 지역·신규 업체·첫 회차 학교가
   **정의상 통과 못 하는 기준**이면 그건 기준이 아니라 **미래를 막는 벽**이다
3. **자른 것이 화면 어딘가에서 세어지나?** 안 세어지면 **없는 것과 구분이 안 된다**
4. **이 숫자(17, 20, 5)는 어디서 왔나?** 원본이 준 것인가, 우리가 정한 것인가.
   **우리가 정한 것이면 주석에 왜 그 값인지 적어라** — 다음 사람이 못 고친다

## 이 규칙이 못 막는 것

**기준이 코드에 안 보이는 경우.** 가장 큰 누락(`P_PRGRS_STAT_CD=007`)은
**API 요청 파라미터**였다. 코드를 아무리 읽어도 "우리가 뭘 안 받고 있는지"는 안 보인다 —
**받은 것만 보이기 때문이다.**

그래서 이 규칙만으로는 부족하고 **`reading-the-source.md` 의 전수 census 가 짝**이다.
**우리가 가진 것을 세는 것으로는 없는 것을 못 찾는다. 원본이 주는 전체를 따로 세야 한다.**
