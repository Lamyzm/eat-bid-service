# 실패와 사실 표기

이 팀의 사고는 대부분 "값이 틀렸다"가 아니라 **"값이 조용히 사라졌다"**였다.

---

## F1. 조용한 실패를 만들지 않는다

**실패는 실패로 끝나야 한다.** 기본값·빈 배열·`true`로 때우면 그 자리가 사고 현장이 된다.

**치른 값 — 여섯:**

| 자리 | 무엇을 했나 | 결과 |
|---|---|---|
| `load_postgres.py` | `except: oj = []` 후 **무조건** `delete from open_auctions` | **매일 03시 무인으로 열린 공고 전량 삭제 후 0건 적재, 정상 종료.** 로그도 비영 종료도 없었다 |
| `app.yaml` initContainer | `psql … \|\| true` | **테이블을 전량 날린 그 파일에** 실패를 못 보게 하는 뚜껑이 덮여 있었다 |
| CronJob | `update_lake.py **;** fetch_open …` | 레이크 갱신이 실패해도 **낡은 레이크로 7개 테이블 재구축** |
| 웹 `.catch(() => {})` **24곳** | | 서버 죽음이 **"공고가 없습니다"**로 보인다. `analysis-board`의 roster 실패는 **"이 학교는 아직 참여 기록이 없습니다"**라고 **사실이 아닌 문장을 단언**한다 |
| `analysis/[id]/page.tsx` | `?? schools[0]` | **요청한 학교와 다른 학교를 그린다** |
| `session.ts` `put()` | `res.ok` 미검사 + 서버가 인증 실패를 **HTTP 200**으로 반환 | 화면은 **"✓ 저장됨"**, 다른 기기엔 값이 없다 |

**두 겹이면 한쪽만 고쳐선 안 잡힌다** — 마지막 항목이 그렇다. `res.ok`를 검사해도 서버가 200을 주면 통과한다.

### 특히: 실패가 **"적게"**로 나타나는 경우

`6d91978`이 "못 읽음"과 "0건"은 막았다. **"짧지만 유효한 JSON"은 통과한다.**
실증: 로그에 `open_auctions: 1`로 하루가 지나간 적이 있고 **아무도 아무 말을 안 했다.**
→ **위험한 건 0이 아니라 3이다.** 급감 방어가 필요하다.

## F2. **표본이 적다는 사실은 화면이 말한다. 로더가 지우지 않는다**

**치른 값 — 문턱이 9곳이었고, 그중 둘이 큰 것을 지우고 있었다:**

| 문턱 | 버리는 것 |
|---|---|
| `len(opened) < 5` | **학교 2,152곳** |
| `having count(*) >= 10` (firms) | **사업자 411곳 (7.0%)** |

그리고 **`firms`에서만 걸렀지 `firm_bids`에는 문턱이 없다.** 두 테이블이 다른 모집단을 갖고 두 엔드포인트가 각각을 읽는다:
```
/api/firms/lookup?bizNo=1038600036  → {"found":false}
/api/firms/record?bizNos=1038600036 → {"totalBids":7,"pushedOut":5,"belowFloor":2}
```
**온보딩은 "기록 없음"이라 하고, 성적 화면은 그 사업자의 7회 이력을 갖고 있다.**

로더 자신의 주석이 원칙을 이미 적어놨다:
> `load_postgres.py` — *"표본이 적은 구간도 버리지 않는다. n을 그대로 실어 보내고, **적다는 사실은 화면이 말한다**."*

**그 원칙에 전제가 붙어 있다 — 화면이 n을 말해야 한다.** 지금 대체로 지킨다(`{view.length}회 기준`, 표본 12 미만은 점 스트립). **잔여: `dense`(잘 나온 구간) 가격선이 n을 안 단다** — 개찰 1회짜리 학교 502곳에서 그 선은 회차 하나다.

### 문턱을 걷을 때의 함정

**문턱 제거가 A-8을 고치는 게 아니라 *가릴* 수 있다.** 지금은 "회차 10인데 5+5"가 문턱 바로 위라 위험 신호인데, 문턱이 없어지면 **조용히 두 행으로 남는다.**
→ **문턱 제거와 카운터를 같은 배포에 넣는다.**

## F3. 우리가 만든 값에는 **출처**를 붙인다

원본에서 온 사실과 우리가 규칙으로 만든 추정을 화면이 구별할 수 있어야 한다.

**치른 값:**
- **`무효`가 원본에 없는 판정이었다.** 우리가 만들어 단언했다
- 품목의 **62.3%가 이름 규칙산**인데 화면은 발주처 지정과 구별 없이 말했다 → `category_src`
- 자격이 **지역만 보고 판정**됐는데 화면은 "자격 충족"이라 했다 → `qualificationBasis: "region-only"`

**설계의 한 줄이 이걸 요약한다:**
> **SSOT의 단위는 값이 아니라 (값, 출처)다. 출처 없는 값은 계약 위반이다.**

**그리고 이건 "모르면 단언 금지"의 반대 방향도 막는다** — 부분문자열 자격 판정(`서구` ⊂ `달서구`)은 **모르는 걸 안다고 단언**하는 쪽이었다.
