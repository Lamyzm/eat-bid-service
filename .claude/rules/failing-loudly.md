# 실패와 사실 표기

이 팀의 사고는 대부분 "값이 틀렸다"가 아니라 **"값이 조용히 사라졌다"**였다.

---

## F1. 조용한 실패를 만들지 않는다

**실패는 실패로 끝나야 한다.** 기본값·빈 배열·`true`로 때우면 그 자리가 사고 현장이 된다.

**치른 값 — 여섯:**

| 자리 | 무엇을 했나 | 결과 |
|---|---|---|
| `load_postgres.py` | `except: oj = []` 후 **무조건** `delete from open_auctions` | **매일 03시 무인으로 열린 공고 전량 삭제 후 0건 적재, 정상 종료.** 로그도 비영 종료도 없었다 |
| `app.yaml` initContainer | `psql … \|\| true` | **테이블을 전량 날린 그 파일에** 실패를 못 보게 하는 뚜껑이 덮여 있었다 |
| CronJob | `update_lake.py **;** fetch_open …` | 레이크 갱신이 실패해도 **낡은 레이크로 7개 테이블 재구축** |
| 웹 `.catch(() => {})` **24곳** | | 서버 죽음이 **"공고가 없습니다"**로 보인다. `analysis-board`의 roster 실패는 **"이 학교는 아직 참여 기록이 없습니다"**라고 **사실이 아닌 문장을 단언**한다 |
| `analysis/[id]/page.tsx` | `?? schools[0]` | **요청한 학교와 다른 학교를 그린다** |
| `session.ts` `put()` | `res.ok` 미검사 + 서버가 인증 실패를 **HTTP 200**으로 반환 | 화면은 **"✓ 저장됨"**, 다른 기기엔 값이 없다 |

**두 겹이면 한쪽만 고쳐선 안 잡힌다** — 마지막 항목이 그렇다. `res.ok`를 검사해도 서버가 200을 주면 통과한다.

### 특히: 실패가 **"적게"**로 나타나는 경우

`6d91978`이 "못 읽음"과 "0건"은 막았다. **"짧지만 유효한 JSON"은 통과한다.**
실증: 로그에 `open_auctions: 1`로 하루가 지나간 적이 있고 **아무도 아무 말을 안 했다.**
→ **위험한 건 0이 아니라 3이다.** 급감 방어가 필요하다.

### F1-b. 시끄럽게 실패한 게 **설계라서가 아니라 운이었던** 자리

**2026-08-29.** 재파싱본이 라이브 레이크에 append 되어 `auctions.areas`가 **4필드/5필드 두 스키마로 갈렸다.** `lake.connect()`는 `union_by_name`으로 읽는데, **먼저 본 파일의 스키마로 통합한다.**

```
areas 스캔        FAIL  TypeMismatchException (STRUCT 5필드 vs 4필드)
areas.pdlc_cd     FAIL  Binder Error: Could not find key "pdlc_cd"
                        Candidate Entries: "pdlc_nm","ctpv_cd","sgg_cd"
```

**⚠ 처음에 여기 "순서가 반대였으면 조용히 NULL이었을 것"이라고 썼다. 재 보니 틀렸다.** 두 파일짜리 실험으로 순서를 뒤집어 봤다:

```
4필드 먼저  →  FAIL  TypeMismatchException
5필드 먼저  →  FAIL  TypeMismatchException   (메시지의 좌우만 바뀐다)
```

**중첩 구조체의 필드 수가 다르면 순서와 무관하게 던진다. 운이 아니라 결정적이다.** 가설을 재기 전에 규칙으로 쓸 뻔했다.

**그런데 조용한 경로는 따로 있고, 그게 더 넓다 — 최상위 컬럼이다:**

```
옛 파일: {bid_id, sigungu}          새 파일: {bid_id, sigungu, sigungu_code}
읽으면:  ('1', None) · ('2', '653')      ← 순서 무관. 예외 없음
```

`union_by_name`은 **없는 최상위 컬럼을 조용히 NULL로 채운다. 그게 설계된 동작이다.** 그리고 **우리는 이미 그걸 겪었다** — `sigungu_code`를 추가한 뒤 옛 파일 전부가 NULL이라 **A-1이 5.76%였다.** 아무 예외도 안 났고, 아무도 안 알려줬고, 리더가 화면을 보고 알아챘다.

| 레이크에 일어난 변화 | 읽을 때 | |
|---|---|---|
| 최상위 컬럼 추가·삭제·**개명** | **조용히 NULL** | 🔴 이게 위험한 쪽 |
| 중첩 구조체 필드 변화 | **예외** (순서 무관) | 시끄러워서 잡혔다 |

**추가는 정상 진화라 NULL이 맞다. 위험한 건 개명·삭제다** — 값이 그대로 있는데 이름이 바뀌면 **옛 데이터가 새 이름 아래에서 통째로 사라지고 아무 소리도 안 난다.** 컬럼이 31→32→36→56으로 네 번 늘어난 레이크에서 다음에 하나가 *바뀌면* 그렇게 된다.

**F1의 나머지 여섯과 방향이 반대다** — 저건 "있는데 안 도는" 것이고 이건 **"없는데 도는 것처럼 보이는"** 것이다. 같은 규칙의 뒷면이라 여기 둔다.

**남아 있다.** 파일을 옮겨도 `connect()`의 통합 규칙은 그대로고, `write_batch`가 append-only인 한 스키마 세대는 계속 섞인다 — **레이크에 이미 네 세대가 있다**(31·32·36·56컬럼). 다음에 컬럼이 하나 붙으면 같은 자리에 다시 선다.

**그리고 지금도 한 줄이면 깨진다:**
```sql
select * from auctions limit 1   →  FAIL   (connect() 뷰. unnest 가 아니라 그냥 투영이다)
```
로더가 무사한 건 `areas`를 안 펼쳐서가 아니라 **컬럼을 이름으로 명시해 뽑아서** `areas`가 투영에 안 들어가기 때문이다. **`select *`를 쓰는 사람이 한 명 생기면 그날 깨진다.**

**⚠ 그리고 이 실패를 확인하는 쿼리 자체에 함정이 있다.** 위가 깨지는 건 `connect()`의 뷰에 `row_number() over (…)`가 있어 `limit 1`이 전량을 읽게 만들기 때문이다. **창 함수 없이 `read_parquet(…) limit 1`을 쓰면 한 파일만 읽고 멈춰 깨진 레이크에서도 통과한다.** 실측:
```
전 파일  select * … limit 1              →  OK    ← 통과했지만 아무것도 확인 못 했다
전 파일  count(*) where len(areas)>0     →  FAIL  ← 전량을 강제하니 나온다
```
**"확인했다"가 "한 파일을 확인했다"였다.** 검증 쿼리는 **전량을 투영하도록 강제**해야 한다 — 이건 `count(*)`가 구조체를 실체화하지 않아 아무것도 증명 못 했던 것(2026-08-29, 같은 날)과 같은 실수의 다른 형태다.

> **처방 미정 — 이 줄이 잊히지 않기 위한 자리다.** 방향만 적어둔다: `connect()`가 스키마 세대를 **발견하면 말해야** 한다(통합 결과를 조용히 고르지 말고). 세대가 둘 이상이면 그 사실 자체가 출력이다.

## F2. **표본이 적다는 사실은 화면이 말한다. 로더가 지우지 않는다**

**치른 값 — 문턱이 9곳이었고, 그중 둘이 큰 것을 지우고 있었다:**

| 문턱 | 버리는 것 |
|---|---|
| `len(opened) < 5` | **학교 2,152곳** |
| `having count(*) >= 10` (firms) | **사업자 411곳 (7.0%)** |

그리고 **`firms`에서만 걸렀지 `firm_bids`에는 문턱이 없다.** 두 테이블이 다른 모집단을 갖고 두 엔드포인트가 각각을 읽는다:
```
/api/firms/lookup?bizNo=1038600036  → {"found":false}
/api/firms/record?bizNos=1038600036 → {"totalBids":7,"pushedOut":5,"belowFloor":2}
```
**온보딩은 "기록 없음"이라 하고, 성적 화면은 그 사업자의 7회 이력을 갖고 있다.**

로더 자신의 주석이 원칙을 이미 적어놨다:
> `load_postgres.py` — *"표본이 적은 구간도 버리지 않는다. n을 그대로 실어 보내고, **적다는 사실은 화면이 말한다**."*

**그 원칙에 전제가 붙어 있다 — 화면이 n을 말해야 한다.** 지금 대체로 지킨다(`{view.length}회 기준`, 표본 12 미만은 점 스트립). **잔여: `dense`(잘 나온 구간) 가격선이 n을 안 단다** — 개찰 1회짜리 학교 502곳에서 그 선은 회차 하나다.

### 문턱을 걷을 때의 함정

**문턱 제거가 A-8을 고치는 게 아니라 *가릴* 수 있다.** 지금은 "회차 10인데 5+5"가 문턱 바로 위라 위험 신호인데, 문턱이 없어지면 **조용히 두 행으로 남는다.**
→ **문턱 제거와 카운터를 같은 배포에 넣는다.**

## F3. 우리가 만든 값에는 **출처**를 붙인다

원본에서 온 사실과 우리가 규칙으로 만든 추정을 화면이 구별할 수 있어야 한다.

**치른 값:**
- **`무효`가 원본에 없는 판정이었다.** 우리가 만들어 단언했다
- 품목의 **62.3%가 이름 규칙산**인데 화면은 발주처 지정과 구별 없이 말했다 → `category_src`
- 자격이 **지역만 보고 판정**됐는데 화면은 "자격 충족"이라 했다 → `qualificationBasis: "region-only"`

**설계의 한 줄이 이걸 요약한다:**
> **SSOT의 단위는 값이 아니라 (값, 출처)다. 출처 없는 값은 계약 위반이다.**

**그리고 이건 "모르면 단언 금지"의 반대 방향도 막는다** — 부분문자열 자격 판정(`서구` ⊂ `달서구`)은 **모르는 걸 안다고 단언**하는 쪽이었다.
